# Design Preferences

Use this as a generic design brief for this portfolio and similar personal technical sites.

## Direction

- Dark, minimal, sharp, and editorial.
- More like a polished independent technical portfolio than a SaaS landing page.
- Use yellow as a restrained accent, not as decoration everywhere.
- Favor quiet confidence over flashy effects.
- The page should feel fluid, not boxed in.

## Layout

- Avoid card-heavy layouts.
- Avoid nested cards, framed sections, and boxed grids unless the content truly needs them.
- Use whitespace, rhythm, and type hierarchy before using borders.
- Keep thin divider lines sparse and subtle.
- Do not make repeated headings too large; reserve display scale for the hero and major section moments.
- Prefer single coherent flows over split layouts that make the page feel like an app dashboard.

## Typography

- Keep headings compact and purposeful.
- Collapsed repeated rows should be quiet; expanded or primary content can be stronger.
- Avoid oversized text at normal desktop zoom.
- Make sure mobile line breaks feel intentional.
- Use monospace sparingly for labels, metadata, and technical accents.

## Copy

- Keep first-view copy short.
- Use specific technical nouns, but avoid dumping internal implementation detail.
- Frame projects by capabilities and outcomes.
- Remove generic portfolio filler and “AI-generated” sounding sentences.
- Avoid terms that feel too company-specific or confidential.

## Interaction

- Interactions should reduce clutter, not create confusion.
- Avoid pointer-dependent behavior for important content.
- Avoid scroll-triggered expand/collapse for resume-critical content.
- Prefer one clear interaction model per section.
- Expandable details should be easy to open, close, and understand.

## Visual Restraint

- Reduce decorative borders and wireframe-like lines.
- Avoid product-card UI when the page is meant to feel editorial.
- Avoid excessive icons or controls.
- Keep accent marks small and deliberate.
- Verify by screenshot after changes; if it feels crowded, reduce hierarchy before adding structure.
