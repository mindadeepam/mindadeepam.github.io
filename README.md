# Deepam Minda

Personal site for [Deepam Minda](https://deepamminda.vercel.app/), an Applied ML Engineer. The site is intentionally small: a home page, a Markdown-backed blog, and a generated resume PDF.

It is deployed on **Vercel**, not GitHub Pages. The repository does not use a JavaScript framework, package manager, or build step for its static pages.

## Repository map

```text
index.html                 Home page
styles.css                 Shared visual system and responsive styles
script.js                  Theme toggle, Markdown renderer, blog rendering
blog/index.html            Blog index
blog/post.html             Blog post shell
posts/                     Markdown sources and post index
resume/build_resume.py     Generates the resume PDF
output/pdf/                Generated resume linked from the home page
api/github-activity.js     Optional Vercel serverless endpoint
agents.md                  Working preferences for coding agents
design.md                  Visual and interaction direction
```

Read [`agents.md`](./agents.md) and [`design.md`](./design.md) before changing content, layout, or interaction behavior. This portfolio should remain concise, editorial, and public-safe; do not add generic landing-page copy, dense card grids, or company-confidential implementation details.

## Requirements

- Git
- Python 3 for a static local server and resume generation
- Node.js 20+ and `npx` only when using the Vercel CLI
- A Vercel account with access to the linked project for previews and deployments

There is no `npm install` step for ordinary static-site work.

## Local development

### Static pages

For home, blog, theme, and Markdown rendering work, use Python's built-in server:

```sh
cd mindadeepam.github.io
python3 -m http.server 3000
```

Open <http://localhost:3000>. This is the fastest option and automatically reflects file changes after a refresh.

Useful local URLs:

- <http://localhost:3000/>
- <http://localhost:3000/blog/>
- <http://localhost:3000/blog/post.html?slug=how-to-async-in-python>
- <http://localhost:3000/type-specimen.html> for the typography comparison page

### Vercel function preview

Use this only when changing or testing files under `api/`, because Python's static server does not run Vercel serverless functions:

```sh
npx vercel@latest login
npx vercel@latest dev
```

If the project is not already linked, the CLI will prompt you to link it. Do not commit the generated `.vercel/` directory; it is already ignored.

## Writing a blog post

Posts are plain Markdown files in [`posts/`](./posts). The blog index is driven by [`posts/index.json`](./posts/index.json), so both files must be updated.

1. Create `posts/your-post-slug.md` using lowercase kebab-case.
2. Add front matter at the top of the file:

   ```md
   ---
   title: Your post title
   date: 2026-09-05
   description: A concise one-sentence summary.
   tags: python, systems
   ---

   # Your post title
   ```

3. Add the matching entry to `posts/index.json`. Keep newest posts first:

   ```json
   {
     "slug": "your-post-slug",
     "title": "Your post title",
     "date": "2026-09-05",
     "displayDate": "05 Sep 2026",
     "description": "A concise one-sentence summary."
   }
   ```

4. Preview `/blog/` and the direct post URL:

   ```text
   /blog/post.html?slug=your-post-slug
   ```

The lightweight renderer supports headings, links, images, lists, blockquotes, tables, fenced code blocks with language labels, and Mermaid diagrams. It does not currently render Jupyter notebooks. When notebook publishing becomes necessary, add a build-time renderer that converts `.ipynb` files to styled static HTML; do not attempt to render raw notebooks in the browser.

## Resume PDF

The public resume is generated by [`resume/build_resume.py`](./resume/build_resume.py). Install its one dependency if necessary, then regenerate the PDF from the `resume/` directory:

```sh
python3 -m pip install reportlab
cd resume
python3 build_resume.py
```

The script writes `output/pdf/Deepam_Minda_Applied_ML_Engineer.pdf`, which is the file linked from the home page. Open the PDF after generating it and check line wrapping, page count, and contact links before committing.

## GitHub activity endpoint

[`api/github-activity.js`](./api/github-activity.js) is a Vercel serverless function that requests the authenticated account's contribution calendar using the GitHub GraphQL API. The current minimal home page does not display this component, but the endpoint is retained for future use.

It requires a server-only `GITHUB_TOKEN` environment variable. For local Vercel development, create `.env.local`:

```sh
GITHUB_TOKEN=github_pat_or_classic_token_here
```

For Vercel environments, add the same variable through the dashboard or CLI:

```sh
npx vercel@latest env add GITHUB_TOKEN development
npx vercel@latest env add GITHUB_TOKEN preview
npx vercel@latest env add GITHUB_TOKEN production
```

Use a token that can see the contribution history you intend to display. Do not commit tokens, paste them into source files, or expose them through browser-side JavaScript. `.env.local` is ignored by Git.

## Deploying with Vercel

The production site is <https://deepamminda.vercel.app/>. GitHub integration may create deployments automatically after a push to the connected branch. For an explicit CLI deployment from the repository root:

```sh
# Create a preview deployment
npx vercel@latest

# Deploy the current state to production
npx vercel@latest --prod
```

The CLI prints the deployment URL. Check the production deployment in a browser after it completes, especially theme persistence, resume download, blog navigation, code blocks, and Mermaid diagrams.

## Contribution checklist

1. Keep the change focused and preserve existing user changes.
2. Use ASCII by default and avoid unrelated formatting churn.
3. Preview desktop and mobile views locally.
4. For blog changes, test both the index and one rendered post.
5. For resume changes, regenerate and visually inspect the PDF.
6. For API changes, use `npx vercel@latest dev` and keep secrets in environment variables.
7. Run `git diff --check` before committing.
8. Do not commit, push, or deploy unless the repository owner explicitly asks.

There is no automated test suite yet. Manual visual verification is part of the expected workflow for this small static site.
