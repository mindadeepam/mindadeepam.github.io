TabFM: in-context learning for tables

Google's tabular foundation model, from 30 June 2026: hand it your labelled rows and the rows to predict, and it answers in a forward pass, with no training on your data. What it is, how it works, where it beats gradient-boosted trees and where it doesn't.

About 12 minutes · builds on the attention and transformer notes · labelled rowsattention

In short

  1. TabFM (Google Research, blog 30 Jun 2026; paper arXiv 2609.37959) is a transformer pretrained only on synthetic tables. You give it training rows with labels and test rows without, as one input, and it predicts the test labels with frozen weights. No gradient steps on your data.
  2. That's in-context learning, the same idea as an LLM learning from examples in its prompt. It descends from TabPFN (Nature, 2025) and TabICL (ICML 2025).
  3. Architecture: each cell becomes a token; the encoder alternates attention across rows within a column and attention across features within a row; each row becomes one vector; a 24-layer predictor lets every row attend to the labelled rows only.
  4. It's invariant to row order by design, but not to column order (RoPE and column grouping); it gets close by averaging 32 column-shuffled views.
  5. On Google's own TabArena numbers it beats tuned gradient-boosted trees and AutoML. In practice, trees still win on huge, imbalanced, latency-critical problems like fraud, and the open weights are non-commercial.

01The idea: learn to learn from a table

The usual way: for each new dataset, train a model (XGBoost, say) with gradient steps. The in-context way: train one model, once, on millions of datasets, so that it learns the act of fitting. Then a new dataset is just its input.

\[ \min_\theta\ \mathbb{E}_{D \sim p(D)} \Big[ -\log q_\theta\big(y_{\text{test}} \mid x_{\text{test}},\ D_{\text{train}}\big) \Big] \]
  • Each pretraining example is a whole dataset drawn from a prior \(p(D)\), split into training rows (with labels, in context) and test rows (labels hidden, to be predicted).
  • Minimizing this loss over many datasets makes \(q_\theta\) approximate the posterior predictive \(p(y \mid x, D)\): amortized Bayesian inference. That's why it's called a prior-data fitted network (TabPFN). The model has learned what a good fit looks like for data like the prior.
  • Why synthetic data works: the prior is built from random structural causal models (random graphs of features causing other features and the label, with noise and non-linearities), which covers the kinds of structure real tables have. Real tables that look like the prior transfer well.

In-context learning vs fine-tuning

Fine-tuning changes the weights with gradients on your data. In-context learning keeps the weights frozen and conditions on your data inside the forward pass: the “training” happens in the activations. The cost moves from training time to prediction time, and the amount of data is capped by the context size.

02How TabFM works

  • Tokens. Each cell becomes a token through 32 learned Fourier frequencies, with separate embeddings for numeric and categorical values. Training rows also get a label embedding; test rows don't.
  • Column attention (across rows). For each feature, its cells attend to each other down the column, so each value is seen in the context of the column's distribution. It uses 256 inducing points, which makes it linear in the number of rows, and only the labelled training rows are summarized.
  • Row attention (across features). Within each row, the features attend to each other, with RoPE positions, so the model learns interactions between columns. It alternates with column attention for two stages.
  • Row vectors. Eight CLS tokens per row are combined into one vector per row.
  • Predictor. A 24-layer transformer over those row vectors. A mask lets every row attend only to the labelled training rows, the in-context “training set”. It outputs class logits (up to 10 classes) or a regression value.

TabFM's forward pass, in pseudocode (simplified)

# X_train: (N, F) with labels y_train;  X_test: (M, F) without labels
tokens = cell_embed(concat([X_train, X_test]))      # (N+M, F, d): one token per cell
tokens[:N] += label_embed(y_train)                  # only training rows carry their label
for stage in range(2):
    tokens = column_attention(tokens, context=N)    # down each column, summarizing the training rows
    tokens = row_attention(tokens)                  # across each row's features (RoPE)
rows = pool_cls(tokens)                             # (N+M, d): one vector per row
mask = attend_only_to(range(N))                     # every row sees the labelled rows, test rows not each other
y_test = head(predictor(rows, mask)[N:])            # 24 layers; predictions for the M test rows
# no gradient steps on your data; by default average 32 column-shuffled views

Why not flatten the table into one long sequence?

Attention over every cell of a \(T\)-row, \(H\)-column table costs \(O(T^2 H^2)\), and it would impose an order that doesn't exist. Attending along columns, then along rows, then between whole rows keeps the cost manageable (context up to about 16K rows) and matches the table's two axes.

03Invariance: rows yes, columns approximately

  • Rows: reordering the rows doesn't change predictions. Rows get no positional encoding, and test rows are masked from each other. That's the right property, since a table's rows are a set.
  • Columns: reordering columns does change predictions, because row attention uses RoPE and columns are grouped with nearby ones. TabFM approximates column invariance by averaging the predictions of 32 column-shuffled views by default. So the default isn't literally a single forward pass, even though the blog describes one.

04Pretraining and size

  • Data: synthetic only, “hundreds of millions” of tables generated from structural causal models, with up to 100 columns. The context grew from 2,048 to 16,384 rows during training.
  • Size: 408.7M parameters in the paper; the released Hugging Face checkpoint is larger, about 1.6B by its weight file.
  • Limits: classification up to 10 classes, plus regression; the library accepts up to 500 features and subsamples larger tables. Compute grows quadratically with the number of context rows, so a GPU is expected.
  • Licence: the code is Apache-2.0, but the released weights are for non-commercial, non-production use. There's also a BigQuery preview (50 feature columns, 10 classes).

The family it belongs to

  • TabPFN v2 (Hollmann et al., Nature, Jan 2025): the prior-data fitted network that started this line; designed for up to about 10K rows and 500 features.
  • TabICL (ICML 2025) and TabICL v2 (Feb 2026): column-then-row encoders with in-context learning over rows, scaling to larger tables. TabFM is roughly a hybrid of TabPFN and TabICL.

06Interview questions

1What is TabFM, in one minute?

A tabular foundation model from Google (June 2026): a transformer pretrained only on synthetic tables from structural causal models. You pass labelled training rows and unlabelled test rows together, and it predicts the test labels with frozen weights through in-context learning, with no training on your data. It alternates column and row attention to encode the table, then a predictor lets each row attend to the labelled rows.

2Why row and column attention instead of flattening the table?

Flattening gives \(T \times H\) tokens, so full attention costs \(O(T^2 H^2)\), and it invents an order. Attending down columns (each value against its column's distribution) and across rows (feature interactions), then between whole rows, matches the table's structure and keeps contexts of ~16K rows feasible.

3Is it permutation-invariant?

Over rows, yes: no positional encoding on rows, and test rows are masked from each other. Over columns, no: row attention uses RoPE and columns are grouped, so it approximates invariance by averaging 32 column-shuffled views.

4How does in-context learning differ from fine-tuning?

Fine-tuning updates the weights with gradients on your data. In-context learning keeps the weights frozen and puts your data in the input, so the fitting happens inside the forward pass. Compute moves to prediction time, and the data you can use is capped by the context size.

5Why does pretraining on synthetic data work?

Minimizing loss on held-out rows across many datasets drawn from a prior teaches the model the posterior predictive \(p(y \mid x, D)\) under that prior: amortized Bayesian inference. A rich prior (random structural causal models) covers the structure real tables have, so it transfers to real data that resembles it.

6What are its main limitations?

A capped context (rows sampled for big tables), at most 10 classes, cost quadratic in context rows (GPU needed), no built-in explanations, a non-commercial licence on the weights, and self-reported benchmarks. Rare-positive problems at scale, like fraud, lose information when the context is sampled.

7How would you evaluate it against XGBoost on a credit dataset?

An out-of-time split, a properly tuned XGBoost (with monotonic constraints if production uses them), and the metrics that matter for credit: AUC and KS, calibration, and the bad rate at a fixed approval rate. Add bootstrap confidence intervals and learning curves over training-set size, plus latency and cost per prediction. I'd expect TabFM to shine at small sizes and trees to catch up or win as data grows.

07Cheat sheet

Objective (prior-data fitting)

\[ \min_\theta\ \mathbb{E}_{D \sim p(D)}\big[-\log q_\theta(y_{\text{test}} \mid x_{\text{test}}, D_{\text{train}})\big] \ \Rightarrow\ q_\theta(y \mid x, D) \approx p(y \mid x, D) \]

Pipeline

\[ \text{cells} \to \text{tokens} \to (\text{column attn} \to \text{row attn}) \times 2 \to \text{row vectors} \to \text{predictor (attend to labelled rows)} \to \hat y \]
