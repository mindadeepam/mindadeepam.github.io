Study notes · Neural networks

Deep learning basics

How a neural network computes, how backprop finds every gradient in one pass, and the pieces that make deep networks trainable: activations, losses, initialization, normalization, regularization, residuals, convolutions.

About 30 minutes · forward pass, backprop, then everything that keeps training stable · forward valuesgradientshighlights

In short

  1. A layer is \(a = f(Wx + b)\): a weighted sum, then a non-linearity. Without the non-linearity, any stack of layers collapses into one linear map.
  2. The forward pass computes and stores every layer's output. The backward pass applies the chain rule from the loss backwards: \(\delta_l = (W_{l+1}^\top \delta_{l+1}) \odot f'(z_l)\), and each weight's gradient is \(\delta_l\, a_{l-1}^\top\).
  3. One backward pass costs about two forward passes and gives the gradient for every weight. That's why deep learning is feasible.
  4. Deep networks fail when gradients vanish or explode (a product of one factor per layer). The fixes are ReLU-family activations, variance-preserving initialization, normalization, residual connections and clipping.
  5. Regularization (weight decay, dropout, early stopping, augmentation) fights overfitting; Adam(W) with a tuned learning rate and warmup is the default optimizer.
  6. Add vectors when they're updates to the same representation (residuals, positions); concatenate when they're different sources that need their own weights.

01A neuron, a layer, a network

A neuron takes a weighted sum of its inputs plus a bias, then applies a non-linear activation. A layer is many neurons side by side, so the weights become a matrix:

\[ z = W x + b \qquad a = f(z) \]
ThingShapeNote
\(x\)\(d_{in}\)Input (or the previous layer's output)
\(W\)\(d_{out} \times d_{in}\)Row \(i\) is neuron \(i\)'s weights
\(b,\ z,\ a\)\(d_{out}\)Bias, pre-activation, activation
A batch \(X\)\(B \times d_{in}\)In code rows are examples: \(Z = X W^\top + b\), shape \(B \times d_{out}\)
Parameters\(d_{out}(d_{in} + 1)\)

Why the non-linearity is essential: two linear layers make one, since \(W_2(W_1 x) = (W_2 W_1) x\). Only the bend between layers lets depth build curved decision boundaries. With it, a single hidden layer that's wide enough can approximate any continuous function (the universal approximation theorem); depth makes that far more efficient.

02The forward pass

Run the layers in order and keep every intermediate result, because the backward pass will need them. For a two-layer classifier:

\[ z_1 = W_1 x + b_1 \qquad a_1 = \text{ReLU}(z_1) \qquad z_2 = W_2 a_1 + b_2 \qquad \hat y = \text{softmax}(z_2) \qquad L = -\sum_k y_k \log \hat y_k \]

Every operation here is simple, with a simple local derivative. That's what makes the next section work: the chain rule just multiplies local derivatives along the path.

03Backpropagation

The question backprop answers: for every weight, how much would the loss change if that weight moved a little? Define the error at layer \(l\) as the gradient at its pre-activation, \(\delta_l = \partial L / \partial z_l\). Everything follows from four equations:

\[ \text{(1)}\ \ \delta_{\text{out}} = \hat y - y \qquad\qquad \text{(2)}\ \ \delta_l = \big(W_{l+1}^\top \delta_{l+1}\big) \odot f'(z_l) \]
\[ \text{(3)}\ \ \frac{\partial L}{\partial W_l} = \delta_l\, a_{l-1}^\top \qquad\qquad \text{(4)}\ \ \frac{\partial L}{\partial b_l} = \delta_l \]
  • (1) Start at the output. For softmax with cross-entropy (or sigmoid with log loss), the gradient at the logits is prediction minus truth. For MSE on a linear output it's \(\hat y - y\) too.
  • (2) Pass the error back one layer. \(W_{l+1}^\top\) sends each unit's error back along the same weights it used going forward (unit \(j\) collects \(\sum_i W_{ij}\, \delta_i\)). Then multiply by the activation's slope, \(f'(z_l)\), slot by slot, because the error has to pass back through the non-linearity. For ReLU that slope is 1 where the unit was on and 0 where it was off.
  • (3) Read off the weight gradient. \(W_l[i,j]\) multiplied \(a_{l-1}[j]\) into \(z_l[i]\), so its gradient is \(\delta_l[i] \cdot a_{l-1}[j]\): an outer product, the same shape as \(W_l\).
  • (4) The bias gradient is just the error, since the bias is added with slope 1.
Batch version (rows = examples)Shape
\(\Delta_{\text{out}} = (\hat Y - Y)/B\)\(B \times K\) (the \(1/B\) is from averaging the loss)
\(\Delta_l = (\Delta_{l+1} W_{l+1}) \odot f'(Z_l)\)\(B \times d_l\)
\(\partial L/\partial W_l = \Delta_l^\top A_{l-1}\)\(d_l \times d_{l-1}\): the sum of every example's outer product
\(\partial L/\partial b_l = \) column sums of \(\Delta_l\)\(d_l\)

Forward and backward, in NumPy

# X: (B, d)  Y: (B, K) one-hot;  W1: (H, d)  W2: (K, H)
Z1 = X @ W1.T + b1            # (B, H)
A1 = relu(Z1)
Z2 = A1 @ W2.T + b2           # (B, K) logits
P  = softmax(Z2)              # (B, K)
loss = -(Y * log(P)).sum() / B

D2  = (P - Y) / B             # delta at the logits: (B, K)
dW2 = D2.T @ A1               # (K, H)
db2 = D2.sum(axis=0)
D1  = (D2 @ W2) * (Z1 > 0)    # back through W2, then ReLU's slope: (B, H)
dW1 = D1.T @ X                # (H, d)
db1 = D1.sum(axis=0)
for p, g in [(W1, dW1), (b1, db1), (W2, dW2), (b2, db2)]:
    p -= lr * g               # one gradient-descent step

Why it's cheap, and what it costs

  • Reverse mode. The loss is one number and there are millions of weights. Going backward from that one number reuses every intermediate result, so one backward pass (about twice the cost of a forward pass) gives all the gradients. Nudging each weight and re-running the forward pass would cost one pass per weight.
  • Memory. The backward pass needs every stored activation, so memory grows with depth × batch × width. Gradient checkpointing stores only some and recomputes the rest, trading compute for memory.
  • Gradient checking: compare with \((L(w + \varepsilon) - L(w - \varepsilon)) / 2\varepsilon\) on a few weights when you write a backward pass by hand.

Trap

“The gradient at a layer is the prediction minus the target.” Only at the output layer. Everywhere else, \(\delta\) is the error passed back through the weights and multiplied by the activation's slope at that layer.

04Gradient descent and optimizers

\[ \text{SGD: } \theta \leftarrow \theta - \eta\, g \qquad \text{Momentum: } v \leftarrow \beta v + g,\ \ \theta \leftarrow \theta - \eta\, v \]
\[ \text{Adam: } m \leftarrow \beta_1 m + (1 - \beta_1) g, \quad v \leftarrow \beta_2 v + (1 - \beta_2) g^2, \quad \theta \leftarrow \theta - \eta\, \frac{\hat m}{\sqrt{\hat v} + \epsilon}, \quad \hat m = \frac{m}{1 - \beta_1^t},\ \hat v = \frac{v}{1 - \beta_2^t} \]
  • Mini-batch SGD: each step uses the gradient on a small batch, a noisy but cheap estimate of the full gradient. The noise even helps escape sharp minima.
  • Momentum keeps a running average of gradients, so steps build up speed in consistent directions and zig-zags cancel out.
  • RMSProp divides each weight's step by a running average of its squared gradient, so rarely-updated and steep directions get sensibly sized steps.
  • Adam does both. The bias correction (\(\hat m, \hat v\)) matters early on: \(m\) and \(v\) start at 0, so without it the first steps would be too small.
  • AdamW applies weight decay directly to the weights (\(\theta \leftarrow \theta - \eta\lambda\theta\)) instead of adding \(\lambda\theta\) to the gradient, where Adam's scaling would distort it. It's the default for transformers.
  • The learning rate is the most important hyperparameter: warm it up at the start, then decay it (step, cosine). A bigger batch can usually take a proportionally bigger learning rate.

Adam / AdamW, in code

m = beta1 * m + (1 - beta1) * g             # running mean of gradients
v = beta2 * v + (1 - beta2) * g * g         # running mean of squared gradients
m_hat = m / (1 - beta1 ** t)                # bias correction (m, v start at 0)
v_hat = v / (1 - beta2 ** t)
w -= lr * (m_hat / (sqrt(v_hat) + eps) + wd * w)   # AdamW: decay applied to w directly

06Losses

\[ \text{MSE} = \tfrac{1}{n}\sum (y - \hat y)^2 \qquad \text{BCE} = -[y \log p + (1 - y)\log(1 - p)] \qquad \text{CE} = -\sum_k y_k \log \hat y_k \qquad \text{Focal} = -(1 - p_t)^\gamma \log p_t \]
  • Each loss is a likelihood: Gaussian noise gives MSE, Laplace noise gives MAE, Bernoulli labels give binary cross-entropy, categorical labels give cross-entropy. Huber is MSE near 0 and MAE in the tails, so it's robust to outliers.
  • Why cross-entropy, not MSE, for classification: with a sigmoid or softmax, MSE's gradient includes the activation's slope, which is tiny exactly when the model is confidently wrong. Cross-entropy's gradient at the logits is simply \(\hat y - y\), largest when most wrong.
  • Focal loss down-weights easy, well-classified examples (\((1 - p_t)^\gamma\)), for heavy class imbalance. Class weights are the simpler alternative.

07Vanishing, exploding and initialization

The backward pass multiplies the error by one factor, \(W^\top \text{diag}(f')\), per layer. Over many layers that product shrinks or grows exponentially: vanishing or exploding gradients. Early layers stop learning, or training blows up.

Initialization keeps the signal's size steady. A pre-activation \(z = \sum_j w_j x_j\) has variance \(n_{in}\,\text{Var}(w)\,\text{Var}(x)\). To keep it equal to \(\text{Var}(x)\) layer after layer:

\[ \text{Xavier (tanh, sigmoid): } \text{Var}(w) = \frac{2}{n_{in} + n_{out}} \qquad \text{He (ReLU): } \text{Var}(w) = \frac{2}{n_{in}} \]
  • He has the extra factor 2 because ReLU zeroes half its inputs, halving the variance.
  • All-zero (or all-equal) initialization fails: every unit in a layer computes the same thing and gets the same gradient, so they stay identical forever. Random initialization breaks the symmetry.
  • The full toolkit against vanishing/exploding: ReLU-family activations, He/Xavier initialization, normalization layers, residual connections, gradient clipping (for exploding), and gated cells in RNNs.

08BatchNorm and LayerNorm

\[ \hat x = \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}} \qquad y = \gamma \hat x + \beta \]
  • BatchNorm (CNNs): statistics per feature over the batch. At inference there may be one example, so it uses running averages saved during training; the train/eval switch is a classic bug. It struggles with small batches and padded sequences.
  • LayerNorm (transformers, RNNs): statistics per example over its features. It doesn't depend on the batch and behaves the same in training and inference.
  • Why they help: they keep each layer's inputs at a steady scale, which allows bigger learning rates and smooths the loss landscape. The learned \(\gamma, \beta\) let the network undo the normalization if that's better.

09Regularization

\[ \text{Dropout (training): } \tilde h = \frac{h \odot m}{1 - p},\ \ m_i \sim \text{Bernoulli}(1 - p) \qquad \text{L2: } L + \frac{\lambda}{2}\lVert w \rVert^2 \]
  • Weight decay (L2) shrinks weights every step, favouring simpler functions. L1 pushes weights to exactly 0 (sparsity).
  • Dropout zeroes each unit with probability \(p\) during training and scales the survivors by \(1/(1-p)\), so the expected activation is unchanged and nothing needs rescaling at inference, where it's off. It stops units relying on each other and acts like averaging many thinned networks.
  • Early stopping keeps the checkpoint with the best validation loss. Data augmentation adds realistic variations. Label smoothing softens one-hot targets so the model isn't pushed to infinite confidence.
  • Bias–variance: big gap between train and validation → overfitting (high variance): regularize, add data, shrink the model. Both bad → underfitting (high bias): bigger model, longer training, better features.

BatchNorm, LayerNorm and dropout, in code

def batchnorm(x, training):                 # x: (B, F)
    if training:
        mu, var = x.mean(axis=0), x.var(axis=0)     # per feature, over the batch
        run_mu  = 0.9 * run_mu  + 0.1 * mu          # saved for inference
        run_var = 0.9 * run_var + 0.1 * var
    else:
        mu, var = run_mu, run_var                   # inference: no batch statistics
    return gamma * (x - mu) / sqrt(var + eps) + beta

def layernorm(x):                           # per example, over its features
    mu  = x.mean(axis=-1, keepdims=True)
    var = x.var(axis=-1, keepdims=True)
    return gamma * (x - mu) / sqrt(var + eps) + beta   # same in training and inference

def dropout(h, p, training):
    if not training:
        return h                            # off at inference
    keep = random(h.shape) > p
    return h * keep / (1 - p)               # scale so the expected value is unchanged

10Residual connections

\[ y = x + F(x) \qquad \frac{\partial y}{\partial x} = I + \frac{\partial F}{\partial x} \]
  • The gradient gets a straight path. The identity term means the error reaches early layers even when \(\partial F/\partial x\) is small. That's what made 100+ layer networks trainable (ResNet, 2015).
  • Doing nothing is easy. A block only has to learn a correction to its input; if a layer isn't useful, \(F \to 0\) leaves the input unchanged. Without the skip, it would have to learn the identity mapping, which is surprisingly hard.
  • The same idea appears as the LSTM's cell update through time and as the transformer's residual stream through depth.

12Convolutions in one page

\[ \text{output size} = \frac{n + 2p - k}{s} + 1 \qquad \text{parameters} = k \cdot k \cdot C_{in} \cdot C_{out} + C_{out} \]
  • Why not a dense layer: parameter sharing (a 3×3×64→64 conv has about 37K weights, whatever the image size) and locality (neighbouring pixels matter together). A pattern learned in one place is detected everywhere: translation equivariance. Pooling adds some invariance and shrinks the map.
  • Receptive field grows with depth, stride, pooling and dilation: early layers see edges, deep layers see objects.
  • 1×1 convolution: a dense layer across channels at every pixel. It changes the channel count cheaply (bottlenecks) and adds a non-linearity; it's the CNN version of the transformer's per-token FFN.
  • Tensor shape in PyTorch: \(B \times C \times H \times W\); the weights are \(C_{out} \times C_{in} \times k \times k\).

A convolution, in code (naive loops)

# x: (C_in, H, W)   w: (C_out, C_in, k, k)   no padding, stride 1
for o in range(C_out):
    for i in range(H - k + 1):
        for j in range(W - k + 1):
            y[o, i, j] = (w[o] * x[:, i:i+k, j:j+k]).sum() + b[o]   # same weights everywhere

13The training loop, and debugging it

  1. For each batch: forward pass → loss → optimizer.zero_grad() → loss.backward() → clip gradients if needed → optimizer.step() → scheduler step.
  2. model.train() for training and model.eval() plus torch.no_grad() for validation (dropout off, BatchNorm uses running statistics).
  • First, overfit one small batch. If the loss can't go near 0, there's a bug, not a modelling problem.
  • Loss flat from the start: learning rate far off, labels misaligned, forgot zero_grad or step, dead ReLUs, inputs not normalized.
  • Loss is NaN: learning rate too high, exploding gradients, log(0); use log-softmax with NLL loss and clip gradients.
  • Train good, validation bad: overfitting or leakage between the splits; regularize, stop early, check the split.
  • Plot training and validation loss together, with the gradient norm and the learning rate underneath.

The training loop, in PyTorch

for epoch in range(epochs):
    model.train()                                   # dropout on, BatchNorm uses batch stats
    for xb, yb in train_loader:
        loss = loss_fn(model(xb), yb)               # forward
        opt.zero_grad()                             # clear old gradients
        loss.backward()                             # backprop: fills p.grad for every weight
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        opt.step()                                  # update weights
        sched.step()                                # learning-rate schedule
    model.eval()                                    # dropout off, BatchNorm uses running stats
    with torch.no_grad():
        val_loss = mean(loss_fn(model(xb), yb) for xb, yb in val_loader)
    # early stopping: keep the checkpoint with the best val_loss

14Training dynamics and loss curves

Read a training run by plotting train and validation loss on the same axes, with the gradient norm and the learning rate underneath. Most problems have a recognisable shape:

  • The learning rate matters more than almost anything else (Greff et al. found this for LSTMs). Tune it first, on a log scale.
  • Warmup: ramp the learning rate up over the first steps. Adam's per-parameter scale is noisy early on, and post-LN transformers diverge without warmup. Then decay it (step, cosine, one-cycle).
  • Batch size and learning rate move together. A bigger batch gives a less noisy gradient, so it can take a proportionally bigger learning rate (the linear scaling rule, with warmup). Very large batches tend to land in sharper minima.
  • Adam vs AdamW: Adam's L2 penalty gets rescaled by its per-parameter step size. AdamW applies weight decay directly to the weights, decoupled from the gradient, which regularizes as intended.
  • Loss landscapes (Li et al., 2018): plot the loss along one or two random directions around the trained weights, with each filter's direction scaled to match its weights (“filter normalization”) so different networks are comparable. Skip connections make the landscape much smoother, and flatter minima tend to generalize better.
  • Double descent: as model size grows, test error can fall, rise near the point where the model just fits the training data, then fall again.

15Odds and ends

Optimizing a metric you can't differentiate

  • Smooth surrogate: replace hard choices (argmax, max) with a softmax, with a temperature, and optimize that. A softened codon adaptation index (CAI), added as an extra loss term, is one example.
  • Gumbel-softmax: a differentiable approximation of sampling a one-hot choice.
  • Straight-through: use the hard choice in the forward pass, and pretend it was the identity in the backward pass.
  • REINFORCE / policy gradient: treat the metric as a reward. It's unbiased but high-variance; subtract a baseline. Summarizers trained with reinforcement learning use it to optimize ROUGE directly.
  • Why it may not help: cross-entropy may already push toward what the metric rewards, and a surrogate can disagree with the real metric.

Neural ODEs

A residual layer, \(h_{l+1} = h_l + f(h_l)\), is one Euler step of \(dh/dt = f(h, t)\). A neural ODE replaces the stack of layers with an ODE solver: continuous depth, and memory that stays constant with depth when trained with the adjoint method. Flows built this way are invertible, which is why they're used for image registration. The costs are slow, adaptive solvers and trouble with stiff dynamics.

Continual learning

Learning tasks in sequence without forgetting the old ones. There are three families of fixes:

  • Regularization: EWC penalizes changes to the weights that mattered for old tasks, with importance measured by the Fisher information.
  • Replay: keep, or generate, old examples and mix them in.
  • Architecture: add new heads or adapters per task.

In production, the same problem shows up as concept drift: monitor, retrain on a schedule, and keep old patterns in the training mix.

Implicit neural representations

An MLP that maps coordinates \((x, y)\) to a pixel value. Because it's continuous, you can sample it at any resolution, which is how arbitrary-scale super-resolution works. Plain MLPs struggle with fine detail (“spectral bias”), so INRs use Fourier features or sine activations (SIREN).

16Interview questions

Answer out loud first, then open the answer.

1Why do we need non-linear activations?

Without them, any stack of layers is one linear map, since \(W_2 W_1 x = (W_2 W_1) x\). It can only draw straight decision boundaries. The non-linearity between layers is what lets depth build complex functions.

2Walk through forward and backward propagation for a two-layer network.

Forward: \(z_1 = W_1 x + b_1\), \(a_1 = \text{ReLU}(z_1)\), \(z_2 = W_2 a_1 + b_2\), \(\hat y = \text{softmax}(z_2)\), cross-entropy loss, storing each value. Backward: \(\delta_2 = \hat y - y\); \(\partial L/\partial W_2 = \delta_2 a_1^\top\), \(\partial L/\partial b_2 = \delta_2\); \(\delta_1 = (W_2^\top \delta_2) \odot \text{ReLU}'(z_1)\); \(\partial L/\partial W_1 = \delta_1 x^\top\), \(\partial L/\partial b_1 = \delta_1\). Then a gradient step on every weight.

3Why is backprop efficient compared with numerical gradients?

Reverse-mode differentiation: from one scalar loss, one backward pass (about two forward passes of compute) reuses all the stored intermediates and yields every weight's gradient. Finite differences need a forward pass per weight, so millions of passes. The price is memory for the stored activations.

4Derive the gradient of softmax with cross-entropy.

With \(\hat y_k = e^{z_k}/\sum_j e^{z_j}\) and \(L = -\sum_k y_k \log \hat y_k\) for one-hot \(y\): \(\partial L/\partial z_i = \hat y_i - y_i\). The softmax's Jacobian and the log cancel neatly, which is why the pair is always used together.

5Why use cross-entropy rather than MSE for classification?

Cross-entropy is the maximum-likelihood loss for categorical labels, and its gradient at the logits is \(\hat y - y\): big when confidently wrong. MSE through a sigmoid or softmax multiplies by the activation's slope, which is near 0 when the output is saturated, so learning stalls exactly when the model is most wrong.

6What causes vanishing and exploding gradients, and how do you fix them?

The backward pass multiplies one Jacobian per layer (weights times activation slopes), so the product shrinks or grows exponentially with depth. Fixes: ReLU-family activations (slope 1), He/Xavier initialization, BatchNorm/LayerNorm, residual connections, gradient clipping for explosions, gated cells (LSTM/GRU) in recurrent nets.

7Xavier vs He initialization? What if you initialize everything to zero?

Both keep the variance of activations (and gradients) roughly constant across layers: Xavier \(\text{Var}(w) = 2/(n_{in} + n_{out})\) for tanh/sigmoid, He \(2/n_{in}\) for ReLU, which zeroes half its inputs. All zeros (or all equal) makes every unit in a layer identical with identical gradients, so they never differentiate (symmetry).

8BatchNorm vs LayerNorm. What changes at inference?

Same formula, different axis: BatchNorm normalizes each feature over the batch (CNNs), LayerNorm each example over its features (transformers, RNNs). At inference BatchNorm uses running means and variances saved during training, so forgetting model.eval() is a bug. LayerNorm needs no batch and behaves the same both ways.

9How does dropout work? Why scale by \(1/(1-p)\)? What happens at inference?

During training each unit is zeroed with probability \(p\), which stops units co-adapting and acts like averaging many thinned networks. Scaling the survivors by \(1/(1-p)\) keeps the expected activation unchanged (inverted dropout), so at inference dropout is simply switched off with no rescaling.

10L1 vs L2 vs weight decay. Why AdamW?

L2 penalizes squared weights, shrinking them smoothly; L1 penalizes absolute values, pushing some exactly to 0. With plain SGD, L2 and weight decay are the same. With Adam, an L2 term in the gradient gets rescaled per weight, weakening it for weights with large gradient history. AdamW decays the weights directly, decoupled from the gradient, so regularization works as intended.

11Adam vs SGD with momentum. Why does Adam need bias correction?

Momentum averages gradients to smooth the path; Adam also scales each weight's step by its recent gradient size, so it needs less tuning and handles uneven scales. SGD with momentum sometimes generalizes a bit better on vision tasks. \(m\) and \(v\) start at 0, so early averages are biased toward 0; dividing by \(1 - \beta^t\) corrects that.

12Why do residual connections help?

\(y = x + F(x)\) gives \(\partial y/\partial x = I + \partial F/\partial x\): an identity path for the gradient through any depth. The block only has to learn a correction, and doing nothing (\(F = 0\)) is easy. They made very deep networks trainable, and the same idea underlies the transformer's residual stream and the LSTM's cell.

13When do you add vectors and when do you concatenate them?

Concatenation followed by a linear layer equals separate projections then a sum, \(W[x;y] = W_1 x + W_2 y\). So concatenating gives each input its own weights, at the cost of width. Adding forces a shared space and keeps the width fixed. Add for updates to the same representation (residuals, positional encodings, the residual stream); concatenate for different sources (LSTM inputs, bi-LSTM outputs, attention heads, U-Net skips, feature fusion).

14Why a CNN instead of a dense network for images? What does a 1×1 convolution do?

Parameter sharing and locality: a small filter reused everywhere has few weights, uses neighbourhood structure and detects a pattern anywhere. A dense layer would need a weight per pixel per unit and relearn each pattern at each position. A 1×1 convolution mixes channels at each pixel: cheap channel reduction or expansion (bottlenecks) plus a non-linearity, the CNN version of a per-token FFN.

15Compute the output size and parameters of a convolution layer.

Output side \((n + 2p - k)/s + 1\): a 32×32 input, 3×3 kernel, padding 1, stride 1 stays 32×32; stride 2 gives 16×16. Parameters: \(k^2 C_{in} C_{out} + C_{out}\), so 3×3, 64→128 has \(9 \times 64 \times 128 + 128 = 73{,}856\), independent of image size.

16Your loss isn't decreasing. How do you debug it?

Overfit a tiny batch first; if that fails it's a bug. Check the data (labels aligned, inputs normalized), the loop (zero_grad, backward, step, train()/eval()), and the loss (log-softmax with NLL, not softmax twice). Then sweep the learning rate on a log scale, check gradient norms per layer for vanishing or exploding, and look for dead ReLUs.

17How does batch size affect training?

Bigger batches give less noisy gradients and better hardware use, and usually allow a proportionally larger learning rate (with warmup). Very large batches can generalize slightly worse (sharper minima) and need more epochs' worth of tuning. Small batches are noisier, which acts as a mild regularizer, but they're slower per example.

Layer and backprop

Optimizers

\[ \text{Adam: } \theta \leftarrow \theta - \eta\, \hat m / (\sqrt{\hat v} + \epsilon) \qquad \text{AdamW: } \ldots - \eta \lambda \theta \]

Initialization, normalization, dropout

\[ \text{He: } 2/n_{in} \quad \text{Xavier: } 2/(n_{in} + n_{out}) \qquad y = \gamma \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}} + \beta \qquad \tilde h = \frac{h \odot m}{1 - p} \]
