Sequence models

RNNs, LSTMs and GRUs: how each one carries memory, how the gradient flows back through it, what every part does, and what breaks without it.

Diagrams, worked maths and practice questions · cell state chidden state hgates

In short

  1. A plain RNN carries one vector, \(h\), and rewrites all of it every step through the same matrix and a tanh. Old information fades, and so does the gradient that could teach it to stay.
  2. A gate is a vector of dials between 0 and 1, recomputed every step from \([h_{t-1}, x_t]\) through its own weight matrix, and multiplied slot by slot into a signal.
  3. The LSTM keeps a notebook \(c\) that changes only by erasing (\(\times f\)) and writing (\(+\, i \odot g\)), and shows \(h = o \odot \tanh(c)\). The GRU merges notebook and output into one \(h\): the update gate \(z\) decides keep-versus-write, the reset gate \(r\) decides what the draft is built from.
  4. Neither cell predicts anything by itself: a separate output layer reads \(h_t\), \(\hat y_t = \text{softmax}(W_y h_t + b_y)\).
  5. Backprop: on the memory path, each step back multiplies the gradient by \(\text{diag}(1 - h_t^2) W_h\) in an RNN, by \(f_t\) in an LSTM and by \(1 - z_t\) in a GRU. Swapping a fixed matrix and slope for a learned dial is the whole fix.
  6. In ablations, the forget gate (started near 1) matters most and the output gate least; the learning rate matters more than any architectural tweak.

01The plain RNN’s problem

\[ \begin{aligned} h_t &= \tanh(W_x x_t + W_h h_{t-1} + b) \\ \hat y_t &= \text{softmax}(W_y h_t + b_y) \end{aligned} \]

Shapes

Notation for the whole page: \(d\) = input size (e.g. the embedding size), \(H\) = hidden size, \(K\) = number of classes (or the vocabulary size \(V\)), \(T\) = sequence length, \(B\) = batch size.

In code everything gets a leading batch dimension, and rows are examples, so a step is \(h_t = \tanh(x_t W_x^\top + h_{t-1} W_h^\top + b)\) with \(x_t\) of shape \(B \times d\) and \(h_t\) of shape \(B \times H\). PyTorch's nn.RNN(d, H, batch_first=True) takes \(B \times T \times d\) and returns all states as \(B \times T \times H\), plus the last one as \(\text{layers} \times B \times H\). Parameters: \(H(d + H) + H\) for the cell, plus \(KH + K\) for the head. PyTorch stores two bias vectors, \(b_{ih}\) and \(b_{hh}\), so it reports \(H(d + H) + 2H\) for the cell; only their sum matters (more on this under the LSTM). None of it depends on \(T\), because the same weights run at every step.

Where \(x_t\) comes from: tokens to vectors

For text, \(x_t\) is a learned embedding, exactly as in a transformer. The text is split into tokens, each token is an id in a vocabulary of size \(V\), and the id picks one row of an embedding table \(E\):

\[ \begin{aligned} X &= E[\text{ids}] \\ h_t &= \text{RNN}(x_t,\ h_{t-1}) \\ z_t &= W_y h_t + b_y \end{aligned} \]
ThingShapeNote
Token ids\(B \times T\)Integers in \([0, V)\)
Embedding table \(E\)\(V \times d\)One learned row per token
\(X = E[\text{ids}]\)\(B \times T \times d\)The cell reads \(x_t\), one \(B \times d\) slice per step
\(h_t\)\(B \times H\)The state after step \(t\)
\(W_y\) / logits \(z_t\)\(V \times H\) / \(B \times V\)Next-token scores for a language model

In PyTorch that's nn.Embedding(V, d) → nn.LSTM(d, H) → nn.Linear(H, V), the same embedding layer a transformer uses.

  • An embedding is the first weight matrix. With a one-hot input, \(W_x\,\text{onehot}(i)\) is just column \(i\) of \(W_x\). The embedding table does that lookup directly, without building a \(V\)-dimensional vector, and the cell's own \(W_x\) then maps \(d \to H\).
  • No position signal. Nothing is added for position: order comes from the recurrence itself, since step \(t\) only runs after step \(t-1\). A transformer needs position embeddings because attention ignores order.
  • Vocabularies. In the LSTM era they were usually whole words (30k–100k) with an <UNK> token for unseen ones, or characters. Transformers use subwords (BPE, WordPiece), so no word is unknown.
  • Initialization. The table was often filled with pretrained word2vec or GloVe vectors, then frozen or fine-tuned. Those give one vector per word type (“bank” is the same in every sentence); the recurrence adds the context in \(h_t\).
  • Weight tying. A language model's output layer \(W_y\) (\(V \times H\)) can share weights with \(E\) when \(H = d\), or with a projection in between (Press & Wolf, 2017): fewer parameters and usually lower perplexity. GPT and BERT do the same.
  • Cost. \(V \cdot d\) is often the largest block of parameters in a small word-level model, another reason to tie weights or use subwords.
  • Padding. Batches pad every sequence to one length with a pad id. padding_idx keeps that row at zero, and packing (pack_padded_sequence) stops the RNN stepping through the padding.
  • Before all this: how text becomes tokens, bag of words, TF-IDF, n-gram models, word2vec and GloVe are covered in depth in the Classical NLP note.
  • Not text? For time series or sensor data there's no vocabulary: \(x_t\) is the feature vector itself, or a linear projection of it. Only categorical features (a store id, the day of the week) get embedding tables, concatenated with the numeric ones.

In code

# one sequence x: (T, d);  W_x: (H, d)  W_h: (H, H)  b: (H,)
h = zeros(H)                          # h_0
states = []
for t in range(T):
    a = W_x @ x[t] + W_h @ h + b      # score: (H,)
    h = tanh(a)                       # new state: (H,)
    states.append(h)
logits = W_y @ h + b_y                # many-to-one head: (K,)
# many-to-many: logits_t = W_y @ states[t] + b_y at every t

The same \(W_x\), \(W_h\), \(W_y\) are used at every step, so the model handles any length, and a pattern learned at one position is recognized at every other. The trouble is that \(h\) does two jobs at once: it is the memory, and it is the output. And every step, all of it goes through \(W_h\) and a tanh.

  • Forgetting. Something seen at step \(k\) reaches step \(T\) only after \(T - k\) passes through that matrix and squash, like a photocopy of a photocopy.
  • No way to leave a slot alone. Keeping a fact means \(W_h\) has to pass that slot through unchanged every step, and the tanh must not squash it. Nothing in the design makes that easy.
  • Vanishing gradients. The gradient from step \(T\) back to step \(k\) is a product of one factor per step in between:
\[ \frac{\partial h_T}{\partial h_k} = \prod_{t=k+1}^{T} \text{diag}\!\left(1 - h_t^2\right) W_h \]

How much one factor can stretch a vector is at most the tanh slope (never above 1, and near 0 when a unit saturates) times the largest stretch of \(W_h\) (its largest singular value). If that's below 1, the product shrinks like a number below 1 raised to the power \(T - k\): exponentially with distance. If \(W_h\) stretches some direction by more than 1, it can explode instead. A weight's gradient is a sum of one share per step, so the shares from distant steps are exponentially smaller than the nearby ones, and the network learns only short-range patterns. That's the same product as the forgetting, read backwards: the state forgets step \(k\), and the gradient can't teach it to remember. Clipping by norm tames explosions but can't fix vanishing. That needs a different update rule.

02What a gate is

\[ \text{gate}_t = \sigma\big(W [h_{t-1}, x_t] + b\big) \in (0, 1)^H \]
  • A vector of dials, one per memory slot. It's a sigmoid because it answers “how much?”: 0 blocks, 1 passes.
  • Used by element-wise multiplication, \(\text{gate} \odot \text{signal}\): slot \(j\) lets through the fraction \(\text{gate}_j\).
  • Recomputed every step from the current input and the previous output, so how much passes depends on the data. Compare the RNN, where how much of the past carries over is fixed by \(W_h\), the same matrix every step.

Trap

A gate is not a weight matrix. It's an activation, a vector computed fresh each step. Each gate has its own weight matrix that computes it.

03The LSTM

Long short-term memory (Hochreiter and Schmidhuber, 1997) gives the network a notebook, the cell state \(c\), kept separate from what it says, \(h\). Each step it decides what to erase, what to write, and what to read out.

One step, in order

In: \(x_t\) (what just happened), \(h_{t-1}\) (what I said last step) and \(c_{t-1}\) (my notebook). Stack the first two into \(u_t = [h_{t-1}, x_t]\), then ask it four questions, each with its own weights:

BlockFormulaQuestion it answers
forget\(f_t = \sigma(W_f u_t + b_f)\)Which old notes do I keep?
input\(i_t = \sigma(W_i u_t + b_i)\)How much of the draft should I write?
candidate\(g_t = \tanh(W_g u_t + b_g)\)What would I write?
output\(o_t = \sigma(W_o u_t + b_o)\)What should I show right now?
\[ \begin{aligned} c_t &= f_t \odot c_{t-1} + i_t \odot g_t \\ h_t &= o_t \odot \tanh(c_t) \end{aligned} \]

Out: \(c_t\) goes only to the next step. \(h_t\) goes to the prediction and to the next step, inside \(u_{t+1}\). Both start at zero. And \(c_{t-1}\) has no separate equation: it is this same update, one step earlier.

One LSTM step, in code

def lstm_step(x, h, c):               # x: (d,)  h, c: (H,)
    u = concat([h, x])                # (H + d,)
    z = W @ u + b                     # one stacked matmul: W (4H, H+d) -> (4H,)
    i, f, g, o = split(z, 4)          # PyTorch order i, f, g, o; each (H,)
    i, f, o = sigmoid(i), sigmoid(f), sigmoid(o)   # dials in (0, 1)
    g = tanh(g)                       # the draft, in (-1, 1)
    c = f * c + i * g                 # erase part, write part
    h = o * tanh(c)                   # read part out
    return h, c

h, c = zeros(H), zeros(H)
for t in range(T):
    h, c = lstm_step(x[t], h, c)

What counts as a block

A block is anything computed from \([h_{t-1}, x_t]\) through its own weight matrix: \(\sigma\) or \(\tanh\) of \(W u_t + b\). The LSTM has four: \(f\), \(i\), \(g\) and \(o\). The inputs and states \(x\), \(h\) and \(c\) have no weights of their own; \(c_t\) and \(h_t\) are just multiplied and added together from the blocks. Each block holds \(H(H + d) + H\) numbers (PyTorch stores one more \(H\) of bias), which is where the parameter count comes from. (The GRU has three: \(z\), \(r\) and its draft \(\tilde h\).)

From \(h_t\) to a prediction

The cell only produces the hidden state. To predict anything, put an ordinary output layer, the “head”, on top. It is not part of the cell:

\[ \hat y_t = \text{softmax}(W_y h_t + b_y), \qquad W_y \text{ is } K \times H \]
  • Many-to-many (tag every word, flag every payment): apply the same \(W_y\) to every \(h_t\).
  • Many-to-one (one label per message): apply it once, usually to the last state \(h_T\), or to a summary of all of them (their mean, max, or an attention-weighted sum).
  • Use a sigmoid for a yes/no label and no activation for regression. In PyTorch, nn.LSTM returns every \(h_t\) plus the final \((h_T, c_T)\); you add nn.Linear(H, K) yourself.

Each block, briefly

Forget gate f · keep

Per slot: keep (1) or erase (0) the old note. Fraud example: keep “new payees lately” through normal payments, and wipe it once the customer verifies with the bank.

Stuck at 1: the notebook can never be cleared, so it fills and saturates. Stuck at 0: no memory at all.

Candidate g · draft

The new content: exactly a plain RNN update, \(\tanh(W_g u_t + b_g)\).

It's tanh, not sigmoid, because a write must push a slot up or down, as evidence for or against.

Input gate i · write?

Is the draft worth writing? It's separate from \(g\) because what an input says and whether to record it are different questions. A routine payment has content, but nothing worth noting.

With one set of weights doing both jobs, they pull against each other. The 1997 paper called this the input weight conflict.

Output gate o · show

Which notes to expose now. It lets a fact sit silently (a password reset three steps ago) until it matters (a large transfer arrives), so stored facts don't disturb every step.

The tanh before it keeps \(h\) bounded, because \(c\) is a sum of writes and can grow.

A natural question

Why does \(h\) go to the next step if the notebook \(c\) already holds everything?

  • \(h\) is read from the notebook. It's \(o \odot \tanh(c)\), so the next step's gates do see the notebook, through this filtered readout.
  • Keeping two states means hiding isn't forgetting. The output gate can hide a slot from everything downstream (the prediction and the next gates) while \(c\) keeps it safe. With one vector doing both jobs, hiding a fact would erase it. That's exactly the GRU's trade-off.
  • \(c\) is unbounded (a sum of writes), so feeding it raw into sigmoid gates would saturate them. \(h\) is bounded.
  • Letting the gates read \(c\) directly was tried. These are “peephole” connections (Gers and Schmidhuber, 2000), and they gave no consistent gain.

Many slots, four moves

\(c\) is one vector of \(H\) slots (often 64 to 512), each with its own dials, so it holds many facts at once: one slot counting new payees, another overwritten every step. Real slots aren't that tidy, since facts get spread across several, but the picture holds. Because \(f\) and \(i\) are separate, each slot has four moves:

fiResultMove
10\(c_{t-1}\)keep: ignore this input
01\(g_t\)replace: erase, then write
11\(c_{t-1} + g_t\)accumulate: keep and add, so it can count
000wipe: clear without writing

Parameters: four blocks, each an \(H \times (H + d)\) matrix plus \(H\) biases, so \(4\,[H(H+d) + H]\). In code they're one \(4H \times (H+d)\) matrix multiply, split into quarters (PyTorch orders them i, f, g, o).

  • PyTorch's second bias. nn.LSTM keeps two bias vectors per block: \(b_{ih}\) on the input projection and \(b_{hh}\) on the hidden projection, so each pre-activation is \(W_{ih} x_t + b_{ih} + W_{hh} h_{t-1} + b_{hh}\). They're always added together, so only \(b_{ih} + b_{hh}\) matters and one of them is redundant. It's there because cuDNN's formulation puts a bias on each of its two matrix multiplies, and PyTorch matches it so the fast kernel can run the same weights. Hence PyTorch's \(4\,[H(H+d) + 2H]\).
  • Not tied to \(T\). The same weights run at every step, so the count is the same for any sequence length.
  • Per layer. In a stack, layer 2 reads layer 1's \(h\), so its input size is \(H\) instead of \(d\) (\(2H\) if bidirectional). A bidirectional layer has two independent sets of weights, one per direction, so it doubles the count.

04The GRU

The gated recurrent unit (Cho et al., 2014) is a simpler LSTM. It merges the notebook and the output into one state \(h\) and uses two gates instead of three.

\[ \begin{aligned} z_t &= \sigma(W_z [h_{t-1}, x_t] + b_z) \\ r_t &= \sigma(W_r [h_{t-1}, x_t] + b_r) \\ \tilde h_t &= \tanh\big(W_n [\, r_t \odot h_{t-1},\; x_t \,] + b_n\big) \\ h_t &= (1 - z_t) \odot h_{t-1} + z_t \odot \tilde h_t \end{aligned} \]
ThingShapeNote
\(W_z, W_r, W_n\)\(H \times (H + d)\) eachStacked in code as \(3H \times (H + d)\); PyTorch order r, z, n
\(z_t, r_t, \tilde h_t, h_t\)\(H\)Everything is one \(H\)-vector per step
Parameters\(3[H(H + d) + H]\); PyTorch \(3[H(H + d) + 2H]\)25% fewer than an LSTM of the same size: 3 blocks instead of 4

PyTorch's GRU also keeps two bias vectors per block, but here the pair isn't fully redundant. Its draft is \(\tanh(W_{in} x_t + b_{in} + r_t \odot (W_{hn} h_{t-1} + b_{hn}))\), so \(b_{hn}\) is scaled by the reset gate while \(b_{in}\) isn't. Only the \(r\) and \(z\) bias pairs collapse into one.

One GRU step, in code

def gru_step(x, h):                   # z = how much to write
    z = sigmoid(W_z @ concat([h, x]) + b_z)
    r = sigmoid(W_r @ concat([h, x]) + b_r)
    draft = tanh(W_n @ concat([r * h, x]) + b_n)   # r filters the past before the matmul
    return (1 - z) * h + z * draft                 # blend old and new
  • Update gate \(z\): how much to write. A slider: the new state sits a fraction \(z\) of the way from the old state to the draft, so it keeps \(1 - z\) and writes \(z\). It does the jobs of the LSTM's forget and input gates at once, tied together: \(f = 1 - z\), \(i = z\).
  • Reset gate \(r\): what the draft is built from. It multiplies the old state before it enters the draft's matrix. With \(r \approx 0\) the draft is built from the input alone, a fresh start (a new sentence, a new session); with \(r \approx 1\) it is a plain RNN update. It erases nothing by itself: erasing happens when \(z\) writes that draft over the old state.
  • No output gate. The state is always fully shown, to the output and to every gate at the next step. It can't hide a fact without forgetting it, which is the trade the LSTM avoids by keeping two states.
  • The cost of tying. Every write erases the same fraction, and the state is an average of old and new, so it stays within the draft's range and can't count. It wins some of this back because the draft reads the old state through \(r\): old memory can ride inside the new write.

A natural question

In the LSTM the input gate multiplies the draft, \(i \odot g\). Why does the GRU's \(r\) act on \(h_{t-1}\) inside the draft instead?

  • Because it has a different job. “How much to write” is already done by \(z\). If \(r\) multiplied the draft's output, it would be a second volume knob for the same thing. Acting on the draft's input gives it a new job: choosing what the draft is computed from.
  • It stands in for the LSTM's output gate, for the draft only. An LSTM's draft reads \(h_{t-1} = o \odot \tanh(c_{t-1})\), a version of the memory already filtered by the output gate. A GRU's \(h\) is the raw memory, so without \(r\) every draft would be built from the entire past, relevant or not.
  • It sits before the matrix multiply so the past's contribution can be dropped slot by slot while the input's is kept; once \(W_n\) mixes them, they can't be pulled apart. (PyTorch applies \(r\) to \(W_{hn} h_{t-1}\), after the past's own multiply but still apart from the input's.)
  • Cho et al. (2014) found that units tracking short-range patterns lean on the reset gate and long-range ones on the update gate. A one-gate version, the minimal gated unit (Zhou et al., 2016), does about as well on several tasks, so the split helps but isn't essential.

Trap: conventions

Here \(z\) means “how much to write” (as in Chung et al., 2014). The original paper and PyTorch flip it: \(h_t = z \odot h_{t-1} + (1 - z) \odot \tilde h_t\), so their \(z\) means “keep”. PyTorch also applies \(r\) after the matrix multiply: \(\tanh(W_{in} x + b_{in} + r \odot (W_{hn} h + b_{hn}))\). Say which convention you're using.

05How the gradient flows: RNN → LSTM → GRU

Backprop through time asks, for every step: if this step's state had been slightly different, how much would the loss change? For an early step, the answer is carried backward one step at a time, and each step multiplies it by how strongly this step's memory depends on the previous step's. Everything that separates the three cells in training comes down to that per-step multiplier.

Two kinds of gradient come out of the walk back:

  • State gradients (\(\delta h\), \(\delta c\)) travel backward through time, one step at a time.
  • Weight gradients are collected along the way. Every weight is shared across steps, so its gradient is a sum of one share per step, each share being (gradient at the output of its multiply) × (what it multiplied)\(^\top\). An early step only adds a real share if its state gradient survived the walk.

Plain RNN: a weight matrix and a slope at every step

\[ \delta h_{t-1} = W_h^\top\big[\delta h_t \odot (1 - h_t^2)\big] \;+\; \text{(gradient from step } t{-}1\text{'s own output)} \]

Each step back goes through the tanh's slope, \(1 - h_t^2\), and then through \(W_h^\top\). Chained over many steps, that's \(\prod \text{diag}(1 - h_t^2) W_h\). If each factor shrinks the gradient, it vanishes exponentially. If \(W_h\) stretches it, it can explode. It's the same fixed matrix at every step, with no way to say “pass this through untouched”.

LSTM: a second path with no weights on it

\[ \delta c_t = \underbrace{\delta h_t \odot o_t \odot \big(1 - \tanh^2 c_t\big)}_{\text{from this step's output}} \;+\; \underbrace{\delta c_{t+1} \odot f_{t+1}}_{\text{from the future, along the cell}} \]
  • The second term is the highway. Going back one step along the cell multiplies the gradient by \(f\), and only \(f\): no weight matrix and no tanh slope. With \(f \approx 1\), it arrives almost whole. With \(f = 1\), the update is \(c_t = c_{t-1} + i_t \odot g_t\), a residual connection through time (the 1997 paper's “constant error carousel”).
  • The gates learn from side branches. Three come from \(\delta c_t\), the output gate from \(\delta h_t\):
    \[ \begin{aligned} \delta f_t &= \delta c_t \odot c_{t-1} \\ \delta i_t &= \delta c_t \odot g_t \\ \delta g_t &= \delta c_t \odot i_t \\ \delta o_t &= \delta h_t \odot \tanh(c_t) \end{aligned} \]
    Each is multiplied by its activation's slope, then feeds its weight's gradient and, through those weights, \(\delta h_{t-1}\). These side paths do go through matrices, so they can still explode, which is why LSTMs are still clipped.
  • Memory and gradient fade together. Unrolled, the cell is a sum of every past write, faded by the forget gates since: \(c_t = \sum_k \big(\prod_{j>k} f_j\big) \odot i_k \odot g_k\). The gradient back to each write is that same product, so the cell keeps a fact exactly as long as it can learn from it. Start the forget bias at 1, so \(f \approx 0.73\). At 0, \(f \approx 0.5\) halves memory and gradient every step, like a plain RNN. Not 10, though: there \(f\) sits a hair below 1, where the sigmoid is flat, so the side branch that trains the gate carries almost no gradient and the gate can barely learn to forget.

GRU: the blend is the highway

\[ \delta h_{t-1} = \delta h_t \odot (1 - z_t) \;+\; \text{(paths through } z_t,\ r_t \text{ and } \tilde h_t\text{)} \]

The direct term comes from the \((1 - z) \odot h_{t-1}\) half of the blend, so it's multiplied only by \(1 - z\), a gate value, just like the LSTM's \(f\). While the GRU keeps (\(z \approx 0\)), the gradient passes back almost whole. When it writes (\(z \approx 1\)), the direct path is cut, and what comes back has to go through the draft (\(r \odot h_{t-1}\) inside \(\tilde h\)). That path runs through \(W_n\) and a tanh slope, like a plain RNN.

That's the whole fix in one line: replace a fixed matrix times a slope with a learned dial. Attention goes one step further and removes the walk altogether, because every token connects to every other in one step (see Transformers).

Trap

“The forget gate is a sigmoid, whose slope is at most 0.25. Doesn't the gradient vanish through it?” No. Along the cell, the gradient is multiplied by the gate's value \(f\), not its slope. The slope only appears on the side branch that trains the gate's own weights.

In practice: clipping and truncated BPTT

  • Clip by norm, not by value. Clipping by norm rescales the whole gradient when its length passes a threshold \(\tau\), so the direction stays the same and only the step shrinks. Clipping by value caps each component on its own, which tilts the direction toward the small components. An exploding gradient usually comes from a steep cliff in the loss: its direction is still useful, it's just far too long (Pascanu et al., 2013). Neither version helps a vanishing gradient, since both only shrink.
\[ \begin{aligned} \text{by norm:}\quad g &\leftarrow g \cdot \min\!\big(1,\ \tau / \lVert g \rVert\big) \\ \text{by value:}\quad g_j &\leftarrow \max(-\tau, \min(\tau, g_j)) \end{aligned} \]
  • Truncated BPTT. Full BPTT stores every step's activations, so memory grows with the sequence length, and a stream that never ends can't be backpropagated at all. Instead, process it in chunks of \(k\) steps: carry the state forward from chunk to chunk, but detach it at each boundary (both \(h\) and \(c\) in an LSTM), so gradients stop there. The price is that the gradient can't teach dependencies longer than \(k\) steps, so pick \(k\) at least as long as the ones you care about.

  • GRU for shorter sequences: there's no separate cell, so retention rests on the update gate alone, and that same gate also decides writing. (2015) found the learning rate was the most important hyperparameter, while most variants changed little. Against transformers, RNNs lose because they run step by step (no parallel training across time), squeeze the past into a fixed-size state, and need \(n\) steps to connect token 1 to token \(n\). Attention keeps every past state and connects any two in one step, at a cost that grows as \(n^2\). RNNs still win for streaming with constant work per event, such as per-transaction scoring or on-device models, because a new event only updates a fixed-size state, while a transformer has to attend over every past event and its cache keeps growing.

08Bidirectional, stacked and in practice

Bidirectional LSTMs

Run two LSTMs over the sequence: one left to right, one right to left. At each position, join their states, so every position sees its whole context:

\[ \begin{aligned} \overrightarrow{h}_t &= \text{LSTM}(x_t, \overrightarrow{h}_{t-1}) \\ \overleftarrow{h}_t &= \text{LSTM}(x_t, \overleftarrow{h}_{t+1}) \\ h_t &= [\overrightarrow{h}_t ;\, \overleftarrow{h}_t] \end{aligned} \]
  • Built for tagging and for labelling finished sequences. Examples: named-entity tags, part-of-speech tags, or one codon per amino acid. A stacked bi-LSTM is a common baseline for exactly that. Each output sees both sides of its position.
  • Costs: twice the parameters and compute, and the output size doubles to \(2H\).
  • Not for generation or live scoring. The backward half has already read the future. For a per-step prediction made in real time, that's leakage: offline metrics look great, and production can't supply the future.
  • Many-to-one with a bi-LSTM: join the forward pass's last state with the backward pass's first state (each has read the whole sequence), or pool over all positions.
  • Its successors: ELMo (2018) used stacked bi-LSTM language models as contextual word embeddings. BERT then replaced the LSTMs with a bidirectional transformer.

Stacking

  • Layer 2 reads layer 1's sequence of \(h\)'s as its inputs. Two to four layers is typical; more rarely helps, because each layer adds another set of weights and another non-linear step between input and output at every time step, so deep stacks get harder to train and the gains flatten out.
  • Put dropout between layers, not on the step-to-step connection. Fresh noise on \(h_{t-1} \to h_t\) at every step corrupts the memory. If you want it there, use the same mask at every step (“variational” dropout).
  • Residual connections between layers help deep stacks; Google's 2016 translation system used 8 LSTM layers with residuals.

09Interview questions

Answer out loud first, then open the answer. Each answer stands on its own: the one-line answer first, then how it works, then why.

Recurrent networks

1Why do plain RNNs struggle with long sequences?

The same matrix and squash are applied to the whole memory at every step, so old information, and the gradient that could teach the network to keep it, shrink (or blow up) exponentially with distance.

All of \(h\) is rewritten every step, and going back from step \(T\) to step \(k\) multiplies one Jacobian per step in between (the matrix of how each slot of a state depends on each slot of the one before):

\[ \begin{aligned} h_t &= \tanh(W_x x_t + W_h h_{t-1} + b) \\ \frac{\partial h_T}{\partial h_k} &= \prod_{t=k+1}^{T} \text{diag}(1 - h_t^2)\, W_h \end{aligned} \]
  • Why it vanishes. One factor can stretch a vector by at most the tanh slope (never above 1, near 0 when a unit saturates) times the largest stretch of \(W_h\) (its largest singular value). If that's below 1, the product shrinks like a number below 1 raised to the power \(T - k\).
  • Why it can explode. If \(W_h\) stretches some direction by more than 1 and the units aren't saturated, the same power can grow instead.
  • Why that stops learning. A weight's gradient is a sum of one share per step, and shares from distant steps are exponentially smaller, so only short-range patterns get learned.
  • Why forgetting is the same thing. Information from step \(k\) reaches step \(T\) through the same chain, so it fades the same way.

Fixes: clipping shrinks an exploding gradient but can't enlarge a vanishing one; that needs gates (LSTM, GRU) or attention.

2Walk me through an LSTM step. What does each gate do?

Each step erases part of the cell, writes a gated draft into it, and reads a filtered view of it out as \(h\).

Stack \(u_t = [h_{t-1}, x_t]\) and compute four blocks, each with its own weights, then update the cell and the output:

\[ \begin{aligned} f_t &= \sigma(W_f u_t + b_f) \\ i_t &= \sigma(W_i u_t + b_i) \\ g_t &= \tanh(W_g u_t + b_g) \\ o_t &= \sigma(W_o u_t + b_o) \\ c_t &= f_t \odot c_{t-1} + i_t \odot g_t \\ h_t &= o_t \odot \tanh(c_t) \end{aligned} \]
  • Forget \(f\): which old notes to keep, slot by slot.
  • Candidate \(g\): the draft of new content, exactly a plain RNN update.
  • Input \(i\): how much of the draft to write. It's separate from \(g\) because what an input says and whether it's worth recording are different questions.
  • Output \(o\): which notes to show now, to the prediction and to the next step's gates.

Why these activations. The gates are sigmoids because each is a per-slot fraction in \((0, 1)\). The draft is tanh because a write must push a slot up or down. The tanh on \(c\) keeps \(h\) bounded, since \(c\) is a sum of writes and can grow. All four read \([h_{t-1}, x_t]\) because whether to keep or write depends on both what just arrived and the context so far.

Likely follow-up: “Why does this help the gradient?” One step back along \(c\) multiplies only by \(f_t\), with no weight matrix, so where \(f \approx 1\) the gradient survives.

3Cell state vs hidden state: why keep both?

\(c\) is the memory and \(h\) is what the cell shows. Keeping them apart lets the LSTM hide a fact without forgetting it, keeps the gates' inputs bounded, and leaves a weight-free gradient path.

\[ \begin{aligned} c_t &= f_t \odot c_{t-1} + i_t \odot g_t \\ h_t &= o_t \odot \tanh(c_t) \end{aligned} \]
  • Hide without forgetting. \(o_t\) can zero a slot in \(h\), so neither the prediction nor the next gates see it, while \(c\) keeps it for later. With one state, as in the GRU, hiding a fact means overwriting it.
  • Bounded inputs for the gates. \(c\) is a running sum of writes, so it's unbounded; fed raw into the next step's sigmoids, it would saturate them. \(h\) lies in \((-1, 1)\).
  • A clean gradient path. \(c\) is only multiplied by \(f\) and added to, so the gradient along it meets no weight matrix. \(h\) goes through all four weight blocks at the next step.

How much it matters: in ablations the output gate is the least important gate (Jozefowicz 2015), and the GRU does without the split at little cost. Letting the gates read \(c\) directly (peepholes) gave no consistent gain.

4How does the LSTM fix vanishing gradients? Can it still vanish or explode?

It adds a memory path whose per-step gradient multiplier is a learned gate value, \(f_t\), instead of a weight matrix times a tanh slope.

On the direct path along the cell, one step back is just:

\[ \frac{\partial c_t}{\partial c_{t-1}} = \text{diag}(f_t) \]
  • Why that helps. No \(W_h\) and no tanh slope sit on this path. Where the network learns \(f \approx 1\), the gradient arrives almost whole: a residual connection through time, the 1997 paper's “constant error carousel”.
  • Why it's controllable. \(f\) is recomputed every step from the data, per slot, so a slot can hold for a long stretch and then reset. A fixed \(W_h\) can't do that.
  • It can still vanish. Over a gap of \(T - k\) steps the factor is a product of \(f\)'s. Below 1 it still decays, just far more slowly and under the model's control.
  • It can still explode. \(h_{t-1}\) feeds every gate and the draft through weight matrices. Those side paths behave like an RNN's, so LSTMs are still clipped.

Likely follow-up: “The sigmoid's slope is at most 0.25, so doesn't the gradient vanish through \(f\)?” No. Along the cell it's multiplied by the gate's value; the slope only appears on the side branch that trains the gate's own weights.

5Why initialize the forget-gate bias to 1? Why not 10?

At 1 the cell starts out remembering, so long-range gradients exist from the start; at 10 the gate is saturated and can't learn to forget.

At initialization the weights are small, so \(f \approx \sigma(b_f)\), and the cell path multiplies both memory and gradient by \(f\) every step.

  • Bias 0: \(f \approx 0.5\), so memory and gradient halve every step, much like a plain RNN. Long-range dependencies send almost no gradient back, so the model never discovers it should keep them.
  • Bias 1: \(f \approx 0.73\). The cell leans toward keeping, gradients reach further back, and the gate is still in the sigmoid's responsive range, so it can learn to move either way.
  • Bias 10: \(f\) is a hair below 1, where the sigmoid is flat. Its slope is almost zero, so the gradient into the gate's weights vanishes and it can barely learn to forget. The cell then piles up writes until \(\tanh(c)\) saturates.

Evidence: Jozefowicz et al. (2015) found this one change closes the LSTM–GRU gap.

In practice: Keras does it by default; PyTorch doesn't. PyTorch's forget slice is [H:2H] (order i, f, g, o). \(b_{ih}\) and \(b_{hh}\) are added together, so set it in one of them only; both would give an effective bias of 2.

6Why separate forget and input gates instead of i = 1 − f?

Separate gates let a slot keep and write at the same time, which is what lets an LSTM accumulate and count. Tied gates force every write to erase.

With separate gates each slot has four moves: keep (\(f = 1, i = 0\)), replace (\(0, 1\)), accumulate (\(1, 1\)) and wipe (\(0, 0\)). Tie them and the update becomes a weighted average of old and new:

\[ c_t = f_t \odot c_{t-1} + (1 - f_t) \odot g_t \]
  • Every write erases. Writing a fraction \(1 - f\) of the draft costs exactly that fraction of the old memory, so remembering and writing compete.
  • It can't count. An average of values in \((-1, 1)\) stays in \((-1, 1)\), so the cell can't grow with the number of events. Weiss et al. (2018) showed the LSTM can count and the GRU, whose gates are tied, can't.
  • The gradient pays too. The cell path's multiplier is \(f = 1 - i\), so each strong write also cuts the gradient flowing back past it.

The other side: coupled gates (CIFG in Greff 2015, and the GRU) do about as well on standard benchmarks, which rarely need counting. Separate gates matter when the task accumulates evidence over time, such as counting events in a session.

7Write the GRU and compare it with the LSTM.

The GRU merges the cell and the output into one state, ties forget and input into one update gate, and drops the output gate: three blocks instead of four.

\[ \begin{aligned} z_t &= \sigma(W_z[h_{t-1}, x_t] + b_z) \\ r_t &= \sigma(W_r[h_{t-1}, x_t] + b_r) \\ \tilde h_t &= \tanh(W_n[r_t \odot h_{t-1}, x_t] + b_n) \\ h_t &= (1 - z_t) \odot h_{t-1} + z_t \odot \tilde h_t \end{aligned} \]

In words: \(z\) slides the state between its old value and the draft, and \(r\) decides how much of the past the draft is built from.

  • Tied gates: \(z\) plays the LSTM's input gate, and \(1 - z\) its forget gate. Every write erases the same fraction, and the state stays within the draft's range, so it can't count.
  • No output gate: the whole state is always shown, so it can't hide a fact without overwriting it.
  • Gradient: one step back along the blend multiplies by \(1 - z_t\), the GRU's version of the LSTM's \(f_t\).
  • Cost: 3 weight blocks instead of 4, so 25% fewer parameters and multiplies per step.

Convention trap: the original paper and PyTorch write \(h_t = z \odot h_{t-1} + (1 - z) \odot \tilde h_t\), so their \(z\) means “keep”, and PyTorch applies \(r\) after the hidden matrix multiply. Say which one you're using.

8What does the reset gate do that the update gate doesn't?

The update gate decides how much of the state to replace; the reset gate decides what the replacement is built from.

\[ \begin{aligned} \tilde h_t &= \tanh(W_n[r_t \odot h_{t-1}, x_t] + b_n) \\ h_t &= (1 - z_t) \odot h_{t-1} + z_t \odot \tilde h_t \end{aligned} \]
  • \(r \approx 0\): the draft ignores the past and is built from \(x_t\) alone, a fresh start (a new sentence, a new session). Then \(z\) decides whether to write it over the old state.
  • \(r \approx 1\): the draft is a plain RNN update from the whole past.
  • Why \(z\) alone isn't enough. Without \(r\), every draft is computed from the entire old state, so \(z\) could only blend the old state with something that already contains it. There'd be no way to build new content that isn't coloured by irrelevant history.
  • Why \(r\) doesn't erase. It only filters the draft's input. Nothing leaves the state until \(z\) writes the draft over it.

Evidence: Cho et al. (2014) saw units that track short-range patterns lean on \(r\), and long-range ones on \(z\). The minimal gated unit (Zhou et al., 2016) uses one gate for both jobs and does about as well on several tasks, so a separate reset gate helps but isn't essential.

9Which LSTM gate matters most? What happens if you remove each one?

The forget gate matters most and the output gate least. Each removal hurts in proportion to the job it leaves undone (Greff 2015; Jozefowicz 2015 ranks forget, then input, then output):

  • Forget gate: the biggest drop, on every task. The cell can only add, so it can't reset at boundaries, it grows on long streams, and \(\tanh(c)\) saturates. That's why it was added in 2000.
  • Tanh on the cell output: also a large drop. \(h = o \odot c\) becomes unbounded, so the next step's gates saturate and activations can blow up.
  • Input gate: every draft is added in full on top of what's stored, so routine inputs keep corrupting stored facts. Worse on speech and handwriting.
  • Output gate: the whole cell is always shown, as in a GRU, so stored facts disturb every step. Also worse on speech and handwriting, though Jozefowicz ranks it the least important gate.
  • Candidate's tanh: writes become unbounded too. It hurt on some tasks.
  • Peepholes, or coupling \(i = 1 - f\): no significant change on benchmarks.

Why the forget gate ranks first: it sets both how long memory lasts and how far the gradient reaches, the two things a plain RNN lacks. Greff also found the learning rate was the most important hyperparameter, while most variants changed little.

10Hypothetical: swap the sigmoid gates for ReLU, tanh, or hard 0/1 switches?

Each one breaks something a gate needs: a value between 0 and 1, the meaning “how much”, or a gradient.

  • ReLU: unbounded above, so a forget value above 1 multiplies the memory by more than 1 every step, and \(c\) and its gradient explode. Below zero it outputs exactly 0 with zero slope, so a gate that closes can get stuck closed.
  • Tanh: range \((-1, 1)\). A negative gate flips a slot's sign every step, so the memory oscillates and “how much to keep” loses its meaning. Rescaled to \((1 + \tanh)/2\), it's just a sigmoid again.
  • Hard 0/1: a step function's slope is 0 almost everywhere, so no gradient reaches the gate's weights and they never learn when to open. Workarounds exist (a straight-through estimator, or a piecewise-linear “hard sigmoid” with a slope in the middle), but they approximate the smooth gate.

Why the sigmoid fits: it's bounded in \((0, 1)\), so it reads as a fraction; it's smooth with a non-zero slope everywhere, so training can move it; and it starts mid-range, with room to open or close.

11Hypothetical: what if f = 1 and i = 1 at every step?

The cell becomes a pure running sum of drafts: it never forgets, grows without limit, and saturates its own readout.

\[ \begin{aligned} c_t &= c_{t-1} + g_t \\ &= \sum_{k \le t} g_k \end{aligned} \]
  • Why it grows. Nothing ever scales \(c\) back, so it's a sum of \(t\) drafts, and its size can keep growing with the length of the stream.
  • Why \(h\) stops responding. \(h = o \odot \tanh(c)\), and once \(|c|\) is large, \(\tanh(c)\) is stuck near \(\pm 1\). New inputs barely change the output.
  • Why learning stalls. The gradient from each output into the cell carries the factor \(1 - \tanh^2(c_t)\), near zero when saturated. The cell path itself multiplies by exactly 1, a perfect carousel, but almost nothing gets onto it.
  • Why it can't reset. With \(f = 1\), facts from a previous sentence or session stay forever and pollute the next.

History: this is close to the original 1997 LSTM, which had no forget gate. Gers et al. (2000) added one because the cell failed on long continuous streams in exactly this way.

12Parameter count for an LSTM and a GRU?

Count weight blocks: an LSTM has 4, a GRU 3 (so 25% fewer), a plain RNN 1. PyTorch stores one extra bias vector per block.

One block maps the \(H + d\) numbers of \([h_{t-1}, x_t]\) to \(H\) outputs: \(H(d + H)\) weights plus \(H\) biases. So:

\[ \begin{aligned} \text{LSTM, textbook} &= 4\,[H(d + H) + H] \\ \text{LSTM, PyTorch} &= 4\,[H(d + H) + 2H] \\ \text{GRU, textbook} &= 3\,[H(d + H) + H] \\ \text{GRU, PyTorch} &= 3\,[H(d + H) + 2H] \end{aligned} \]
  • PyTorch's second bias. nn.LSTM and nn.GRU keep \(b_{ih}\) on the input projection and \(b_{hh}\) on the hidden one. In an LSTM each pre-activation is \(W_{ih}x_t + b_{ih} + W_{hh}h_{t-1} + b_{hh}\), so only the sum \(b_{ih} + b_{hh}\) matters: the second vector is redundant, kept to match cuDNN's formulation.
  • The GRU is not fully redundant. Its candidate is \(\tanh(W_{in}x_t + b_{in} + r_t \odot (W_{hn}h_{t-1} + b_{hn}))\), so \(b_{hn}\) sits inside the reset gate's product while \(b_{in}\) doesn't. Only the \(r\) and \(z\) pairs collapse to one.
  • Independent of \(T\): the same weights run at every step.
  • Per layer: in a stack, layer 2 reads layer 1's states, so its input size is \(H\), or \(2H\) if bidirectional. A bidirectional layer has two sets of weights, so it doubles the count.

A plain RNN is one block, \(H(d + H) + H\) (PyTorch adds \(H\)). An output head over \(K\) classes adds \(KH + K\), and an embedding table for a vocabulary of \(V\) tokens adds \(Vd\).

13LSTM or GRU, and why did transformers replace both?

Neither wins consistently, so try both. Lean GRU for small data, shorter sequences or tight latency; lean LSTM for long dependencies, counting, or plenty of data.

  • GRU is cheaper per step. 3 weight blocks instead of 4, so 25% fewer parameters and multiplies: lower latency and memory.
  • GRU can suit small data. Fewer parameters leave less room to overfit, though the effect is modest.
  • GRU is weaker over long spans. With no separate cell, retention rests on the update gate alone, and that gate also decides writing: keeping a slot means not writing to it, and every write erases part of it, so old facts erode. And with no output gate to protect a hidden memory, it can't hide a fact without erasing it (ablations rate this as minor).
  • LSTM can hold and count. Separate forget and input gates keep and add at once, so a slot holds a fact or a count while others are rewritten.
  • Evidence: Chung et al. (2014) found them comparable; Jozefowicz et al. (2015) found the GRU ahead except on language modelling, until a forget bias of 1 closed the gap; Greff et al. (2015) found no variant reliably beat the standard LSTM.

Why transformers replaced both: attention trains all positions in parallel, links any two tokens in one step and keeps every past token, at \(n^2\) cost. RNNs still suit streaming, with constant work per event.

14Is the LSTM's \(h_t\) the prediction? How do you get an output?

No. \(h_t\) is the hidden state; a separate output layer, the head, turns it into a prediction.

\[ \hat y_t = \text{softmax}(W_y h_t + b_y), \qquad W_y \text{ is } K \times H \]
  • Why a separate head. \(h_t\) holds \(H\) numbers in \((-1, 1)\) chosen to be useful memory, not \(K\) probabilities that sum to 1. The head maps the state to the task's outputs, so the same cell serves any task by changing only the head.
  • Many-to-many (tag every token, flag every payment): apply the same head at every step and add up the per-step losses.
  • Many-to-one (one label per message): apply it once, to \(h_T\) or to a pool of all the \(h_t\). Pooling (mean, max or attention weights) helps on long inputs, because \(h_T\) is dominated by the most recent steps.
  • Activation by task: softmax for one of \(K\) classes, sigmoid for yes/no or multi-label, none for regression.

In PyTorch: nn.LSTM returns every \(h_t\) (\(B \times T \times H\)) plus the final \((h_T, c_T)\); you add nn.Linear(H, K). With padded batches, read each sequence's true last state, not the padding's.

15Why does the GRU's reset gate act on \(h_{t-1}\) inside the draft, when the LSTM's input gate multiplies the draft's output?

Because the GRU's update gate already does the input gate's job, so \(r\) gets a different one: choosing what the draft is computed from.

\[ \begin{aligned} \text{LSTM write} &= i_t \odot g_t \\ \text{GRU draft} &= \tanh(W_n[r_t \odot h_{t-1}, x_t] + b_n) \end{aligned} \]
  • Not a second volume knob. “How much to write” is \(z\), in \(h_t = (1 - z_t) \odot h_{t-1} + z_t \odot \tilde h_t\). An \(r\) on the draft's output would duplicate it.
  • A stand-in for the output gate, for the draft only. An LSTM's draft reads \(h_{t-1} = o \odot \tanh(c_{t-1})\), memory already filtered by \(o\). A GRU's \(h\) is the raw memory, so without \(r\) every draft would be built from all of the past, relevant or not.
  • Why before the matrix multiply. Once \(W_n\) mixes \(h_{t-1}\) and \(x_t\), their contributions can't be pulled apart. Filtering \(h_{t-1}\) first drops the past slot by slot while keeping the input.

PyTorch's variant computes \(\tanh(W_{in}x_t + b_{in} + r_t \odot (W_{hn}h_{t-1} + b_{hn}))\): \(r\) acts after the hidden multiply but still apart from the input's. It's faster, because \(W_{hn}h_{t-1}\) can run in the same multiply as the other gates' hidden projections, and the accuracy difference is usually small.

16Compare how the gradient flows back through time in an RNN, an LSTM and a GRU.

On the memory path, one step back multiplies the gradient by a fixed matrix and a slope in an RNN, but only by a learned gate value in an LSTM (\(f_t\)) or a GRU (\(1 - z_t\)).

\[ \begin{aligned} \text{RNN:}\quad \delta h_{t-1} &= W_h^\top\big[\delta h_t \odot (1 - h_t^2)\big] + \dots \\ \text{LSTM:}\quad \delta c_{t-1} &= \delta c_t \odot f_t + \dots \\ \text{GRU:}\quad \delta h_{t-1} &= \delta h_t \odot (1 - z_t) + \dots \end{aligned} \]

Here \(\delta x\) means the gradient of the loss with respect to \(x\). The “\(\dots\)” are the other routes: the step's own output and, in the gated cells, the paths through the gates and the draft.

  • RNN: the same \(W_h\) and a tanh slope at every step, so over many steps the product vanishes or explodes exponentially, and nothing in the model can stop it.
  • LSTM and GRU: no weight matrix and no slope on the direct path. The multiplier is per slot and per step, and the network can hold it near 1 where memory is needed: a near-identity highway, like a residual connection through time.
  • What still goes through weights: the gates and the draft read \(h_{t-1}\) through matrices, so those side paths can still explode. Clip by norm.
  • GRU detail: when it writes (\(z \approx 1\)), the direct path is cut, and the gradient has to go back through the draft, which behaves like an RNN step.

Likely follow-up: attention removes the walk altogether, since any two tokens are one step apart.

17What is truncated backprop through time, and what does it cost you?

Backpropagate through only the last \(k\) steps of a long sequence, while still carrying the state forward through all of it.

Split the stream into chunks of \(k\) steps. Run each chunk forward from the previous chunk's final state, backprop and update within the chunk, then detach the state: keep its values, but cut the graph, so the next chunk's gradients stop at the boundary.

h, c = zeros(H), zeros(H)
for chunk, target in chunks(stream, k):
    h, c = h.detach(), c.detach()       # keep values, cut the graph
    out, (h, c) = lstm(chunk, (h, c))   # forward k steps
    loss(head(out), target).backward(); clip(); step()
  • Why truncate. Full BPTT stores every step's activations, so memory grows with sequence length, and you get one update per whole sequence. A stream that never ends can't be backpropagated at all.
  • Why detach. Without it the graph would chain back through every earlier chunk, and memory would grow just as before. In an LSTM, detach both \(h\) and \(c\).
  • The cost. The gradient can't teach dependencies longer than \(k\) steps. The state still carries information further, but only what was stored for shorter-range reasons. Pick \(k\) at least as long as the dependencies you care about.
18Gradient clipping: by norm or by value? Why?

By norm: it shrinks an oversized gradient without changing its direction, while clipping by value changes the direction.

\[ \begin{aligned} \text{by norm:}\quad g &\leftarrow g \cdot \min\!\big(1,\ \tau / \lVert g \rVert\big) \\ \text{by value:}\quad g_j &\leftarrow \max(-\tau, \min(\tau, g_j)) \end{aligned} \]
  • By norm looks at the whole gradient vector, usually the global norm over all parameters. If it's longer than \(\tau\), it's scaled down to length \(\tau\). Every component shrinks by the same factor, so the step points the same way, just shorter.
  • By value caps each component separately. Big components are cut and small ones aren't, so the direction tilts toward the small ones.
  • Why direction matters. An exploding gradient in an RNN usually comes from a steep cliff in the loss surface. Its direction is still informative, it's just far too long, and a full step would throw the weights off the cliff (Pascanu et al., 2013).
  • What clipping can't do: it only shrinks, so it does nothing for vanishing gradients.

Choosing \(\tau\): log the gradient norm and set \(\tau\) a little above its typical value, so only spikes get clipped. Common choices are 1–5 for RNNs and 1.0 for transformers.

19What is teacher forcing, and what is exposure bias?

Teacher forcing trains a sequence generator on the true previous token instead of its own guess. Exposure bias is the mismatch this creates at inference, when the model has to condition on its own outputs.

\[ \begin{aligned} \text{training:}\quad s_t &= \text{LSTM}_{\text{dec}}(y_{t-1},\ s_{t-1}) \\ \text{inference:}\quad s_t &= \text{LSTM}_{\text{dec}}(\hat y_{t-1},\ s_{t-1}) \end{aligned} \]

In words: \(s_t\) is the decoder's state; in training its input is the true previous token \(y_{t-1}\), at inference the model's own guess \(\hat y_{t-1}\).

  • Why teacher forcing. Each step's loss is computed on a correct prefix, so one early mistake doesn't derail the rest, and gradients stay stable. In a transformer it's also what makes training parallel: every input is known, so all positions run at once under a causal mask.
  • Why exposure bias hurts. The model never saw its own errors in training. One wrong token at inference puts it in a state it never learned from, the next guess is worse, and errors compound over long outputs.
  • Fixes: scheduled sampling (Bengio et al., 2015) gradually swaps true inputs for the model's own predictions during training; sequence-level training scores whole generated outputs with a metric (via REINFORCE); and beam search at inference reduces the damage of one early slip.

Trade-off: scheduled sampling breaks a transformer's parallel training, so large language models mostly accept the bias and lean on scale and decoding instead.

20When can't you use a bidirectional LSTM?

Whenever the prediction at step \(t\) has to be made before the future arrives: generation, forecasting, and live per-event scoring.

\[ h_t = [\overrightarrow{h}_t ;\, \overleftarrow{h}_t], \qquad \overleftarrow{h}_t \text{ has read } x_t, \dots, x_T \]
  • Why it leaks. The backward pass starts at the end of the sequence, so \(\overleftarrow{h}_t\) already contains everything after \(t\). For a fraud score per payment, that means using payments that hadn't happened yet: offline metrics look great, and production can't supply the future.
  • Why it can't generate. Producing token \(t+1\) needs a state that depends only on tokens up to \(t\). The backward half would need the very tokens it's trying to produce.
  • Where it shines: labelling a finished sequence, such as tagging, named entities, one codon per amino acid, or one label for a whole message. Every position benefits from both sides.
  • Costs: twice the parameters and compute, an output of size \(2H\), and no output until the whole sequence has arrived.

Many-to-one with a bi-LSTM: join the forward pass's last state with the backward pass's first state, since each has read the whole sequence, or pool over all positions.
