Study notes · Deep learning

Sequence models

RNNs, LSTMs and GRUs: how each one carries memory, how the gradient flows back through it, what every part does, and what breaks without it.

Diagrams, worked maths and practice questions · cell state chidden state hgates

In short

  1. A plain RNN carries one vector, \(h\), and rewrites all of it every step through the same matrix and a tanh. Old information fades, and so does the gradient that could teach it to stay.
  2. A gate is a vector of dials between 0 and 1, recomputed every step from \([h_{t-1}, x_t]\) through its own weight matrix, and multiplied slot by slot into a signal.
  3. The LSTM keeps a notebook \(c\) that changes only by erasing (\(\times f\)) and writing (\(+\, i \odot g\)), and shows \(h = o \odot \tanh(c)\). The GRU merges notebook and output into one \(h\): the update gate \(z\) decides keep-versus-write, the reset gate \(r\) decides what the draft is built from.
  4. Neither cell predicts anything by itself: a separate output layer reads \(h_t\), \(\hat y_t = \text{softmax}(W_y h_t + b_y)\).
  5. Backprop: on the memory path, each step back multiplies the gradient by \(\text{diag}(1 - h_t^2) W_h\) in an RNN, by \(f_t\) in an LSTM and by \(1 - z_t\) in a GRU. Swapping a fixed matrix and slope for a learned dial is the whole fix.
  6. In ablations, the forget gate (started near 1) matters most and the output gate least; the learning rate matters more than any architectural tweak.

01The plain RNN’s problem

\[ h_t = \tanh(W_x x_t + W_h h_{t-1} + b), \qquad \hat y_t = \text{softmax}(W_y h_t + b_y) \]

Shapes

Notation for the whole page: \(d\) = input size (e.g. the embedding size), \(H\) = hidden size, \(K\) = number of classes (or the vocabulary size \(V\)), \(T\) = sequence length, \(B\) = batch size.

ThingShapeNote
\(x_t\)\(d\)One step's input
\(h_{t-1},\ a_t,\ h_t\)\(H\)State, score, new state
\(W_x\)\(H \times d\)Input → state
\(W_h\)\(H \times H\)State → state (square: the state maps onto itself)
\(b\)\(H\)
\(W_y,\ b_y\)\(K \times H,\ K\)The output head
\(z_t,\ \hat y_t\)\(K\)Logits, probabilities
Whole sequence in / all states out\(T \times d\) / \(T \times H\)One row per step
Weight gradient share \(\delta a_t\, x_t^\top\)\((H \times 1)(1 \times d) = H \times d\)Same shape as \(W_x\) ✓

In code everything gets a leading batch dimension, and rows are examples, so a step is \(h_t = \tanh(x_t W_x^\top + h_{t-1} W_h^\top + b)\) with \(x_t\) of shape \(B \times d\) and \(h_t\) of shape \(B \times H\). PyTorch's nn.RNN(d, H, batch_first=True) takes \(B \times T \times d\) and returns all states as \(B \times T \times H\), plus the last one as \(\text{layers} \times B \times H\). Parameters: \(H(d + H) + H\) for the cell, plus \(KH + K\) for the head.

Where \(x_t\) comes from: tokens to vectors

For text, \(x_t\) is a learned embedding, exactly as in a transformer. The text is split into tokens, each token is an id in a vocabulary of size \(V\), and the id picks one row of an embedding table \(E\):

\[ \begin{aligned} X &= E[\text{ids}] \\ h_t &= \text{RNN}(x_t,\ h_{t-1}) \\ z_t &= W_y h_t + b_y \end{aligned} \]
ThingShapeNote
Token ids\(B \times T\)Integers in \([0, V)\)
Embedding table \(E\)\(V \times d\)One learned row per token
\(X = E[\text{ids}]\)\(B \times T \times d\)The cell reads \(x_t\), one \(B \times d\) slice per step
\(h_t\)\(B \times H\)The state after step \(t\)
\(W_y\) / logits \(z_t\)\(V \times H\) / \(B \times V\)Next-token scores for a language model

In PyTorch that's nn.Embedding(V, d) → nn.LSTM(d, H) → nn.Linear(H, V), the same embedding layer a transformer uses.

  • An embedding is the first weight matrix. With a one-hot input, \(W_x\,\text{onehot}(i)\) is just column \(i\) of \(W_x\). The embedding table does that lookup directly, without building a \(V\)-dimensional vector, and the cell's own \(W_x\) then maps \(d \to H\).
  • No position signal. Nothing is added for position: order comes from the recurrence itself, since step \(t\) only runs after step \(t-1\). A transformer needs position embeddings because attention ignores order.
  • Vocabularies. In the LSTM era they were usually whole words (30k–100k) with an <UNK> token for unseen ones, or characters. Transformers use subwords (BPE, WordPiece), so no word is unknown.
  • Initialization. The table was often filled with pretrained word2vec or GloVe vectors, then frozen or fine-tuned. Those give one vector per word type (“bank” is the same in every sentence); the recurrence adds the context in \(h_t\).
  • Weight tying. A language model's output layer \(W_y\) (\(V \times H\)) can share weights with \(E\) when \(H = d\), or with a projection in between (Press & Wolf, 2017): fewer parameters and usually lower perplexity. GPT and BERT do the same.
  • Cost. \(V \cdot d\) is often the largest block of parameters in a small word-level model, another reason to tie weights or use subwords.
  • Padding. Batches pad every sequence to one length with a pad id. padding_idx keeps that row at zero, and packing (pack_padded_sequence) stops the RNN stepping through the padding.
  • Not text? For time series or sensor data there's no vocabulary: \(x_t\) is the feature vector itself, or a linear projection of it. Only categorical features (a store id, the day of the week) get embedding tables, concatenated with the numeric ones.

In code

# one sequence x: (T, d);  W_x: (H, d)  W_h: (H, H)  b: (H,)
h = zeros(H)                          # h_0
states = []
for t in range(T):
    a = W_x @ x[t] + W_h @ h + b      # score: (H,)
    h = tanh(a)                       # new state: (H,)
    states.append(h)
logits = W_y @ h + b_y                # many-to-one head: (K,)
# many-to-many: logits_t = W_y @ states[t] + b_y at every t

The same \(W_x\), \(W_h\), \(W_y\) are used at every step, so the model handles any length, and a pattern learned at one position is recognized at every other. The trouble is that \(h\) does two jobs at once: it is the memory, and it is the output. And every step, all of it goes through \(W_h\) and a tanh.

  • Forgetting. Something seen at step \(k\) reaches step \(T\) only after \(T - k\) passes through that matrix and squash, like a photocopy of a photocopy.
  • No way to leave a slot alone. Keeping a fact means \(W_h\) has to pass that slot through unchanged every step, and the tanh must not squash it. Nothing in the design makes that easy.
  • Vanishing gradients. The gradient from step \(T\) back to step \(k\) is a product of one factor per step in between:
\[ \frac{\partial h_T}{\partial h_k} = \prod_{t=k+1}^{T} \text{diag}\!\left(1 - h_t^2\right) W_h \]

If each factor shrinks things, the product shrinks exponentially with distance. If one stretches, it can explode. That's the same product as the forgetting, read backwards: the state forgets step \(k\), and the gradient can't teach it to remember. Clipping by norm tames explosions but can't fix vanishing. That needs a different update rule.

02What a gate is

\[ \text{gate}_t = \sigma\big(W [h_{t-1}, x_t] + b\big) \in (0, 1)^H \]
  • A vector of dials, one per memory slot. It's a sigmoid because it answers “how much?”: 0 blocks, 1 passes.
  • Used by element-wise multiplication, \(\text{gate} \odot \text{signal}\): slot \(j\) lets through the fraction \(\text{gate}_j\).
  • Recomputed every step from the current input and the previous output, so how much passes depends on the data. Compare the RNN, where how much of the past carries over is fixed by \(W_h\), the same matrix every step.

Trap

A gate is not a weight matrix. It's an activation, a vector computed fresh each step. Each gate has its own weight matrix that computes it.

03The LSTM

Long short-term memory (Hochreiter and Schmidhuber, 1997) gives the network a notebook, the cell state \(c\), kept separate from what it says, \(h\). Each step it decides what to erase, what to write, and what to read out.

One step, in order

In: \(x_t\) (what just happened), \(h_{t-1}\) (what I said last step) and \(c_{t-1}\) (my notebook). Stack the first two into \(u_t = [h_{t-1}, x_t]\), then ask it four questions, each with its own weights:

BlockFormulaQuestion it answers
forget\(f_t = \sigma(W_f u_t + b_f)\)Which old notes do I keep?
input\(i_t = \sigma(W_i u_t + b_i)\)How much of the draft should I write?
candidate\(g_t = \tanh(W_g u_t + b_g)\)What would I write?
output\(o_t = \sigma(W_o u_t + b_o)\)What should I show right now?
\[ c_t = f_t \odot c_{t-1} + i_t \odot g_t \qquad\qquad h_t = o_t \odot \tanh(c_t) \]

Out: \(c_t\) goes only to the next step. \(h_t\) goes to the prediction and to the next step, inside \(u_{t+1}\). Both start at zero. And \(c_{t-1}\) has no separate equation: it is this same update, one step earlier.

Shapes

ThingShapeNote
\(u_t = [h_{t-1}; x_t]\)\(H + d\)Stacked input
\(W_f, W_i, W_g, W_o\)\(H \times (H + d)\) eachIn code: one stacked \(4H \times (H + d)\) matrix, one multiply, split into quarters
\(b_f, b_i, b_g, b_o\)\(H\) each
\(f_t, i_t, g_t, o_t\)\(H\)One dial (or draft value) per slot
\(c_t,\ h_t\)\(H\)Same size, so \(\odot\) works slot by slot
PyTorch weight_ih_l0 / weight_hh_l0\(4H \times d\) / \(4H \times H\)The same stacked matrix, split by input; order i, f, g, o
nn.LSTM output, \((h_n, c_n)\)\(B \times T \times H\), \((\text{layers} \times B \times H)\) eachBidirectional: output \(B \times T \times 2H\)

For \(d = 100\) and \(H = 128\) that is \(4 \times (128 \times 228 + 128) = 117{,}248\).

One LSTM step, in code

def lstm_step(x, h, c):               # x: (d,)  h, c: (H,)
    u = concat([h, x])                # (H + d,)
    z = W @ u + b                     # one stacked matmul: W (4H, H+d) -> (4H,)
    i, f, g, o = split(z, 4)          # PyTorch order i, f, g, o; each (H,)
    i, f, o = sigmoid(i), sigmoid(f), sigmoid(o)   # dials in (0, 1)
    g = tanh(g)                       # the draft, in (-1, 1)
    c = f * c + i * g                 # erase part, write part
    h = o * tanh(c)                   # read part out
    return h, c

h, c = zeros(H), zeros(H)
for t in range(T):
    h, c = lstm_step(x[t], h, c)

What counts as a block

A block is anything computed from \([h_{t-1}, x_t]\) through its own weight matrix: \(\sigma\) or \(\tanh\) of \(W u_t + b\). The LSTM has four: \(f\), \(i\), \(g\) and \(o\). The inputs and states \(x\), \(h\) and \(c\) have no weights of their own; \(c_t\) and \(h_t\) are just multiplied and added together from the blocks. Each block holds \(H(H + d) + H\) numbers, which is where the parameter count comes from. (The GRU has three: \(z\), \(r\) and its draft \(\tilde h\).)

From \(h_t\) to a prediction

The cell only produces the hidden state. To predict anything, put an ordinary output layer, the “head”, on top. It is not part of the cell:

\[ \hat y_t = \text{softmax}(W_y h_t + b_y), \qquad W_y \text{ is } K \times H \]
  • Many-to-many (tag every word, flag every payment): apply the same \(W_y\) to every \(h_t\).
  • Many-to-one (one label per message): apply it once, usually to the last state \(h_T\), or to a summary of all of them (their mean, max, or an attention-weighted sum).
  • Use a sigmoid for a yes/no label and no activation for regression. In PyTorch, nn.LSTM returns every \(h_t\) plus the final \((h_T, c_T)\); you add nn.Linear(H, K) yourself.

Each block, briefly

Forget gate f · keep

Per slot: keep (1) or erase (0) the old note. Fraud example: keep “new payees lately” through normal payments, and wipe it once the customer verifies with the bank.

Stuck at 1: the notebook can never be cleared, so it fills and saturates. Stuck at 0: no memory at all.

Candidate g · draft

The new content: exactly a plain RNN update, \(\tanh(W_g u_t + b_g)\).

It's tanh, not sigmoid, because a write must push a slot up or down, as evidence for or against.

Input gate i · write?

Is the draft worth writing? It's separate from \(g\) because what an input says and whether to record it are different questions. A routine payment has content, but nothing worth noting.

With one set of weights doing both jobs, they pull against each other. The 1997 paper called this the input weight conflict.

Output gate o · show

Which notes to expose now. It lets a fact sit silently (a password reset three steps ago) until it matters (a large transfer arrives), so stored facts don't disturb every step.

The tanh before it keeps \(h\) bounded, because \(c\) is a sum of writes and can grow.

A natural question

Why does \(h\) go to the next step if the notebook \(c\) already holds everything?

  • \(h\) is read from the notebook. It's \(o \odot \tanh(c)\), so the next step's gates do see the notebook, through this filtered readout.
  • Keeping two states means hiding isn't forgetting. The output gate can hide a slot from everything downstream (the prediction and the next gates) while \(c\) keeps it safe. With one vector doing both jobs, hiding a fact would erase it. That's exactly the GRU's trade-off.
  • \(c\) is unbounded (a sum of writes), so feeding it raw into sigmoid gates would saturate them. \(h\) is bounded.
  • Letting the gates read \(c\) directly was tried. These are “peephole” connections (Gers and Schmidhuber, 2000), and they gave no consistent gain.

Many slots, four moves

\(c\) is one vector of \(H\) slots (often 64 to 512), each with its own dials, so it holds many facts at once: one slot counting new payees, another overwritten every step. Real slots aren't that tidy, since facts get spread across several, but the picture holds. Because \(f\) and \(i\) are separate, each slot has four moves:

fiResultMove
10\(c_{t-1}\)keep: ignore this input
01\(g_t\)replace: erase, then write
11\(c_{t-1} + g_t\)accumulate: keep and add, so it can count
000wipe: clear without writing

Parameters: four blocks, each an \(H \times (H + d)\) matrix plus \(H\) biases, so \(4\,[H(H+d) + H]\). In code they're one \(4H \times (H+d)\) matrix multiply, split into quarters (PyTorch orders them i, f, g, o, and keeps two bias vectors per block).

04The GRU

The gated recurrent unit (Cho et al., 2014) is a simpler LSTM. It merges the notebook and the output into one state \(h\) and uses two gates instead of three.

\[ z_t = \sigma(W_z [h_{t-1}, x_t] + b_z) \qquad r_t = \sigma(W_r [h_{t-1}, x_t] + b_r) \]
\[ \tilde h_t = \tanh\big(W_n [\, r_t \odot h_{t-1},\; x_t \,] + b_n\big) \qquad h_t = (1 - z_t) \odot h_{t-1} + z_t \odot \tilde h_t \]
ThingShapeNote
\(W_z, W_r, W_n\)\(H \times (H + d)\) eachStacked in code as \(3H \times (H + d)\); PyTorch order r, z, n
\(z_t, r_t, \tilde h_t, h_t\)\(H\)Everything is one \(H\)-vector per step
Parameters\(3[H(H + d) + H]\)25% fewer than an LSTM of the same size

One GRU step, in code

def gru_step(x, h):                   # z = how much to write
    z = sigmoid(W_z @ concat([h, x]) + b_z)
    r = sigmoid(W_r @ concat([h, x]) + b_r)
    draft = tanh(W_n @ concat([r * h, x]) + b_n)   # r filters the past before the matmul
    return (1 - z) * h + z * draft                 # blend old and new
  • Update gate \(z\): how much to write. A slider: the new state sits a fraction \(z\) of the way from the old state to the draft, so it keeps \(1 - z\) and writes \(z\). It does the jobs of the LSTM's forget and input gates at once, tied together: \(f = 1 - z\), \(i = z\).
  • Reset gate \(r\): what the draft is built from. It multiplies the old state before it enters the draft's matrix. With \(r \approx 0\) the draft is built from the input alone, a fresh start (a new sentence, a new session); with \(r \approx 1\) it is a plain RNN update. It erases nothing by itself: erasing happens when \(z\) writes that draft over the old state.
  • No output gate. The state is always fully shown, to the output and to every gate at the next step. It can't hide a fact without forgetting it, which is the trade the LSTM avoids by keeping two states.
  • The cost of tying. Every write erases the same fraction, and the state is an average of old and new, so it stays within the draft's range and can't count. It wins some of this back because the draft reads the old state through \(r\): old memory can ride inside the new write.

A natural question

In the LSTM the input gate multiplies the draft, \(i \odot g\). Why does the GRU's \(r\) act on \(h_{t-1}\) inside the draft instead?

  • Because it has a different job. “How much to write” is already done by \(z\). If \(r\) multiplied the draft's output, it would be a second volume knob for the same thing. Acting on the draft's input gives it a new job: choosing what the draft is computed from.
  • It stands in for the LSTM's output gate, for the draft only. An LSTM's draft reads \(h_{t-1} = o \odot \tanh(c_{t-1})\), a version of the memory already filtered by the output gate. A GRU's \(h\) is the raw memory, so without \(r\) every draft would be built from the entire past, relevant or not.
  • It sits before the matrix multiply so the past's contribution can be dropped slot by slot while the input's is kept; once \(W_n\) mixes them, they can't be pulled apart. (PyTorch applies \(r\) to \(W_{hn} h_{t-1}\), after the past's own multiply but still apart from the input's.)
  • Cho et al. (2014) found that units tracking short-range patterns lean on the reset gate and long-range ones on the update gate. A one-gate version, the minimal gated unit (Zhou et al., 2016), does about as well on several tasks, so the split helps but isn't essential.

Who does what

The same jobs exist in all three cells. What changes is which piece does them.

Trap: conventions

Here \(z\) means “how much to write” (as in Chung et al., 2014). The original paper and PyTorch flip it: \(h_t = z \odot h_{t-1} + (1 - z) \odot \tilde h_t\), so their \(z\) means “keep”. PyTorch also applies \(r\) after the matrix multiply: \(\tanh(W_{in} x + b_{in} + r \odot (W_{hn} h + b_{hn}))\). Say which convention you're using.

05How the gradient flows: RNN → LSTM → GRU

Backprop through time asks, for every step: if this step's state had been slightly different, how much would the loss change? For an early step, the answer is carried backward one step at a time, and each step multiplies it by how strongly this step's memory depends on the previous step's. Everything that separates the three cells in training comes down to that per-step multiplier.

Two kinds of gradient come out of the walk back:

  • State gradients (\(\delta h\), \(\delta c\)) travel backward through time, one step at a time.
  • Weight gradients are collected along the way. Every weight is shared across steps, so its gradient is a sum of one share per step, each share being (gradient at the output of its multiply) × (what it multiplied)\(^\top\). An early step only adds a real share if its state gradient survived the walk.

Plain RNN: a weight matrix and a slope at every step

\[ \delta h_{t-1} = W_h^\top\big[\delta h_t \odot (1 - h_t^2)\big] \;+\; \text{(gradient from step } t{-}1\text{'s own output)} \]

Each step back goes through the tanh's slope, \(1 - h_t^2\), and then through \(W_h^\top\). Chained over many steps, that's \(\prod \text{diag}(1 - h_t^2) W_h\). If each factor shrinks the gradient, it vanishes exponentially. If \(W_h\) stretches it, it can explode. It's the same fixed matrix at every step, with no way to say “pass this through untouched”.

LSTM: a second path with no weights on it

\[ \delta c_t = \underbrace{\delta h_t \odot o_t \odot \big(1 - \tanh^2 c_t\big)}_{\text{from this step's output}} \;+\; \underbrace{\delta c_{t+1} \odot f_{t+1}}_{\text{from the future, along the cell}} \]
  • The second term is the highway. Going back one step along the cell multiplies the gradient by \(f\), and only \(f\): no weight matrix and no tanh slope. With \(f \approx 1\), it arrives almost whole. With \(f = 1\), the update is \(c_t = c_{t-1} + i_t \odot g_t\), a residual connection through time (the 1997 paper's “constant error carousel”).
  • The gates learn from side branches. Three come from \(\delta c_t\), the output gate from \(\delta h_t\):
    \[ \begin{aligned} \delta f_t &= \delta c_t \odot c_{t-1} \\ \delta i_t &= \delta c_t \odot g_t \\ \delta g_t &= \delta c_t \odot i_t \\ \delta o_t &= \delta h_t \odot \tanh(c_t) \end{aligned} \]
    Each is multiplied by its activation's slope, then feeds its weight's gradient and, through those weights, \(\delta h_{t-1}\). These side paths do go through matrices, so they can still explode, which is why LSTMs are still clipped.
  • Memory and gradient fade together. Unrolled, the cell is a sum of every past write, faded by the forget gates since: \(c_t = \sum_k \big(\prod_{j>k} f_j\big) \odot i_k \odot g_k\). The gradient back to each write is that same product, so the cell keeps a fact exactly as long as it can learn from it. Start the forget bias at 1, so \(f \approx 0.73\). At 0, \(f \approx 0.5\) halves memory and gradient every step, like a plain RNN.

GRU: the blend is the highway

\[ \delta h_{t-1} = \delta h_t \odot (1 - z_t) \;+\; \text{(paths through } z_t,\ r_t \text{ and } \tilde h_t\text{)} \]

The direct term comes from the \((1 - z) \odot h_{t-1}\) half of the blend, so it's multiplied only by \(1 - z\), a gate value, just like the LSTM's \(f\). While the GRU keeps (\(z \approx 0\)), the gradient passes back almost whole. When it writes (\(z \approx 1\)), the direct path is cut, and what comes back has to go through the draft (\(r \odot h_{t-1}\) inside \(\tilde h\)). That path runs through \(W_n\) and a tanh slope, like a plain RNN.

Multiplier per step on the memory pathWeight matrix in it?tanh slope in it?Set by
RNN\(\text{diag}(1 - h_t^2)\,W_h\)YesYesFixed weights, the same every step

BPTT, in code (plain RNN, loss at the last step)

# stored from the forward pass: x[1..T], h[0..T] with h[0] = 0
dh = W_y.T @ (y_hat - y)              # gradient arriving at h_T
dW_x, dW_h, db = 0, 0, 0
for t in range(T, 0, -1):             # t = T ... 1
    da = dh * (1 - h[t] ** 2)         # back through tanh
    dW_x += outer(da, x[t])           # every step adds a share
    dW_h += outer(da, h[t - 1])
    db   += da
    dh = W_h.T @ da                   # one step back in time: x W_h^T
clip_by_norm([dW_x, dW_h, db], max_norm=5.0)
# LSTM: the cell carries dc back with only  dc = dc_next * f_next  (+ the term from h)

That's the whole fix in one line: replace a fixed matrix times a slope with a learned dial. Attention goes one step further and removes the walk altogether, because every token connects to every other in one step (see Transformers).

Trap

“The forget gate is a sigmoid, whose slope is at most 0.25. Doesn't the gradient vanish through it?” No. Along the cell, the gradient is multiplied by the gate's value \(f\), not its slope. The slope only appears on the side branch that trains the gate's own weights.

06What the research found

Most of this comes from two big ablation studies: Greff et al. (2015, “LSTM: A Search Space Odyssey”, 8 variants on speech, handwriting and music) and Jozefowicz et al. (2015, over 10,000 architectures searched).

ChangeWhat happened
Original LSTM, no forget gateOn long continuous streams the cell grows without limit. The forget gate was added to fix this. Gers et al., 2000
Remove the forget gateThe biggest drop of any change, on every task. Greff 2015
Remove the tanh on the cell outputAlso a large drop: \(h\) becomes unbounded. Greff 2015
Remove the input gate, the output gate or the candidate's tanhWorse on speech and handwriting, no effect on music. Greff 2015

The takeaways

  • The forget gate, started near 1, is the heart of it. The output gate matters least, which is why the GRU can drop it.
  • Greff also found the learning rate mattered more than any architectural variant, and the hyperparameters barely interact. Tune the learning rate first.
  • A neat theory result (Tallec and Ollivier, 2018): gates fall out of asking a recurrent model to be robust to time being stretched or squeezed. That suggests setting the forget bias from the dependency lengths you expect (“chrono” initialization).

In practice, try both gated cells: the gap between them is usually smaller than the effect of features and tuning. Against transformers, RNNs lose because they run step by step (no parallel training across time), squeeze the past into a fixed-size state, and need \(n\) steps to connect token 1 to token \(n\). Attention keeps every past state and connects any two in one step, at a cost that grows as \(n^2\). RNNs still win for streaming with constant work per event: per-transaction scoring, or on-device.

08Bidirectional, stacked and in practice

Bidirectional LSTMs

Run two LSTMs over the sequence: one left to right, one right to left. At each position, join their states, so every position sees its whole context:

\[ \overrightarrow{h}_t = \text{LSTM}(x_t, \overrightarrow{h}_{t-1}) \qquad \overleftarrow{h}_t = \text{LSTM}(x_t, \overleftarrow{h}_{t+1}) \qquad h_t = [\overrightarrow{h}_t ;\, \overleftarrow{h}_t] \]
  • Built for tagging and for labelling finished sequences. Examples: named-entity tags, part-of-speech tags, or one codon per amino acid. A stacked bi-LSTM is a common baseline for exactly that. Each output sees both sides of its position.
  • Costs: twice the parameters and compute, and the output size doubles to \(2H\).
  • Not for generation or live scoring. The backward half has already read the future. For a per-step prediction made in real time, that's leakage: offline metrics look great, and production can't supply the future.
  • Many-to-one with a bi-LSTM: join the forward pass's last state with the backward pass's first state (each has read the whole sequence), or pool over all positions.
  • Its successors: ELMo (2018) used stacked bi-LSTM language models as contextual word embeddings. BERT then replaced the LSTMs with a bidirectional transformer.

Stacking

  • Layer 2 reads layer 1's sequence of \(h\)'s as its inputs. Two to four layers is typical; more rarely helps.
  • Put dropout between layers, not on the step-to-step connection. Fresh noise on \(h_{t-1} \to h_t\) at every step corrupts the memory. If you want it there, use the same mask at every step (“variational” dropout).
  • Residual connections between layers help deep stacks; Google's 2016 translation system used 8 LSTM layers with residuals.

  • Teacher forcing: while training a generator, feed it the true previous token, not its own guess. It's faster and more stable, but at inference it meets its own mistakes for the first time (“exposure bias”).
  • Variable lengths: pad to the longest, then mask or pack (pack_padded_sequence) and read each sequence's true last state. Without that, padding steps keep changing the state.
  • Checklist: forget bias 1, clipping by norm (1–5), Adam with a tuned learning rate, standardized inputs, truncated BPTT for long streams (detach both \(h\) and \(c\)).

09Interview questions

Answer out loud first, then open the answer.

Recurrent networks

1Why do plain RNNs struggle with long sequences?

One vector is both the memory and the output, and every step all of it goes through \(W_h\) and a tanh. Old information fades, and the gradient back to old steps is a product of one Jacobian, \(\text{diag}(1 - h^2) W_h\), per step. Below 1 per step it vanishes exponentially, above 1 it can explode. Forgetting and vanishing are the same product read in two directions. Clipping fixes explosions only.

2Walk me through an LSTM step. What does each gate do?

Stack \(h_{t-1}\) and \(x_t\). The forget gate chooses what to keep from \(c_{t-1}\), the candidate \(g\) is the draft of new content, the input gate chooses how much of the draft to write, and the output gate chooses what to show:

\[ \begin{aligned} c_t &= f \odot c_{t-1} + i \odot g \\ h_t &= o \odot \tanh(c_t) \end{aligned} \]

The gates are sigmoids because they're per-slot fractions. The candidate is tanh because a write must go up or down.

3Cell state vs hidden state: why keep both?

\(c\) is long-term storage: unbounded, only scaled and added to, never read directly from outside. \(h = o \odot \tanh(c)\) is the bounded readout used by the output and the next step's gates. Two states mean the cell can hide a fact without forgetting it. The GRU, with one state, can't.

4How does the LSTM fix vanishing gradients? Can it still vanish or explode?

Along the cell, \(\partial c_t/\partial c_{t-1} = \text{diag}(f_t)\): no weight matrix, no tanh slope. With \(f\) near 1 the gradient survives many steps (the constant error carousel, a residual connection through time). It can still vanish over very long gaps, since it's a product of \(f\)'s. The paths through \(h\) go through weights and can explode, so clip.

5Why initialize the forget-gate bias to 1? Why not 10?

At initialization gates sit near σ(bias). A bias of 0 gives \(f \approx 0.5\), halving memory and gradient every step. A bias of 1 gives \(f \approx 0.73\), so the cell starts out remembering. At 10, the sigmoid is flat, so the gate can barely learn to forget. Jozefowicz et al. found this one change closes the LSTM–GRU gap. Keras does it by default; PyTorch doesn't.

6Why separate forget and input gates instead of i = 1 − f?

Separate gates allow four moves: keep, replace, accumulate (keep and write) and wipe (erase without writing). Tied gates make the update a weighted average, so every write erases the same fraction, the state can't exceed the draft so it can't count, and every write cuts the gradient by \(1 - i\). The other side: coupled gates (CIFG, and the GRU) do about as well on most benchmarks.

7Write the GRU and compare it with the LSTM.
\[ \begin{aligned} z &= \sigma(W_z[h_{t-1}, x_t]) \\ r &= \sigma(W_r[h_{t-1}, x_t]) \\ \tilde h &= \tanh(W_n[r \odot h_{t-1}, x_t]) \\ h_t &= (1-z) \odot h_{t-1} + z \odot \tilde h \end{aligned} \]

One state instead of two. The update gate is the LSTM's forget and input tied (\(f = 1 - z\), \(i = z\)). There's no output gate, and \(r\) controls how much past the draft sees. Three blocks instead of four. Mention that PyTorch's \(z\) means “keep”.

8What does the reset gate do that the update gate doesn't?

The update gate decides how much of the state to replace. The reset gate decides what the replacement is built from: with \(r \approx 0\) the draft ignores the past, a fresh start. Without \(r\), every draft would mix in the whole past, so the GRU couldn't cleanly start over at a sentence or session boundary.

9Which LSTM gate matters most? What happens if you remove each one?

Forget gate: removing it causes the biggest drop on every task, because the cell can't reset. Output tanh: removing it also hurts badly, since \(h\) becomes unbounded. Input gate, output gate, candidate tanh: removing them hurts on some tasks. Peepholes and coupling make no significant difference (Greff 2015). Jozefowicz ranks them forget, then input, then output.

10Hypothetical: swap the sigmoid gates for ReLU, tanh, or hard 0/1 switches?

ReLU: a gate above 1 amplifies the memory every step, so it explodes. Tanh: a negative gate flips the memory's sign, so it's no longer “how much to keep”. Hard 0/1: the slope is 0 almost everywhere, so no gradient reaches the gate's weights and they never learn when to open. Sigmoid is the one that is a smooth fraction.

11Hypothetical: what if f = 1 and i = 1 at every step?

The cell adds every draft forever: \(c\) grows without limit, \(\tanh(c)\) sticks near ±1, and \(h\) stops responding. The tanh slope then starves the gradient on its way into the cell. That's why the original LSTM needed the forget gate on long streams.

12Parameter count for an LSTM and a GRU?

One block is \(H(H + d) + H\). An LSTM has 4 blocks and a GRU 3, so the GRU has 25% fewer. PyTorch adds another \(H\) per block for its second bias vector. The count doesn't depend on sequence length, because the weights are shared across time.

13LSTM or GRU, and why did transformers replace both?

GRU for less data, shorter sequences or tight latency. LSTM for long dependencies, counting, or plenty of data; try both. Transformers train in parallel across positions, connect any two tokens in one step, and keep every past token instead of one fixed state, at \(n^2\) cost. RNNs still suit streaming with constant memory per event.

14Is the LSTM's \(h_t\) the prediction? How do you get an output?

No. \(h_t\) is the hidden state; a separate output layer reads it, \(\hat y_t = \text{softmax}(W_y h_t + b_y)\), and that layer isn't part of the cell. Many-to-many applies the same \(W_y\) at every step; many-to-one applies it once, to \(h_T\) or to a pooled summary of all the \(h_t\). In PyTorch you put an nn.Linear on top of nn.LSTM's outputs.

15Why does the GRU's reset gate act on \(h_{t-1}\) inside the draft, when the LSTM's input gate multiplies the draft's output?

Different jobs. \(z\) already decides how much to write, the LSTM's \(i\) job, so a reset gate on the output would be a second volume knob. On the input, \(r\) decides what the draft is built from: \(r \approx 0\) means start fresh from the input alone. That stands in for the LSTM's output gate, whose filtered \(h\) is what an LSTM draft reads. It acts before the matrix multiply so the past and the input stay separable.

16Compare how the gradient flows back through time in an RNN, an LSTM and a GRU.

On the memory path, one step back multiplies the gradient by \(\text{diag}(1 - h_t^2) W_h\) in an RNN: a fixed matrix and a slope, so the product vanishes or explodes. In an LSTM it's \(f_t\) along the cell, since \(\delta c_t\) gets \(\delta c_{t+1} \odot f_{t+1}\). In a GRU it's \(1 - z_t\) along the blend. Gate values near 1 give a near-identity highway. The gates' own gradients branch off and pass through weights, so clipping is still needed.
