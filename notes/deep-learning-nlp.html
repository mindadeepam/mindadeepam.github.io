Study notes · Deep learning

Deep learning – NLP

RNNs, LSTMs and GRUs, transformers, BERT and GPT, and fine-tuning: what every part does, why it is there, and what breaks without it.

Diagrams, worked maths and practice questions · cell state chidden state hgates

In short

  1. A plain RNN carries one vector, \(h\), and rewrites all of it every step through the same matrix and a tanh. Old information fades, and so does the gradient that could teach it to stay.
  2. A gate is a vector of dials between 0 and 1, recomputed every step from \([h_{t-1}, x_t]\) through its own weight matrix, and multiplied slot by slot into a signal.
  3. The LSTM keeps a notebook \(c\) that changes only by erasing (\(\times f\)) and writing (\(+\, i \odot g\)), and shows \(h = o \odot \tanh(c)\). The GRU merges notebook and output into one \(h\): the update gate \(z\) decides keep-versus-write, the reset gate \(r\) decides what the draft is built from.
  4. Neither cell predicts anything by itself: a separate output layer reads \(h_t\), \(\hat y_t = \text{softmax}(W_y h_t + b_y)\).
  5. Backprop: on the memory path, each step back multiplies the gradient by \(\text{diag}(1 - h_t^2) W_h\) in an RNN, by \(f_t\) in an LSTM and by \(1 - z_t\) in a GRU. Swapping a fixed matrix and slope for a learned dial is the whole fix.
  6. In ablations, the forget gate (started near 1) matters most and the output gate least; the learning rate matters more than any architectural tweak.
  7. Transformers drop recurrence: each token reads every other token directly, \(\text{softmax}(QK^\top/\sqrt{d_k})\,V\). Training runs in parallel and any two tokens are one step apart, at a cost that grows as \(n^2\).

01The plain RNN’s problem

\[ h_t = \tanh(W_x x_t + W_h h_{t-1} + b), \qquad \hat y_t = \text{softmax}(W_y h_t + b_y) \]

Shapes

Notation for the whole page: \(d\) = input size (e.g. the embedding size), \(H\) = hidden size, \(K\) = number of classes (or the vocabulary size \(V\)), \(T\) = sequence length, \(B\) = batch size.

ThingShapeNote
\(x_t\)\(d\)One step's input
\(h_{t-1},\ a_t,\ h_t\)\(H\)State, score, new state
\(W_x\)\(H \times d\)Input → state
\(W_h\)\(H \times H\)State → state (square: the state maps onto itself)

\(W_y,\ b_y\)\(K \times H,\ K\)The output head
\(z_t,\ \hat y_t\)\(K\)Logits, probabilities

Weight gradient share \(\delta a_t\, x_t^\top\)\((H \times 1)(1 \times d) = H \times d\)Same shape as \(W_x\) ✓

In code everything gets a leading batch dimension, and rows are examples, so a step is \(h_t = \tanh(x_t W_x^\top + h_{t-1} W_h^\top + b)\) with \(x_t\) of shape \(B \times d\) and \(h_t\) of shape \(B \times H\). PyTorch's nn.RNN(d, H, batch_first=True) takes \(B \times T \times d\) and returns all states as \(B \times T \times H\), plus the last one as \(\text{layers} \times B \times H\). Parameters: \(H(d + H) + H\) for the cell, plus \(KH + K\) for the head.

In code

# one sequence x: (T, d);  W_x: (H, d)  W_h: (H, H)  b: (H,)
h = zeros(H)                          # h_0
states = []
for t in range(T):
    a = W_x @ x[t] + W_h @ h + b      # score: (H,)
    h = tanh(a)                       # new state: (H,)
    states.append(h)
logits = W_y @ h + b_y                # many-to-one head: (K,)
# many-to-many: logits_t = W_y @ states[t] + b_y at every t

The same \(W_x\), \(W_h\), \(W_y\) are used at every step, so the model handles any length, and a pattern learned at one position is recognized at every other. The trouble is that \(h\) does two jobs at once: it is the memory, and it is the output. And every step, all of it goes through \(W_h\) and a tanh.

  • Forgetting. Something seen at step \(k\) reaches step \(T\) only after \(T - k\) passes through that matrix and squash, like a photocopy of a photocopy.
  • No way to leave a slot alone. Keeping a fact means \(W_h\) has to pass that slot through unchanged every step, and the tanh must not squash it. Nothing in the design makes that easy.
  • Vanishing gradients. The gradient from step \(T\) back to step \(k\) is a product of one factor per step in between:
\[ \frac{\partial h_T}{\partial h_k} = \prod_{t=k+1}^{T} \text{diag}\!\left(1 - h_t^2\right) W_h \]

If each factor shrinks things, the product shrinks exponentially with distance. If one stretches, it can explode. That's the same product as the forgetting, read backwards: the state forgets step \(k\), and the gradient can't teach it to remember. Clipping by norm tames explosions but can't fix vanishing. That needs a different update rule.

02What a gate is

\[ \text{gate}_t = \sigma\big(W [h_{t-1}, x_t] + b\big) \in (0, 1)^H \]
  • A vector of dials, one per memory slot. It's a sigmoid because it answers “how much?”: 0 blocks, 1 passes.
  • Used by element-wise multiplication, \(\text{gate} \odot \text{signal}\): slot \(j\) lets through the fraction \(\text{gate}_j\).
  • Recomputed every step from the current input and the previous output, so how much passes depends on the data. Compare the RNN, where how much of the past carries over is fixed by \(W_h\), the same matrix every step.

Trap

A gate is not a weight matrix. It's an activation, a vector computed fresh each step. Each gate has its own weight matrix that computes it.

03The LSTM

Long short-term memory (Hochreiter and Schmidhuber, 1997) gives the network a notebook, the cell state \(c\), kept separate from what it says, \(h\). Each step it decides what to erase, what to write, and what to read out.

One step, in order

In: \(x_t\) (what just happened), \(h_{t-1}\) (what I said last step) and \(c_{t-1}\) (my notebook). Stack the first two into \(u_t = [h_{t-1}, x_t]\), then ask it four questions, each with its own weights:

BlockFormulaQuestion it answers
forget\(f_t = \sigma(W_f u_t + b_f)\)Which old notes do I keep?
input\(i_t = \sigma(W_i u_t + b_i)\)How much of the draft should I write?
candidate\(g_t = \tanh(W_g u_t + b_g)\)What would I write?
output\(o_t = \sigma(W_o u_t + b_o)\)What should I show right now?
\[ c_t = f_t \odot c_{t-1} + i_t \odot g_t \qquad\qquad h_t = o_t \odot \tanh(c_t) \]

Out: \(c_t\) goes only to the next step. \(h_t\) goes to the prediction and to the next step, inside \(u_{t+1}\). Both start at zero. And \(c_{t-1}\) has no separate equation: it is this same update, one step earlier.

Shapes

ThingShapeNote
\(u_t = [h_{t-1}; x_t]\)\(H + d\)Stacked input
\(W_f, W_i, W_g, W_o\)\(H \times (H + d)\) eachIn code: one stacked \(4H \times (H + d)\) matrix, one multiply, split into quarters
\(b_f, b_i, b_g, b_o\)\(H\) each

One LSTM step, in code

def lstm_step(x, h, c):               # x: (d,)  h, c: (H,)
    u = concat([h, x])                # (H + d,)
    z = W @ u + b                     # one stacked matmul: W (4H, H+d) -> (4H,)
    i, f, g, o = split(z, 4)          # PyTorch order i, f, g, o; each (H,)
    i, f, o = sigmoid(i), sigmoid(f), sigmoid(o)   # dials in (0, 1)
    g = tanh(g)                       # the draft, in (-1, 1)
    c = f * c + i * g                 # erase part, write part
    h = o * tanh(c)                   # read part out
    return h, c

h, c = zeros(H), zeros(H)
for t in range(T):
    h, c = lstm_step(x[t], h, c)

What counts as a block

A block is anything computed from \([h_{t-1}, x_t]\) through its own weight matrix: \(\sigma\) or \(\tanh\) of \(W u_t + b\). The LSTM has four: \(f\), \(i\), \(g\) and \(o\). The inputs and states \(x\), \(h\) and \(c\) have no weights of their own; \(c_t\) and \(h_t\) are just multiplied and added together from the blocks. Each block holds \(H(H + d) + H\) numbers, which is where the parameter count comes from. (The GRU has three: \(z\), \(r\) and its draft \(\tilde h\).)

From \(h_t\) to a prediction

The cell only produces the hidden state. To predict anything, put an ordinary output layer, the “head”, on top. It is not part of the cell:

\[ \hat y_t = \text{softmax}(W_y h_t + b_y), \qquad W_y \text{ is } K \times H \]
  • Many-to-many (tag every word, flag every payment): apply the same \(W_y\) to every \(h_t\).
  • Many-to-one (one label per message): apply it once, usually to the last state \(h_T\), or to a summary of all of them (their mean, max, or an attention-weighted sum).
  • Use a sigmoid for a yes/no label and no activation for regression. In PyTorch, nn.LSTM returns every \(h_t\) plus the final \((h_T, c_T)\); you add nn.Linear(H, K) yourself.

Each block, briefly

Forget gate f · keep

Per slot: keep (1) or erase (0) the old note. Fraud example: keep “new payees lately” through normal payments, and wipe it once the customer verifies with the bank.

Stuck at 1: the notebook can never be cleared, so it fills and saturates. Stuck at 0: no memory at all.

Candidate g · draft

The new content: exactly a plain RNN update, \(\tanh(W_g u_t + b_g)\).

It's tanh, not sigmoid, because a write must push a slot up or down, as evidence for or against.

Input gate i · write?

Is the draft worth writing? It's separate from \(g\) because what an input says and whether to record it are different questions. A routine payment has content, but nothing worth noting.

With one set of weights doing both jobs, they pull against each other. The 1997 paper called this the input weight conflict.

Output gate o · show

Which notes to expose now. It lets a fact sit silently (a password reset three steps ago) until it matters (a large transfer arrives), so stored facts don't disturb every step.

The tanh before it keeps \(h\) bounded, because \(c\) is a sum of writes and can grow.

A common question

Why does \(h\) go to the next step if the notebook \(c\) already holds everything?

  • \(h\) is read from the notebook. It's \(o \odot \tanh(c)\), so the next step's gates do see the notebook, through this filtered readout.
  • Keeping two states means hiding isn't forgetting. The output gate can hide a slot from everything downstream (the prediction and the next gates) while \(c\) keeps it safe. With one vector doing both jobs, hiding a fact would erase it. That's exactly the GRU's trade-off.
  • \(c\) is unbounded (a sum of writes), so feeding it raw into sigmoid gates would saturate them. \(h\) is bounded.
  • Letting the gates read \(c\) directly was tried. These are “peephole” connections (Gers and Schmidhuber, 2000), and they gave no consistent gain.

Many slots, four moves

\(c\) is one vector of \(H\) slots (often 64 to 512), each with its own dials, so it holds many facts at once: one slot counting new payees, another overwritten every step. Real slots aren't that tidy, since facts get spread across several, but the picture holds. Because \(f\) and \(i\) are separate, each slot has four moves:

fiResultMove
10\(c_{t-1}\)keep: ignore this input
01\(g_t\)replace: erase, then write
11\(c_{t-1} + g_t\)accumulate: keep and add, so it can count
000wipe: clear without writing

Parameters: four blocks, each an \(H \times (H + d)\) matrix plus \(H\) biases, so \(4\,[H(H+d) + H]\). In code they're one \(4H \times (H+d)\) matrix multiply, split into quarters (PyTorch orders them i, f, g, o, and keeps two bias vectors per block).

04The GRU

The gated recurrent unit (Cho et al., 2014) is a simpler LSTM. It merges the notebook and the output into one state \(h\) and uses two gates instead of three.

\[ z_t = \sigma(W_z [h_{t-1}, x_t] + b_z) \qquad r_t = \sigma(W_r [h_{t-1}, x_t] + b_r) \]
\[ \tilde h_t = \tanh\big(W_n [\, r_t \odot h_{t-1},\; x_t \,] + b_n\big) \qquad h_t = (1 - z_t) \odot h_{t-1} + z_t \odot \tilde h_t \]
ThingShapeNote
\(W_z, W_r, W_n\)\(H \times (H + d)\) eachStacked in code as \(3H \times (H + d)\); PyTorch order r, z, n
\(z_t, r_t, \tilde h_t, h_t\)\(H\)Everything is one \(H\)-vector per step
Parameters\(3[H(H + d) + H]\)25% fewer than an LSTM of the same size

One GRU step, in code

def gru_step(x, h):                   # z = how much to write
    z = sigmoid(W_z @ concat([h, x]) + b_z)
    r = sigmoid(W_r @ concat([h, x]) + b_r)
    draft = tanh(W_n @ concat([r * h, x]) + b_n)   # r filters the past before the matmul
    return (1 - z) * h + z * draft                 # blend old and new
  • Update gate \(z\): how much to write. A slider: the new state sits a fraction \(z\) of the way from the old state to the draft, so it keeps \(1 - z\) and writes \(z\). It does the jobs of the LSTM's forget and input gates at once, tied together: \(f = 1 - z\), \(i = z\).
  • Reset gate \(r\): what the draft is built from. It multiplies the old state before it enters the draft's matrix. With \(r \approx 0\) the draft is built from the input alone, a fresh start (a new sentence, a new session); with \(r \approx 1\) it is a plain RNN update. It erases nothing by itself: erasing happens when \(z\) writes that draft over the old state.
  • No output gate. The state is always fully shown, to the output and to every gate at the next step. It can't hide a fact without forgetting it, which is the trade the LSTM avoids by keeping two states.
  • The cost of tying. Every write erases the same fraction, and the state is an average of old and new, so it stays within the draft's range and can't count. It wins some of this back because the draft reads the old state through \(r\): old memory can ride inside the new write.

A common question

In the LSTM the input gate multiplies the draft, \(i \odot g\). Why does the GRU's \(r\) act on \(h_{t-1}\) inside the draft instead?

  • Because it has a different job. “How much to write” is already done by \(z\). If \(r\) multiplied the draft's output, it would be a second volume knob for the same thing. Acting on the draft's input gives it a new job: choosing what the draft is computed from.
  • It stands in for the LSTM's output gate, for the draft only. An LSTM's draft reads \(h_{t-1} = o \odot \tanh(c_{t-1})\), a version of the memory already filtered by the output gate. A GRU's \(h\) is the raw memory, so without \(r\) every draft would be built from the entire past, relevant or not.
  • It sits before the matrix multiply so the past's contribution can be dropped slot by slot while the input's is kept; once \(W_n\) mixes them, they can't be pulled apart. (PyTorch applies \(r\) to \(W_{hn} h_{t-1}\), after the past's own multiply but still apart from the input's.)
  • Cho et al. (2014) found that units tracking short-range patterns lean on the reset gate and long-range ones on the update gate. A one-gate version, the minimal gated unit (Zhou et al., 2016), does about as well on several tasks, so the split helps but isn't essential.

Trap: conventions

Here \(z\) means “how much to write” (as in Chung et al., 2014). The original paper and PyTorch flip it: \(h_t = z \odot h_{t-1} + (1 - z) \odot \tilde h_t\), so their \(z\) means “keep”. PyTorch also applies \(r\) after the matrix multiply: \(\tanh(W_{in} x + b_{in} + r \odot (W_{hn} h + b_{hn}))\). Say which convention you're using.

05How the gradient flows: RNN → LSTM → GRU

Backprop through time asks, for every step: if this step's state had been slightly different, how much would the loss change? For an early step, the answer is carried backward one step at a time, and each step multiplies it by how strongly this step's memory depends on the previous step's. Everything that separates the three cells in training comes down to that per-step multiplier.

Two kinds of gradient come out of the walk back:

  • State gradients (\(\delta h\), \(\delta c\)) travel backward through time, one step at a time.
  • Weight gradients are collected along the way. Every weight is shared across steps, so its gradient is a sum of one share per step, each share being (gradient at the output of its multiply) × (what it multiplied)\(^\top\). An early step only adds a real share if its state gradient survived the walk.

Plain RNN: a weight matrix and a slope at every step

\[ \delta h_{t-1} = W_h^\top\big[\delta h_t \odot (1 - h_t^2)\big] \;+\; \text{(gradient from step } t{-}1\text{'s own output)} \]

Each step back goes through the tanh's slope, \(1 - h_t^2\), and then through \(W_h^\top\). Chained over many steps, that's \(\prod \text{diag}(1 - h_t^2) W_h\). If each factor shrinks the gradient, it vanishes exponentially. If \(W_h\) stretches it, it can explode. It's the same fixed matrix at every step, with no way to say “pass this through untouched”.

LSTM: a second path with no weights on it

\[ \delta c_t = \underbrace{\delta h_t \odot o_t \odot \big(1 - \tanh^2 c_t\big)}_{\text{from this step's output}} \;+\; \underbrace{\delta c_{t+1} \odot f_{t+1}}_{\text{from the future, along the cell}} \]
  • The second term is the highway. Going back one step along the cell multiplies the gradient by \(f\), and only \(f\): no weight matrix and no tanh slope. With \(f \approx 1\), it arrives almost whole. With \(f = 1\), the update is \(c_t = c_{t-1} + i_t \odot g_t\), a residual connection through time (the 1997 paper's “constant error carousel”).
  • The gates learn from side branches. From \(\delta c_t\): \(\delta f_t = \delta c_t \odot c_{t-1}\), \(\delta i_t = \delta c_t \odot g_t\), \(\delta g_t = \delta c_t \odot i_t\). From \(\delta h_t\): \(\delta o_t = \delta h_t \odot \tanh(c_t)\). Each is multiplied by its activation's slope, then feeds its weight's gradient and, through those weights, \(\delta h_{t-1}\). These side paths do go through matrices, so they can still explode, which is why LSTMs are still clipped.
  • Memory and gradient fade together. Unrolled, the cell is a sum of every past write, faded by the forget gates since: \(c_t = \sum_k \big(\prod_{j>k} f_j\big) \odot i_k \odot g_k\). The gradient back to each write is that same product, so the cell keeps a fact exactly as long as it can learn from it. Start the forget bias at 1, so \(f \approx 0.73\). At 0, \(f \approx 0.5\) halves memory and gradient every step, like a plain RNN.

GRU: the blend is the highway

\[ \delta h_{t-1} = \delta h_t \odot (1 - z_t) \;+\; \text{(paths through } z_t,\ r_t \text{ and } \tilde h_t\text{)} \]

The direct term comes from the \((1 - z) \odot h_{t-1}\) half of the blend, so it's multiplied only by \(1 - z\), a gate value, just like the LSTM's \(f\). While the GRU keeps (\(z \approx 0\)), the gradient passes back almost whole. When it writes (\(z \approx 1\)), the direct path is cut, and what comes back has to go through the draft (\(r \odot h_{t-1}\) inside \(\tilde h\)). That path runs through \(W_n\) and a tanh slope, like a plain RNN.

BPTT, in code (plain RNN, loss at the last step)

# stored from the forward pass: x[1..T], h[0..T] with h[0] = 0
dh = W_y.T @ (y_hat - y)              # gradient arriving at h_T
dW_x, dW_h, db = 0, 0, 0
for t in range(T, 0, -1):             # t = T ... 1
    da = dh * (1 - h[t] ** 2)         # back through tanh
    dW_x += outer(da, x[t])           # every step adds a share
    dW_h += outer(da, h[t - 1])
    db   += da
    dh = W_h.T @ da                   # one step back in time: x W_h^T
clip_by_norm([dW_x, dW_h, db], max_norm=5.0)
# LSTM: the cell carries dc back with only  dc = dc_next * f_next  (+ the term from h)

That's the whole fix in one line: replace a fixed matrix times a slope with a learned dial. Attention goes one step further and removes the walk altogether, because every token connects to every other in one step (Part 09).

Trap

“The forget gate is a sigmoid, whose slope is at most 0.25. Doesn't the gradient vanish through it?” No. Along the cell, the gradient is multiplied by the gate's value \(f\), not its slope. The slope only appears on the side branch that trains the gate's own weights.

06What the research found

Most of this comes from two big ablation studies: Greff et al. (2015, “LSTM: A Search Space Odyssey”, 8 variants on speech, handwriting and music) and Jozefowicz et al. (2015, over 10,000 architectures searched).

The takeaways

  • The forget gate, started near 1, is the heart of it. The output gate matters least, which is why the GRU can drop it.
  • Greff also found the learning rate mattered more than any architectural variant, and the hyperparameters barely interact. Tune the learning rate first.
  • A neat theory result (Tallec and Ollivier, 2018): gates fall out of asking a recurrent model to be robust to time being stretched or squeezed. That suggests setting the forget bias from the dependency lengths you expect (“chrono” initialization).

In practice, try both gated cells: the gap between them is usually smaller than the effect of features and tuning. Against transformers, RNNs lose because they run step by step (no parallel training across time), squeeze the past into a fixed-size state, and need \(n\) steps to connect token 1 to token \(n\). Attention keeps every past state and connects any two in one step, at a cost that grows as \(n^2\). RNNs still win for streaming with constant work per event: per-transaction scoring, or on-device.

08Bidirectional, stacked and in practice

Bidirectional LSTMs

Run two LSTMs over the sequence: one left to right, one right to left. At each position, join their states, so every position sees its whole context:

\[ \overrightarrow{h}_t = \text{LSTM}(x_t, \overrightarrow{h}_{t-1}) \qquad \overleftarrow{h}_t = \text{LSTM}(x_t, \overleftarrow{h}_{t+1}) \qquad h_t = [\overrightarrow{h}_t ;\, \overleftarrow{h}_t] \]
  • Built for tagging and for labelling finished sequences. Examples: named-entity tags, part-of-speech tags, or one codon per amino acid. A stacked bi-LSTM is a common baseline for exactly that. Each output sees both sides of its position.
  • Costs: twice the parameters and compute, and the output size doubles to \(2H\).
  • Not for generation or live scoring. The backward half has already read the future. For a per-step prediction made in real time, that's leakage: offline metrics look great, and production can't supply the future.
  • Many-to-one with a bi-LSTM: join the forward pass's last state with the backward pass's first state (each has read the whole sequence), or pool over all positions.
  • Its successors: ELMo (2018) used stacked bi-LSTM language models as contextual word embeddings. BERT then replaced the LSTMs with a bidirectional transformer.

Stacking

  • Layer 2 reads layer 1's sequence of \(h\)'s as its inputs. Two to four layers is typical; more rarely helps.
  • Put dropout between layers, not on the step-to-step connection. Fresh noise on \(h_{t-1} \to h_t\) at every step corrupts the memory. If you want it there, use the same mask at every step (“variational” dropout).
  • Residual connections between layers help deep stacks; Google's 2016 translation system used 8 LSTM layers with residuals.

09From LSTMs to transformers

The field moved from LSTMs to transformers in three steps, each fixing the last one's bottleneck.

1. Seq2seq: encode, then decode (Sutskever, Vinyals and Le, 2014)

An LSTM encoder reads the source sentence. Its last state is handed to an LSTM decoder, which writes the output one token at a time, each output becoming the next input:

\[ h_j = \text{LSTM}_{\text{enc}}(x_j, h_{j-1}) \qquad c = h_T \]
\[ s_t = \text{LSTM}_{\text{dec}}(y_{t-1}, s_{t-1}),\ \ s_0 = c \qquad p(y_t \mid y_{<t}, x) = \text{softmax}(W s_t) \qquad L = -\sum_t \log p(y_t \mid y_{<t}, x) \]

2. Attention: let the decoder look back (Bahdanau, Cho and Bengio, 2014)

Keep every encoder state. At each decoder step, score each one against the decoder's current state, softmax the scores into weights, and read their weighted sum, the context:

\[ e_{tj} = v^\top \tanh(W s_{t-1} + U h_j) \quad \text{(additive; Luong's dot-product version: } e_{tj} = s_{t-1}^\top h_j\text{)} \]
\[ \alpha_{tj} = \frac{\exp(e_{tj})}{\sum_k \exp(e_{tk})} \qquad c_t = \sum_j \alpha_{tj} h_j \qquad s_t = \text{LSTM}_{\text{dec}}([y_{t-1};\, c_t],\ s_{t-1}) \]

10The transformer, part by part

Each token starts as an embedding (a learned vector per token) plus a position signal. A stack of identical blocks then updates every token's vector, and each block does two things: attention moves information between tokens, and a small MLP processes it within each token.

Self-attention: a soft lookup

\[ Q = XW_Q,\quad K = XW_K,\quad V = XW_V \qquad\qquad \text{Attention}(Q, K, V) = \text{softmax}\!\Big(\frac{QK^\top}{\sqrt{d_k}}\Big) V \]
  • Every token makes three vectors: a query (what am I looking for?), a key (what do I contain, as an advertisement?) and a value (what do I hand over if picked?).
  • Score = query · key. Row \(i\) of \(QK^\top\) says how relevant each token \(j\) is to token \(i\). The softmax turns each row into weights that are positive and add up to 1.
  • Output = weighted average of values. Token \(i\)'s new vector is a mix of every token's value, weighted by relevance. All tokens do this at once, as two matrix multiplies, which is why it trains in parallel.
  • Why three separate projections? What a token looks for and what it advertises differ (a verb looks for its subject; the subject doesn't look for the verb the same way), so the scores can be asymmetric. And what gets copied (the value) needn't be what was matched on (the key).

Why divide by \(\sqrt{d_k}\)

A dot product of two random \(d_k\)-dimensional vectors with unit-variance entries has variance \(d_k\). With \(d_k = 64\) the scores spread over tens, the softmax goes nearly one-hot, and its gradient goes to almost zero: the same saturation problem as a tanh stuck at ±1. Dividing by \(\sqrt{d_k}\) brings the variance back to about 1.

Multi-head attention

\[ \text{head}_i = \text{Attention}\big(XW_Q^{(i)},\, XW_K^{(i)},\, XW_V^{(i)}\big) \qquad \text{MultiHead}(X) = [\text{head}_1; \dots; \text{head}_h]\, W_O \]

Instead of one attention over the full width \(d\), run \(h\) heads in parallel, each with its own \(W_Q, W_K, W_V\) of width \(d/h\), then concatenate their outputs and mix them with \(W_O\). One softmax can only focus on one pattern per token; several heads can track several (a syntactic link, a coreference, a neighbouring word) at once. It costs about the same as one full-width head.

Where word order comes from

Attention treats its input as a set: shuffle the tokens and the outputs shuffle the same way. So position has to be added.

  • Sinusoidal (the original paper): fixed sine and cosine vectors of different frequencies added to the embeddings. They work for any length and change smoothly with position.
  • Learned (BERT, GPT-2): one trained vector per position. Simple, but capped at the longest length seen in training.
  • RoPE (most modern LLMs, e.g. Llama): rotate each query and key by an angle proportional to its position, so \(q_i \cdot k_j\) depends only on the offset \(i - j\). Relative position is built into the score itself.
\[ PE_{(pos,\,2i)} = \sin\!\big(pos / 10000^{2i/d}\big) \qquad PE_{(pos,\,2i+1)} = \cos\!\big(pos / 10000^{2i/d}\big) \]

Each dimension pair is a sine wave of a different wavelength, so every position gets a unique pattern, and a fixed offset is a fixed rotation of it. That makes relative positions easy to read off.

The block

\[ x \leftarrow x + \text{MultiHead}(\text{LN}(x)) \qquad x \leftarrow x + \text{FFN}(\text{LN}(x)) \]
\[ \text{FFN}(x) = W_2\,\text{GELU}(W_1 x) \]
  • The FFN is a two-layer MLP applied to each token separately, usually 4× wider than \(d\). Attention gathers; the FFN thinks. Most of a transformer's parameters, and much of its stored knowledge, live here.
  • Residual connections make each sublayer add to the stream instead of replacing it, so the gradient has a straight path through every layer. It's the same trick as the LSTM's \(c_t = c_{t-1} + \dots\), applied across depth instead of time.
  • LayerNorm, not BatchNorm. LayerNorm normalizes each token's vector on its own, so it doesn't care about batch size, sequence length or padding, and it behaves the same in training and at inference. BatchNorm would average across a batch of padded, variable-length sequences, and breaks with a batch of one.
  • Pre-LN vs post-LN. The original transformer put LayerNorm after each residual add (post-LN) and needed a learning-rate warmup to train. Putting it inside the branch (pre-LN, above) keeps the residual path clean and trains more stably, so most modern models use pre-LN.

The transformer in pseudocode

def attention(Q, K, V, mask=None):          # Q: (n, d_k)  K: (m, d_k)  V: (m, d_v)
    scores = Q @ K.T / sqrt(d_k)            # (n, m): how relevant each key is to each query
    if mask is not None:
        scores = where(mask, scores, -inf)  # blocked pairs get weight 0
    A = softmax(scores, axis=-1)            # each row sums to 1
    return A @ V                            # (n, d_v): weighted mix of values

def multi_head(X, mask=None):               # X: (n, d)
    Q, K, V = X @ W_Q, X @ W_K, X @ W_V     # each (n, d)
    Q, K, V = split_heads(Q, K, V, h)       # each (h, n, d/h)
    heads = [attention(Q[i], K[i], V[i], mask) for i in range(h)]
    return concat(heads, axis=-1) @ W_O     # (n, d)

def block(X, mask=None):                    # one pre-LN transformer block
    X = X + multi_head(layer_norm(X), mask)          # mix information BETWEEN tokens
    X = X + gelu(layer_norm(X) @ W_1) @ W_2          # MLP WITHIN each token: d -> 4d -> d
    return X                                # same shape in and out: (n, d)

def gpt(tokens):                            # decoder-only, e.g. GPT
    n = len(tokens)
    X = E[tokens] + P[:n]                   # token + position embeddings: (n, d)
    causal = tril(ones(n, n))               # token i may see tokens j <= i
    for _ in range(L):
        X = block(X, mask=causal)
    return layer_norm(X) @ E.T              # logits (n, V); output weights tied to E

def generate(prompt, steps, temperature=1.0):
    tokens = list(prompt)
    for _ in range(steps):
        logits = gpt(tokens)[-1]            # only the last position predicts the next token
        tokens.append(sample(softmax(logits / temperature)))
    return tokens
# KV cache: store each layer's K and V for past tokens; a new token computes only its own
# q, k, v and attends to the cache, so each step costs O(n * d) instead of re-running everything.

Masks

Before the softmax, blocked scores are set to \(-\infty\), so they get weight 0. A padding mask blocks pad tokens. A causal mask blocks the future: token \(i\) may only attend to tokens \(j \le i\). That's what lets a decoder train on every position of a sequence at once without peeking at the answer.

What it costs

  • Attention builds an \(n \times n\) score matrix per head: about \(n^2 d\) time and \(n^2\) memory per layer. The FFN costs about \(n d^2\). Short sequences are dominated by the FFN, long ones by attention.
  • Training processes all positions at once. Generation is still one token at a time; the KV cache stores every past token's keys and values, so each new token costs about \(n d\) instead of recomputing everything.
  • Parameters per block: \(4d^2\) for \(W_Q, W_K, W_V, W_O\), plus \(8d^2\) for the FFN with a 4× hidden width, so about \(12 d^2\).

12Pretrained language models: BERT, GPT and fine-tuning

The modern recipe: pretrain a transformer on a huge unlabelled corpus with a self-supervised objective, then adapt it to a small labelled task. The two classic objectives produce the two classic shapes.

\[ L_{\text{BERT}} = -\sum_{i \in \mathcal{M}} \log p\big(x_i \mid x_{\setminus \mathcal{M}}\big) \qquad L_{\text{GPT}} = -\sum_t \log p(x_t \mid x_{<t}), \quad p(x) = \prod_t p(x_t \mid x_{<t}) \]

Here \(\mathcal{M}\) is the set of masked positions and \(x_{\setminus \mathcal{M}}\) is everything else. BERT learns from about 15% of the tokens per sentence, while GPT learns from every one.

BERT: fill in the blanks (encoder-only)

  • Masked language modelling. Pick 15% of the tokens. Of those, replace 80% with [MASK], 10% with a random token, and leave 10% unchanged. Predict the original token at those positions only, with cross-entropy over the vocabulary.
  • Why 80/10/10? It fixes two problems you'd get if every chosen position showed [MASK]:
    • A train/test mismatch. The loss would only ever ask about [MASK] positions, so the model would have no reason to build careful vectors for the ordinary words it sees. But BERT is mostly used as an encoder for classification, tagging, QA and embeddings, and there the input never contains [MASK]: every token is a real word. (You can put [MASK] in at inference for fill-in-the-blank; that is the one exception.)
    • The random 10% (“the cat sat on the banana”, predict “mat”) means no visible word can be blindly trusted, since any might be a planted fake. The model has to check every token against its context.
    • The unchanged 10% (the true word shown, still predicted) stops the opposite habit of ignoring what it sees: the visible word is usually right, so use it, but verify it. These positions also look exactly like real inputs.
    • Because the random and unchanged cases look like ordinary words, the model can't tell which tokens are being tested, so it keeps a good contextual vector for all of them. Overall that's 12% of tokens masked, 1.5% randomized and 1.5% left as-is. The exact split was chosen by ablation in the BERT paper.
  • Input format: [CLS] tokens [SEP], with token, position and segment embeddings added together. The final [CLS] vector feeds classification heads, and each token's final vector feeds tagging heads.
  • Next-sentence prediction was a second objective in the original BERT. RoBERTa dropped it, trained longer and re-drew the mask every epoch (“dynamic masking”), and did better.
  • Why bidirectional suits understanding: each token sees both sides, which is what tagging and classification need. It can't generate text left to right naturally.
  • Domain BERTs: the same recipe on other “languages”. ProtBert is BERT trained with masked LM on protein sequences, with amino acids as tokens.

Training and using BERT, end to end

1. Pretraining (self-supervised). Corrupt the input \(x\) into \(\tilde x\) by choosing 15% of positions \(\mathcal M\) and applying 80/10/10. Run the encoder, and at each chosen position predict the original token:

\[ L_{\text{MLM}} = -\frac{1}{|\mathcal M|}\sum_{i \in \mathcal M} \log p_\theta(x_i \mid \tilde x), \qquad p_\theta(\cdot \mid \tilde x) = \text{softmax}\big(E\, g(h_i) + b\big) \]

Here \(h_i\) is the encoder's final vector at position \(i\), \(g\) is a small dense + GELU + LayerNorm head, and \(E\) is the token-embedding matrix reused as the output layer (one logit per vocabulary word). The original BERT added next-sentence prediction, a binary cross-entropy on the [CLS] vector, so \(L = L_{\text{MLM}} + L_{\text{NSP}}\); RoBERTa later dropped it.

for batch in corpus_batches:                      # token ids (B, n), e.g. n = 512

    loss.backward(); clip_grad_norm(1.0); adamw.step(); warmup_then_linear_decay.step(); zero_grad()

GPT: predict the next token (decoder-only)

  • A causal mask, and a loss at every position: predict token \(t+1\) from tokens \(1 \dots t\). Every position is a training example, so it's very data-efficient.
  • It generates naturally, one token at a time. Scaled up, it gives modern LLMs, which can do new tasks from a few examples in the prompt (in-context learning). TabFM applies the same idea to tables.

Tokenization

  • Words: any word outside the vocabulary becomes an unknown token. Characters: nothing is unknown, but sequences get long. Subwords sit in between: frequent words stay whole, and rare words split into pieces.
  • BPE (GPT) starts from characters (or bytes) and repeatedly merges the most frequent adjacent pair. WordPiece (BERT) is similar but picks the merge that most increases the likelihood of the corpus. SentencePiece runs on raw text and can learn a BPE or unigram vocabulary.
  • Domain tokens: in biology, amino acids or codons (3-nucleotide units) are natural tokens.

A common question

Why can a frozen backbone with a linear head beat a model trained from scratch, or a much bigger fine-tuned one?

The pretrained embeddings already encode the structure, learned from far more data than the labelled set. With little labelled data, training millions of parameters overfits, while a linear head has few parameters, so low variance. A model trained from scratch has to learn the representation and the task from the same small dataset.

LoRA

\[ W' = W + \frac{\alpha}{r} B A, \qquad B \in \mathbb{R}^{d \times r},\ A \in \mathbb{R}^{r \times k},\ r \ll \min(d, k) \]
  • Freeze \(W\) and train only the low-rank pair \(B A\), often under 1% of the parameters. \(B\) starts at 0, so training starts from the unchanged model.
  • It works because the weight change needed for a new task tends to have low intrinsic rank. After training, merge \(BA\) into \(W\): no extra inference cost.
  • QLoRA keeps the frozen base in 4-bit precision and trains LoRA on top, which fits big models on one GPU.

LoRA, in code

class LoRALinear:
    def __init__(self, W, r=8, alpha=16):      # W: (d_out, d_in), frozen
        self.W = W
        self.A = randn(r, d_in) * 0.01         # trainable
        self.B = zeros(d_out, r)               # trainable, starts at 0: the model starts unchanged
        self.scale = alpha / r
    def forward(self, x):
        return self.W @ x + self.scale * (self.B @ (self.A @ x))
# after training: W_merged = W + scale * B @ A   (no extra cost at inference)

Catastrophic forgetting

Fine-tuning can overwrite what the model learned in pretraining. To reduce it:

  • use a small learning rate and fewer epochs;
  • freeze the lower layers, or use layer-wise learning-rate decay (lower layers learn slower);
  • use LoRA or adapters;
  • mix some old data back in (replay);
  • or penalize changes to the weights that mattered most (EWC; see 15).

Masking logits

Set the logits of invalid classes to \(-\infty\) before the softmax:

  • those classes get probability 0;
  • the softmax renormalizes over the valid set;
  • no gradient flows to the masked logits.

It's the same mechanism as a transformer's causal and padding masks. Codon-optimization models use it so every predicted codon matches its amino acid. Apply the mask at both training and inference. Otherwise the model trains on a different distribution from the one it's used on.

15Odds and ends

Optimizing a metric you can't differentiate

  • Smooth surrogate: replace hard choices (argmax, max) with a softmax, with a temperature, and optimize that. A softened codon adaptation index (CAI), added as an extra loss term, is one example.
  • Gumbel-softmax: a differentiable approximation of sampling a one-hot choice.
  • Straight-through: use the hard choice in the forward pass, and pretend it was the identity in the backward pass.
  • REINFORCE / policy gradient: treat the metric as a reward. It's unbiased but high-variance; subtract a baseline. Summarizers trained with reinforcement learning use it to optimize ROUGE directly.
  • Why it may not help: cross-entropy may already push toward what the metric rewards, and a surrogate can disagree with the real metric.

Neural ODEs

A residual layer, \(h_{l+1} = h_l + f(h_l)\), is one Euler step of \(dh/dt = f(h, t)\). A neural ODE replaces the stack of layers with an ODE solver: continuous depth, and memory that stays constant with depth when trained with the adjoint method. Flows built this way are invertible, which is why they're used for image registration. The costs are slow, adaptive solvers and trouble with stiff dynamics.

Continual learning

Learning tasks in sequence without forgetting the old ones. There are three families of fixes:

  • Regularization: EWC penalizes changes to the weights that mattered for old tasks, with importance measured by the Fisher information.
  • Replay: keep, or generate, old examples and mix them in.
  • Architecture: add new heads or adapters per task.

In production, the same problem shows up as concept drift: monitor, retrain on a schedule, and keep old patterns in the training mix.

Implicit neural representations

An MLP that maps coordinates \((x, y)\) to a pixel value. Because it's continuous, you can sample it at any resolution, which is how arbitrary-scale super-resolution works. Plain MLPs struggle with fine detail (“spectral bias”), so INRs use Fourier features or sine activations (SIREN).

16Interview questions

Answer out loud first, then open the answer.

Recurrent networks

1Why do plain RNNs struggle with long sequences?

One vector is both the memory and the output, and every step all of it goes through \(W_h\) and a tanh. Old information fades, and the gradient back to old steps is a product of one Jacobian, \(\text{diag}(1 - h^2) W_h\), per step. Below 1 per step it vanishes exponentially, above 1 it can explode. Forgetting and vanishing are the same product read in two directions. Clipping fixes explosions only.

2Walk me through an LSTM step. What does each gate do?

Stack \(h_{t-1}\) and \(x_t\). The forget gate chooses what to keep from \(c_{t-1}\). The candidate \(g\) is the draft of new content. The input gate chooses how much of the draft to write: \(c_t = f \odot c_{t-1} + i \odot g\). The output gate chooses what to show: \(h_t = o \odot \tanh(c_t)\). The gates are sigmoids because they're per-slot fractions. The candidate is tanh because a write must go up or down.

3Cell state vs hidden state: why keep both?

\(c\) is long-term storage: unbounded, only scaled and added to, never read directly from outside. \(h = o \odot \tanh(c)\) is the bounded readout used by the output and the next step's gates. Two states mean the cell can hide a fact without forgetting it. The GRU, with one state, can't.

4How does the LSTM fix vanishing gradients? Can it still vanish or explode?

Along the cell, \(\partial c_t/\partial c_{t-1} = \text{diag}(f_t)\): no weight matrix, no tanh slope. With \(f\) near 1 the gradient survives many steps (the constant error carousel, a residual connection through time). It can still vanish over very long gaps, since it's a product of \(f\)'s. The paths through \(h\) go through weights and can explode, so clip.

5Why initialize the forget-gate bias to 1? Why not 10?

At initialization gates sit near σ(bias). A bias of 0 gives \(f \approx 0.5\), halving memory and gradient every step. A bias of 1 gives \(f \approx 0.73\), so the cell starts out remembering. At 10, the sigmoid is flat, so the gate can barely learn to forget. Jozefowicz et al. found this one change closes the LSTM–GRU gap. Keras does it by default; PyTorch doesn't.

6Why separate forget and input gates instead of i = 1 − f?

Separate gates allow four moves: keep, replace, accumulate (keep and write) and wipe (erase without writing). Tied gates make the update a weighted average, so every write erases the same fraction, the state can't exceed the draft so it can't count, and every write cuts the gradient by \(1 - i\). The other side: coupled gates (CIFG, and the GRU) do about as well on most benchmarks.

7Write the GRU and compare it with the LSTM.

\(z = \sigma(W_z[h,x])\), \(r = \sigma(W_r[h,x])\), \(\tilde h = \tanh(W_n[r \odot h, x])\), \(h_t = (1-z) h_{t-1} + z \tilde h\). One state instead of two. The update gate is the LSTM's forget and input tied (\(f = 1 - z\), \(i = z\)). There's no output gate, and \(r\) controls how much past the draft sees. Three blocks instead of four. Mention that PyTorch's \(z\) means “keep”.

8What does the reset gate do that the update gate doesn't?

The update gate decides how much of the state to replace. The reset gate decides what the replacement is built from: with \(r \approx 0\) the draft ignores the past, a fresh start. Without \(r\), every draft would mix in the whole past, so the GRU couldn't cleanly start over at a sentence or session boundary.

9Which LSTM gate matters most? What happens if you remove each one?

Forget gate: removing it causes the biggest drop on every task, because the cell can't reset. Output tanh: removing it also hurts badly, since \(h\) becomes unbounded. Input gate, output gate, candidate tanh: removing them hurts on some tasks. Peepholes and coupling make no significant difference (Greff 2015). Jozefowicz ranks them forget, then input, then output.

10Hypothetical: swap the sigmoid gates for ReLU, tanh, or hard 0/1 switches?

ReLU: a gate above 1 amplifies the memory every step, so it explodes. Tanh: a negative gate flips the memory's sign, so it's no longer “how much to keep”. Hard 0/1: the slope is 0 almost everywhere, so no gradient reaches the gate's weights and they never learn when to open. Sigmoid is the one that is a smooth fraction.

11Hypothetical: what if f = 1 and i = 1 at every step?

The cell adds every draft forever: \(c\) grows without limit, \(\tanh(c)\) sticks near ±1, and \(h\) stops responding. The tanh slope then starves the gradient on its way into the cell. That's why the original LSTM needed the forget gate on long streams.

12Parameter count for an LSTM and a GRU?

One block is \(H(H + d) + H\). An LSTM has 4 blocks and a GRU 3, so the GRU has 25% fewer. PyTorch adds another \(H\) per block for its second bias vector. The count doesn't depend on sequence length, because the weights are shared across time.

13LSTM or GRU, and why did transformers replace both?

GRU for less data, shorter sequences or tight latency. LSTM for long dependencies, counting, or plenty of data; try both. Transformers train in parallel across positions, connect any two tokens in one step, and keep every past token instead of one fixed state, at \(n^2\) cost. RNNs still suit streaming with constant memory per event.

14Is the LSTM's \(h_t\) the prediction? How do you get an output?

No. \(h_t\) is the hidden state; a separate output layer reads it, \(\hat y_t = \text{softmax}(W_y h_t + b_y)\), and that layer isn't part of the cell. Many-to-many applies the same \(W_y\) at every step; many-to-one applies it once, to \(h_T\) or to a pooled summary of all the \(h_t\). In PyTorch you put an nn.Linear on top of nn.LSTM's outputs.

15Why does the GRU's reset gate act on \(h_{t-1}\) inside the draft, when the LSTM's input gate multiplies the draft's output?

Different jobs. \(z\) already decides how much to write, the LSTM's \(i\) job, so a reset gate on the output would be a second volume knob. On the input, \(r\) decides what the draft is built from: \(r \approx 0\) means start fresh from the input alone. That stands in for the LSTM's output gate, whose filtered \(h\) is what an LSTM draft reads. It acts before the matrix multiply so the past and the input stay separable.

16Compare how the gradient flows back through time in an RNN, an LSTM and a GRU.

On the memory path, one step back multiplies the gradient by \(\text{diag}(1 - h_t^2) W_h\) in an RNN: a fixed matrix and a slope, so the product vanishes or explodes. In an LSTM it's \(f_t\) along the cell, since \(\delta c_t\) gets \(\delta c_{t+1} \odot f_{t+1}\). In a GRU it's \(1 - z_t\) along the blend. Gate values near 1 give a near-identity highway. The gates' own gradients branch off and pass through weights, so clipping is still needed.

Transformers

T1Why did transformers replace LSTMs?

Three reasons. They train in parallel across positions instead of step by step. Any two tokens are one attention step apart, so there's no long chain for gradients to vanish along. And they keep every past token instead of squeezing the past into one fixed state. The price is \(n^2\) cost in sequence length, and generation is still sequential (helped by the KV cache).

T2Walk me through self-attention. Why separate Q, K and V?

Project each token into a query, a key and a value. Scores are \(QK^\top/\sqrt{d_k}\), a softmax per row turns them into weights, and each output is the weighted sum of values. Separate projections let “what I look for” differ from “what I advertise” (so relevance can be asymmetric), and let what gets copied differ from what was matched on.

T3Why divide by \(\sqrt{d_k}\)?

A dot product of two random \(d_k\)-dimensional vectors has variance about \(d_k\). Large scores push the softmax to near one-hot, where its gradient is almost zero. Dividing by \(\sqrt{d_k}\) keeps the scores' variance near 1, so the softmax stays in its sensitive range.

T4Why multi-head attention?

One softmax gives each token a single attention pattern. With \(h\) heads of width \(d/h\), each head can track a different relation (syntax, coreference, nearby words), and \(W_O\) mixes the results. The cost is about the same as one full-width head.

T5How does a transformer know word order? What is RoPE?

Attention is permutation-equivariant, so position must be injected: sinusoidal encodings (fixed, any length), learned position vectors (capped at the trained length), or RoPE. RoPE rotates each query and key by an angle proportional to its position, so \(q_i \cdot k_j\) depends only on the relative offset \(i - j\). Most modern LLMs use it.

T6What do the FFN, the residual connections and LayerNorm each do? Why not BatchNorm?

The FFN is a per-token MLP: attention moves information between tokens, and the FFN processes it within each one (most parameters live here). Residuals give gradients a straight path through depth, like the LSTM's cell through time. LayerNorm normalizes each token on its own, so it's independent of batch size, length and padding. BatchNorm would mix statistics across padded sequences and fail with a batch of one. Pre-LN trains more stably than post-LN, which needed warmup.

T7Encoder-only vs decoder-only vs encoder–decoder: what are cross-attention and the causal mask for?

Encoder-only (BERT) is bidirectional and trained to fill in masked tokens, which suits classification and embeddings. Decoder-only (GPT) uses a causal mask and is trained to predict the next token, which suits generation. Encoder–decoder (T5, the original) maps one sequence to another; its decoder's cross-attention takes queries from the decoder and keys and values from the encoder. The causal mask sets future scores to \(-\infty\), so training on all positions at once can't peek at the answer.

T8What does attention cost, and what is the KV cache?

About \(n^2 d\) time and \(n^2\) memory per layer for the score matrix, versus \(n d^2\) for the FFN. At generation, each new token would otherwise recompute keys and values for the whole prefix; the KV cache stores them, so a new token costs about \(n d\). The cache's memory grows with length, which is what limits long contexts.

T9How many parameters does one transformer block have?

About \(4d^2\) for \(W_Q, W_K, W_V, W_O\), plus \(8d^2\) for an FFN with hidden width \(4d\) (two \(d \times 4d\) matrices), so about \(12 d^2\), plus small LayerNorm and bias terms. Embeddings add vocabulary size × \(d\).

Pretrained models and training

P1Explain BERT's pretraining. Why the 80/10/10 rule?

Masked language modelling: pick 15% of tokens and predict the originals from both sides' context, with cross-entropy at those positions only. Of the chosen tokens, 80% become [MASK], 10% a random token, and 10% stay as they are. Since [MASK] never appears at fine-tuning time, the random and unchanged cases force a useful representation for every token. The original BERT also used next-sentence prediction, which RoBERTa showed wasn't needed.

P2Frozen backbone with a linear probe, full fine-tune, or LoRA: when each? Why can a probe beat a big trained model?

Use a probe when labelled data is small and the pretrained embeddings already capture the structure: few parameters, low variance, cheap. Fine-tune (with a small learning rate, maybe only the top layers) when there's more data or a domain shift. Use LoRA when memory is tight or many tasks share one base. A probe can win because the representation was learned from far more data than the labelled set; a big model trained on the small set overfits. That's ppLM-CO's result: 62K trainable parameters against 7.1M.

P3What is LoRA, and why does it work?

Freeze \(W\) and learn a low-rank update, \(W' = W + (\alpha/r) BA\), with \(r\) small (say 8) and \(B\) starting at zero. You train under 1% of the parameters, and \(BA\) merges into \(W\) afterwards, so inference costs nothing extra. It works because the change a new task needs tends to have low intrinsic rank. QLoRA does the same on a 4-bit frozen base.

P4What does a \(-\infty\) logit mask do to the probabilities and the gradients?

Masked classes get \(e^{-\infty} = 0\) probability, so the softmax renormalizes over the valid set, and no gradient flows to the masked logits. It's the same mechanism as the causal and padding masks. Apply it in both training and inference; otherwise the model trains on a different distribution from the one it's used on.

P5Bi-LSTM or transformer for a per-token tagging task?

Both see both sides. A bi-LSTM carries context through gated states (\(n\) steps from end to end, cheap per token, fine on small data). A transformer connects any two positions in one step and can start from a pretrained encoder like BERT, which usually wins when one exists, at \(n^2\) cost. Watch inference on sequences longer than any in training: learned position embeddings can't extend, while RoPE or an RNN handles length more gracefully. Either way, a CRF layer or a logit mask can enforce valid outputs.

P6Validation loss starts rising at epoch 5 while training loss keeps falling. What do you do?

It's overfitting. Keep the epoch-5 checkpoint (early stopping with some patience). Then add regularization: dropout, weight decay, augmentation, a smaller model or more data. Lower the learning rate or add decay if the curves are noisy. Before all that, rule out leakage or a distribution shift between the splits, and check that the metric you care about moves the same way as the loss.

P7Your loss suddenly spikes to NaN halfway through training. Causes and fixes?

Usually exploding gradients: one bad batch or a steep cliff in the loss, often worse in RNNs or with fp16 overflow. Clip the gradient norm, lower the learning rate or add warmup, check the inputs for huge or missing values, use numerically stable log-softmax, and use loss scaling for fp16. Plot the gradient norm next to the loss to confirm.

P8How would you optimize a metric that isn't differentiable?

Use a smooth surrogate (soft versions of max and argmax, with a temperature), Gumbel-softmax, a straight-through estimator, or REINFORCE with the metric as the reward and a baseline to cut variance. Or keep cross-entropy and weight it. Check that the surrogate tracks the real metric; it can also add nothing when cross-entropy already captures what the metric rewards.

P9What is catastrophic forgetting, and how do you reduce it?

Training on new data overwrites what the model knew. To reduce it: a small learning rate and fewer epochs; freeze lower layers or use layer-wise learning-rate decay; adapters or LoRA; replay some old data; or EWC, which penalizes moving the weights that mattered for old tasks (weighted by Fisher information). In production, the same issue shows up as retraining under drift.
