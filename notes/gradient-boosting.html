Gradient boosting and XGBoost

What happens at every step and every node: trees fitted to gradients one by one, what XGBoost computes at a node (g, h, the leaf weight, the gain), how missing values and categories are handled, why each regularizer exists, and what breaks when you change one.

About 50 minutes, plus the questions · six loan applicants worked tree by tree, then XGBoost at the node, then the libraries and the practice · predictionsgradientschosen split or leaf

In short

  1. Boosting builds \(F(x) = F_0 + \eta \sum_m f_m(x)\), one small regression tree at a time. Each tree is fitted to the negative gradient of the loss at the current predictions: the residual \(y - F\) for squared error, \(y - p\) for log loss. It's gradient descent, with each step a tree.
  2. A leaf stores a correction, not a target. For squared error the best correction is the mean residual and the best split is the biggest drop in squared error. For classification \(F\) is the log-odds, and the sigmoid is applied once, to the total.
  3. XGBoost expands each row's loss to second order around its current prediction: slope \(g\) and bend \(h\). Summing over a leaf gives the best leaf value \(w^* = -G/(H + \lambda)\). A split's gain is half of (left score + right score − parent score), minus \(\gamma\), where a node's score is \(G^2/(H + \lambda)\). For log loss, \(g = p - y\) and \(h = p(1 - p)\).
  4. \(\lambda\) shrinks leaves with a small hessian sum (few rows, or rows the model is already sure about), \(\gamma\) is a price per leaf, and min_child_weight is a minimum hessian per child. All three stop a leaf chasing a handful of rows.
  5. Missing values: at every split, the missing rows' \(G\) and \(H\) are tried on the left and on the right, and the better side is stored as the default direction. If training had no missing values, that direction was never learned.
  6. Speed comes from histograms (bin once, sum \(g\) and \(h\) per bin, get one child by subtraction) and parallel work inside each tree. LightGBM adds leaf-wise growth, GOSS and EFB; CatBoost adds ordered target statistics, ordered boosting and symmetric trees.
  7. Boosting cuts bias and overfits as trees are added; a forest cuts variance and doesn't. Fix \(\eta\), early-stop on a validation set that looks like production, then tune depth and min_child_weight, subsampling, and the penalties.
  8. In practice: scale_pos_weight multiplies the predicted odds (recalibrate), monotone constraints are enforced at split time with bounds on the leaf values, split-count and gain importances mislead (prefer SHAP), and a sum of trees can't extrapolate.

Settings used throughout: learning rate \(\eta = 0.3\) (XGBoost's default), and each tree makes one split, so every tree can be worked by hand. The same steps work at any depth.

A tree is questions plus numbers

A tree asks a few yes/no questions, like “late < 1.5?”, to send each row to a leaf, and each leaf holds one number. Building a tree means choosing two things: the questions, which decide which rows end up together, and the number in each leaf. A row the tree has never seen still falls into some leaf, so the tree works on new data too.

The model is a sum of trees

\[ F(x) = F_0 + \eta\, f_1(x) + \dots + \eta\, f_M(x) \]
  • \(F_0\) is the starting number, the same for everyone.
  • \(f_m(x)\) is the \(m\)-th tree's output: a correction to the prediction so far, not a prediction on its own.
  • \(\eta\) is the learning rate: each correction is only partly trusted (section 02 says why).
  • For regression, \(F\) is the prediction itself. For classification, \(F\) is a score, the log-odds, which becomes a probability only at the very end (section 05).

One loss for the whole model

Each row gets a penalty for how wrong it is, and the penalties add up: \(L = \sum_i \ell(y_i, F_i)\). For regression \(\ell = \tfrac12 (y - F)^2\), so being off by 10 costs 50; for classification it's the log loss. Everything below is chosen to make this one number smaller: the starting number, every split and every leaf.

One tree at a time

Choosing 100 trees at once to minimize \(L\) is hopeless: there are far too many combinations. So boosting is greedy (the textbook name is forward stagewise additive modelling): keep everything built so far fixed, find the one new tree that lowers \(L\) the most, add it, freeze it, repeat. Every round solves the same problem: with the current predictions \(F_i\) fixed, find the tree \(f\) that minimizes

\[ \sum_i \ell\big(y_i,\ F_i + f(x_i)\big) \]

This is “the loss inside the tree”. It isn't Gini or entropy, which belong to a standalone classification tree; it's the model's own loss, measured after adding the new tree. And since a leaf holds a number to be added, every tree in boosting is a regression tree, even for classification.

In an interview: “Boosting builds an additive model, a starting value plus a sum of small trees. Each tree is a correction to the prediction so far, fitted greedily to lower one loss given everything before it. Each is a regression tree, even for classification, because its leaves hold numbers that get added to a score. A forest averages independent deep trees to cut variance; boosting adds shallow trees in sequence to cut bias, which is why it can overfit as trees are added.”

\[ \begin{aligned} \text{drop} &= \frac12 \Big[ \frac{(\sum r_L)^2}{n_L} + \frac{(\sum r_R)^2}{n_R} \\ &\qquad - \frac{(\sum r)^2}{n} \Big] \end{aligned} \]

Deeper trees repeat the search inside each child, on that child's rows only, with that child's own loss as the “before”. They stop at the maximum depth, or when no split lowers the loss.

The learning rate

Don't add the whole tree. Add \(\eta\) times it, with \(\eta = 0.3\): +4.5 for rows 1–4 and −9 for rows 5–6, so \(F\) becomes 84.5 (rows 1–4) and 71 (rows 5–6).

  • Why not the full +15 and −30? Tree 1 was fitted to these exact rows, noise included, so trusting it fully overfits. Taking 30% leaves room for later trees to correct it. The cost is more trees (section 03).
  • Does \(\eta\) change which split wins? No. The split search pretends the full leaf value will be added; \(\eta\) is applied afterwards. Adding only \(\eta\) of a leaf's value removes a share \(2\eta - \eta^2\) of its full drop (expand \(\tfrac12\sum (r - \eta w)^2\)). With \(\eta = 0.3\) that's 0.51 for every split: 1200 → 612, 1350 → 688.5, 540 → 275.4. Every drop shrinks by the same factor, so the order is unchanged. What \(\eta\) does change is the residuals the next tree sees.

03Why it's called gradient boosting

The slope of \(\tfrac12 (y - F)^2\) in the prediction \(F\) is \(F - y\). So the residual is minus the slope:

\[ \begin{aligned} \frac{\partial}{\partial F}\, \tfrac12 (y - F)^2 &= F - y \\ r &= y - F \\ &= -\frac{\partial}{\partial F}\, \tfrac12 (y - F)^2 \end{aligned} \]

Each tree in section 02 was fitted to minus the slope of every row's loss: the downhill direction for that row. Adding the tree moves every row a little way downhill. That's gradient descent, and it generalizes to any loss you can differentiate.

Gradient descent on the predictions

Treat the \(n\) training predictions as the parameters. Their loss is a function of \(n\) numbers, and plain gradient descent would update each one:

\[ \begin{aligned} L(F_1, \dots, F_n) &= \sum_i \ell(y_i, F_i) \\ g_i &= \frac{\partial \ell(y_i, F_i)}{\partial F_i} \\ F_i &\leftarrow F_i - \eta\, g_i \end{aligned} \]

That would just memorize the training rows, and say nothing about a new \(x\). So boosting replaces the step \(-g\) by the tree that's closest to it, which is a function of the features and therefore works for any row:

\[ \begin{aligned} f_m &= \arg\min_{f \in \text{trees}} \sum_i \big(-g_i - f(x_i)\big)^2 \\ F_m(x) &= F_{m-1}(x) + \eta\, f_m(x) \end{aligned} \]

In words: the tree is the best tree-shaped approximation of the negative gradient, and adding it is one gradient step taken in the space of functions. That's why it's called functional gradient descent, and why \(-g_i\) is called the pseudo-residual.

Friedman's algorithm (classic gradient boosting)

  1. Start at the best constant: \(F_0 = \arg\min_c \sum_i \ell(y_i, c)\).
  2. Each round: compute the pseudo-residuals \(r_i = -g_i\) at \(F_{m-1}\).
  3. Fit a regression tree to the \(r_i\) by squared error. This only chooses the regions (the leaves).
  4. Re-set each leaf to the value that minimizes the real loss on that leaf's rows: \(c_j = \arg\min_c \sum_{i \in j} \ell\big(y_i, F_{m-1}(x_i) + c\big)\).
  5. Add \(\eta\) times the tree, and repeat.

Why step 4 matters. For absolute error the tree is fitted to signs, ±1, so its raw leaf values are at most 1 in size: useless as step sizes when the residuals are in the tens. Re-setting each leaf to its median residual makes every step the right size. For squared error the mean residual is already the best value, so step 4 changes nothing. For log loss the best value has no formula, so it takes one Newton step instead. XGBoost goes further and uses that Newton information to choose the splits too (section 06).

Why the loss matters: outliers. In a larger simulated loan book, corrupting 2% of the training limits with a +₹500k typo gave a test RMSE of 29.0 under squared error, against 10.5 under absolute error and 10.9 under Huber. Under squared error those rows have residuals near 500 and every tree chases them; under absolute error each row only says “up” or “down”.

Initialization

\(F_0\) is the best constant for the loss: the mean for squared error, the median for absolute error, and the log-odds of the base rate for log loss, where the slope \(\sum (p - y)\) is zero exactly when \(p = \bar y\). A bad start isn't fatal but wastes trees: in the same simulated book (8.7% defaults), starting XGBoost at \(p = 0.5\) needed 64 trees instead of 35 to reach the same test log loss, because the first trees spent themselves walking everyone down to 8.7%. Recent XGBoost versions estimate the start from the data for this reason.

Shrinkage: why a small learning rate generalizes better

Each tree is a greedy, noisy estimate of the downhill direction, fitted to the same rows it will be judged on. A full step bakes all of that noise in, and later trees have to spend themselves undoing it. A small step keeps only a little of each tree, so the final model is an average over many trees, each fitted to slightly different residuals: the noise in any one of them is diluted. It's the same reason a small step size makes gradient descent stable. Validation log loss on the simulated book, depth-3 trees, 400 trees each:

  • The cost is training and prediction time, both proportional to the number of trees.

Stochastic gradient boosting

Friedman's later variant fits each tree on a random subsample of the rows, drawn without replacement, typically 50–80% (subsample). The tree is then applied to every row, so every prediction still moves. It helps in three ways: consecutive trees can't all latch onto the same noisy rows, so they're less alike and the sum has lower variance; each tree is cheaper; and the left-out rows give a free out-of-bag estimate of each round's improvement. The cost is a little bias and noisier steps, so it usually wants a few more trees. Column subsampling (section 09) does the same with features.

In an interview: “Gradient boosting is gradient descent in function space. Each round computes the negative gradient of the loss for every row at the current predictions, fits a regression tree to it by least squares, sets each leaf to the value that minimizes the real loss there, and adds a shrunk copy. For squared error the negative gradient is the residual, so ‘fit the residuals’ is a special case; for absolute error it's the sign; for log loss it's \(y - p\). Start at the best constant, keep the learning rate small, and subsample rows to decorrelate the trees.”

04g and h: the same thing, renamed

Section 02 used residuals and row counts, which only make sense for squared error. This section renames them so the same steps work for any loss. Nothing new happens yet.

Two new names

For every row define \(g = F - y\) (minus the residual) and \(h = 1\). Over the rows of a leaf, \(G = \sum g\), which is \(-\sum r\), and \(H = \sum h\), which is the row count \(n\). Section 02's two results become:

\[ \begin{aligned} \text{leaf value} &= \frac{\sum r}{n} \\ &= -\frac{G}{H} \\ \text{drop} &= \frac12 \Big[ \frac{G_L^2}{H_L} + \frac{G_R^2}{H_R} \\ &\qquad - \frac{(G_L + G_R)^2}{H_L + H_R} \Big] \end{aligned} \]

Check on Tree 1 (late < 1.5): the left rows have \(g\) = −20, −30, −10, 0, so \(G = -60\), \(H = 4\) and \(-G/H = 15\). The right rows have \(G = 60\), \(H = 2\), giving −30. The drop is ½ × [3600/4 + 3600/2 − 0/6] = 1350. All as before.

Slope and bend

Why these names? Nudge a leaf by \(w\). From section 02 the slope of the leaf's loss is \(-\sum (r - w)\), which is

\[ \frac{\partial\, \text{leaf loss}}{\partial w} = G + H w \]

Read it like walking down a hill. \(G\) is the slope right now, at \(w = 0\): its sign says which way is downhill and its size how steep. \(H\) is how fast that slope flattens per unit walked. If the slope is \(G\) and it flattens by \(H\) per unit, you reach flat ground after \(G/H\) units downhill: \(w = -G/H\). On Tree 1's left leaf (\(G = -60\), \(H = 4\)):

\(w\)051015
Slope \(G + H w\)−60−40−200

So per row, \(g\) is the slope of that row's loss in its prediction (the gradient), and \(h\) is the bend, how fast the slope changes (the hessian, the second derivative). For squared error the slope is \(F - y\) and the bend is always 1, which is why section 02 looked like “mean residual”. “Residual” and “row count” only mean something for squared error; “slope” and “bend” mean something for any loss with two derivatives and a bend above 0. Section 05 swaps in log loss and keeps every step.

In an interview: “Write \(g\) for each row's gradient of the loss with respect to its prediction and \(h\) for the second derivative. For squared error \(g = F - y\) and \(h = 1\), so \(-G/H\) is the mean residual and the gain is the squared-error drop.”

05Classification, tree by tree

F is a score, and the sigmoid comes last

A sum of trees can be any number, while a probability must stay in (0, 1), and probabilities can't be added (0.6 + 0.7 = 1.3). So for classification \(F\) is the log-odds, and it becomes a probability only at the very end:

\[ \begin{aligned} p &= \sigma(F) \\ &= \frac{1}{1 + e^{-F}} \\ F &= \log\frac{p}{1 - p} \end{aligned} \]
\(F\)−2−1012
\(p = \sigma(F)\)0.120.270.50.730.88
  • A tree has no sigmoid inside it. Each leaf holds a change in log-odds, like −0.3 or +0.6.
  • The sigmoid is applied once, to the total: \(p = \sigma(F_0 + \eta f_1 + \eta f_2 + \dots)\).
  • During training the sigmoid appears only when computing \(g\) and \(h\), always on the running total \(F\).

The loss, and round 0

\[ \ell = -\big[\, y \log p + (1 - y) \log (1 - p) \,\big] \]

A defaulter costs \(-\log p\) and a non-defaulter \(-\log(1 - p)\): a defaulter given \(p\) = 0.9, 0.5 or 0.1 costs 0.11, 0.69 or 2.30. The best single probability for everyone is the base rate, here 3/6 = 0.5, so \(F_0 = \log(0.5/0.5)\), which is 0, and every row starts at \(p = 0.5\). In general \(F_0 = \log\frac{\bar y}{1 - \bar y}\); for a 10% default rate that's \(\log(0.1/0.9) = -2.20\).

The slope g and the bend h

One fact does all the work: the sigmoid's slope is \(p(1 - p)\).

\[ \begin{aligned} \frac{d\sigma}{dF} &= \frac{e^{-F}}{(1 + e^{-F})^2} \\ &= \frac{1}{1 + e^{-F}} \cdot \frac{e^{-F}}{1 + e^{-F}} \\ &= p\,(1 - p) \end{aligned} \]

The slope \(g\), by the chain rule through \(p\):

\[ \begin{aligned} y = 1:\quad \frac{d\ell}{dF} &= -\frac{1}{p} \cdot p(1 - p) \\ &= p - 1 \\ y = 0:\quad \frac{d\ell}{dF} &= \frac{1}{1 - p} \cdot p(1 - p) \\ &= p \\ \text{both:}\quad g &= p - y \end{aligned} \]

The bend \(h\): in \(g = p - y\) only \(p\) moves as \(F\) moves, at the sigmoid's rate, so

\[ \begin{aligned} h &= \frac{dg}{dF} \\ &= p\,(1 - p) \end{aligned} \]

What they mean:

  • \(g = p - y\) is the probability error, with a sign. Positive means \(p\) is too high, so push down. It plays the role the residual played (\(y - p = -g\)).
  • \(h = p(1 - p)\) is how much \(p\) moves when \(F\) moves by 1. It depends on how sure the model already is: 0.25 at \(p = 0.5\), 0.09 at 0.9, 0.0099 at 0.99.

This is the one real difference from regression: \(h\) is no longer 1. A row the model is unsure about has a large \(h\); a row it's sure about has \(h\) near 0. And the claim about round 0 follows: for a single constant the slope is \(\sum (p - y)\), zero at \(p = \bar y\).

Why the exact leaf value doesn't work

In section 02 each leaf's best nudge was exact. Try that here, on the split late < 1.5:

  • Left leaf (rows 1–4, labels 0, 0, 1, 0, all at \(F = 0\)): the best probability is the leaf's rate, 1/4, so the best nudge solves \(\sigma(0 + w) = 1/4\): \(w = \log(1/3)\), about −1.10. That one works.
  • Right leaf (rows 5–6, both defaulted): the best probability is 1, so \(w = +\infty\). A pure leaf wants infinity.
  • From Tree 2 on, rows in a leaf have different \(F\)s, and the best \(w\) solves \(\sum_i \sigma(F_i + w) = \sum_i y_i\), which has no formula. A numerical search for every leaf of every candidate split, every round, is too slow, and each new loss would need its own solver.

The shortcut: a Newton step

Do exactly what section 04 did: the slope is \(G\) now and it flattens by \(H\) per unit, so walk \(G/H\) downhill.

\[ \begin{aligned} w &= -\frac{G}{H} \\ &= -\frac{\sum_i (p_i - y_i)}{\sum_i p_i (1 - p_i)} \end{aligned} \]
  • For squared error this is exact, because the bend really is constant.
  • For log loss it's an approximation. As you walk, \(p\) shifts and the bend changes; we pretend it stays at today's value. That replaces each row's loss curve with a parabola with the same slope and bend at the current point: the second-order approximation, or a Newton step (step = −slope / bend). It's close enough, and the next tree corrects what's left.
  • On Tree 1's leaves: left, \(G = 1\), \(H = 1\), so \(w = -1\) (exact: −1.10); right, \(G = -1\), \(H = 0.5\), so \(w = +2\) (exact: ∞, but the shortcut gives a finite step).

Why divide by \(H\), not by the number of rows? \(g\) is an error in probability, while \(F\) is measured in log-odds. Near \(p = 0.5\), one unit of log-odds moves \(p\) by about 0.25. The left leaf is 0.25 too high on average, so it needs about 0.25 / 0.25 = 1 unit down. Dividing by \(h\) converts “wrong in probability” into “how far to move in log-odds”. In regression \(F\) and \(y\) share units, so \(h = 1\).

The split score carries over unchanged: the same \(\tfrac12[G_L^2/H_L + G_R^2/H_R - G^2/H]\), now the loss a split removes under the parabola. It's Newton's method for logistic regression, one leaf at a time.

06XGBoost at a node

Section 05 already did XGBoost's core: it chose splits and leaf values from \(g\) and \(h\). On top of that, XGBoost adds penalties inside the objective (this section and 07), a learned direction for missing values (08), and engineering for speed (09).

Why it needs penalties. Look at the right leaf in section 05: +2 in Tree 1 and +1.55 in Tree 2, each time from just two rows, and a score of 17.6 after 200 trees. Small leaves take big swings on very little evidence. So XGBoost minimizes the loss plus a price for complexity:

\[ \begin{aligned} \text{Obj} &= \sum_i \ell\big(y_i,\ F_i + f(x_i)\big) \\ &\quad + \gamma T + \tfrac12 \lambda \sum_{j=1}^{T} w_j^2 \end{aligned} \]

In words: the loss after adding this round's tree \(f\), plus \(\gamma\) for each of its \(T\) leaves, plus an L2 price \(\lambda\) on its leaf values \(w_j\) (the same idea as ridge regression).

The derivation in five steps

Step 1: the objective is the line above. Step 2: replace each row's loss with a parabola. A Taylor expansion approximates a curve near a point from its value, slope and bend there; “second order” means stopping at the bend. The tree nudges row \(i\) by \(f_i = f(x_i)\):

\[ \begin{aligned} \ell(y_i,\ F_i + f_i) &\approx \ell(y_i, F_i) + g_i f_i + \tfrac12 h_i f_i^2 \\ g_i &= \frac{\partial \ell(y_i, F_i)}{\partial F_i} \\ h_i &= \frac{\partial^2 \ell(y_i, F_i)}{\partial F_i^2} \end{aligned} \]

In words: loss after the nudge ≈ loss now + slope × nudge + ½ × bend × nudge². Why second order: a first-order version (\(g f\) alone) is a straight line, which has no bottom: it says which way is downhill, not how far. The bend makes it a parabola, and a parabola's bottom has a formula.

Step 3: group the rows by leaf. Every row in leaf \(j\) gets the same \(w_j\). Drop \(\ell(y_i, F_i)\), which the tree can't change, and add up each leaf's rows:

\[ \begin{aligned} \text{Obj} &\approx \sum_{j=1}^{T} \Big[\, G_j w_j + \tfrac12 (H_j + \lambda)\, w_j^2 \,\Big] + \gamma T \\ G_j &= \sum_{i \in j} g_i \\ H_j &= \sum_{i \in j} h_i \end{aligned} \]

Each leaf is now its own parabola, and \(\lambda\) simply adds to the bend.

Step 4: the best leaf value. Set each leaf's slope to zero:

\[ \begin{aligned} G_j + (H_j + \lambda)\, w_j &= 0 \\ w_j^* &= -\frac{G_j}{H_j + \lambda} \end{aligned} \]

Step 5: score a tree, then a split. Put \(w_j^*\) back into the leaf's parabola to see how low it gets:

\[ \begin{aligned} &G_j w_j^* + \tfrac12 (H_j + \lambda)\, {w_j^*}^2 \\ &\quad = -\frac{G_j^2}{H_j + \lambda} + \frac{G_j^2}{2(H_j + \lambda)} \\ &\quad = -\frac{G_j^2}{2(H_j + \lambda)} \\ &\text{Obj}^* = -\frac12 \sum_{j=1}^{T} \frac{G_j^2}{H_j + \lambda} + \gamma T \end{aligned} \]

\(\text{Obj}^*\) is the structure score of a tree shape: the best it can do, computed from sums alone, with nothing refitted (lower is better; tutorials call \(G^2/(H + \lambda)\) a leaf's similarity score). A split turns one leaf into two, which adds one leaf and costs \(\gamma\). Its gain is the drop in the structure score:

\[ \begin{aligned} \text{Gain} &= \frac12 \Big[ \frac{G_L^2}{H_L + \lambda} + \frac{G_R^2}{H_R + \lambda} \\ &\qquad - \frac{(G_L + G_R)^2}{H_L + H_R + \lambda} \Big] - \gamma \end{aligned} \]

In words: (left score + right score − the score without splitting), halved, minus the price of a leaf. The tree takes the split with the largest gain; if none is above 0, the node stays a leaf (exact XGBoost applies \(\gamma\) afterwards, by pruning; section 07). You've done every step by hand already. The only new pieces are \(\lambda\) in the denominators and \(\gamma\) at the end; with \(\lambda = 0\) and \(\gamma = 0\) it's exactly section 05. One implementation detail: XGBoost stores \(\eta\, w^*\) in each leaf, so its dumped leaf values already include the learning rate.

The weighted least-squares view

Complete the square in each row's term from step 2:

\[ g\, w + \tfrac12 h\, w^2 = \tfrac12 h \Big(w + \frac{g}{h}\Big)^2 - \frac{g^2}{2h} \]

The last part doesn't depend on \(w\). So each XGBoost tree is a weighted least-squares fit to the targets \(-g/h\), with weights \(h\): each row asks for its own Newton step, weighted by how sure that step is. For squared error that's the residuals with weight 1, section 02 again. This view explains why the approximate split finder weights its quantiles by \(h\) (section 09).

07What each regularizer does, and why it exists

Every penalty answers the same failure: a leaf that takes a big step on little evidence. For log loss, “little evidence” has two forms: few rows, or rows the model is already sure about, whose \(h = p(1 - p)\) is tiny. Both make \(H\) small, and \(-G/H\) huge.

Think of \(\lambda\) as \(\lambda\) units of hessian saying “don't move”, added to every leaf. It matters only where the real \(H\) is comparable to it: small leaves and confident regions. It also enters the gain, where it shrinks each child's score \(G^2/(H + \lambda)\), so splits that isolate a small group earn less. On the six rows, \(\lambda = 1\) holds the pure late 2–3 group's score to 3.9 after 200 trees, against 17.6 with \(\lambda = 0\).

γ: a price per leaf, and pruning

A split must earn more than \(\gamma\), or it isn't worth the extra leaf. Two details matter at node level:

  • Units. XGBoost's code and dumps use the gain without the ½, and compare that number with gamma. The toy split's dumped gain is 1.167, so it survives gamma = 1.1 and is pruned at gamma = 1.2.
  • When it's applied. XGBoost's exact method grows the tree to max_depth first, then prunes bottom-up: a split is removed if its gain is below \(\gamma\) and both its children are leaves. So a weak split with a strong split below it survives, which matters for patterns like XOR, where the first cut gains almost nothing but enables a big second one. With the default histogram method, \(\gamma\) is checked as the tree grows instead, so a weak first cut is never made and an XOR-like pair can be missed.

\(\gamma\) also caps the tree's size indirectly: on noisy data most deep splits have small gains, and a \(\gamma\) on that scale removes them.

min_child_weight: a minimum hessian, not a row count

Each child needs \(H \ge\) min_child_weight, or the split is refused. For squared error (\(h = 1\)) that's a minimum row count. For log loss it counts rows weighted by how unsure the model is. Take 10 rows the model is 99% sure won't default (\(p = 0.01\), \(h = 0.0099\) each), one of which defaults anyway:

\[ \begin{aligned} G &= 10 \times 0.01 - 1 \\ &= -0.9 \\ H &= 10 \times 0.0099 \\ &= 0.099 \\ w_{\lambda = 0} &= 0.9 / 0.099 \\ &\approx 9.1 \\ w_{\lambda = 1} &= 0.9 / 1.099 \\ &\approx 0.82 \end{aligned} \]

With \(\lambda = 0\), one surprise would take the whole leaf from 1% risk to about 99% (before the learning rate). With the default min_child_weight = 1, the leaf isn't allowed at all, since \(H = 0.099 < 1\). At \(p = 0.03\) (\(h \approx 0.029\)), it takes about 35 rows to reach \(H = 1\). So min_child_weight blocks leaves made of rows the model already has right, where a big step would only chase noise. Two consequences:

  • It tightens on its own as training goes on. As predictions grow confident, each row's \(h\) shrinks, so the same rows carry less weight and fewer splits pass.
  • The toy can't split at all under the default: every cut leaves one side with \(H\) below 1 (0.75, 0.5 or 0.25). Section 15 shows what that does.

α, max_delta_step, and the rest

\(\alpha\) (L1) adds \(\alpha \sum_j \lvert w_j \rvert\). The parabola gets a kink at 0, and the solution moves \(G\) toward 0 by \(\alpha\) before dividing:

\[ \begin{aligned} w^* &= -\frac{\text{sign}(G)\, \max(\lvert G \rvert - \alpha,\ 0)}{H + \lambda} \\ \text{leaf score} &= \frac{\max(\lvert G \rvert - \alpha,\ 0)^2}{H + \lambda} \end{aligned} \]

A leaf whose \(\lvert G \rvert \le \alpha\) gets exactly 0, and the gain uses the thresholded \(G\) too. max_delta_step caps \(\lvert w \rvert\) directly; XGBoost suggests it for logistic loss on extremely imbalanced data, where \(H\) can be tiny. The learning rate, row subsampling and column subsampling regularize the ensemble rather than a leaf (sections 03 and 09).

In an interview: “\(\lambda\) adds to the hessian in every leaf, so it shrinks leaves with little hessian (few rows, or confident ones) and barely touches big leaves. \(\gamma\) is the minimum gain for a split, a price per leaf: the exact method prunes bottom-up after growing, the histogram method refuses weak splits as it grows. min_child_weight is the minimum hessian sum per child; for log loss it blocks leaves made of rows the model is already sure about. \(\alpha\) soft-thresholds \(G\), so weak leaves go to exactly 0.”

08Missing values: the learned default direction

Real data has holes: a blank field, no credit history yet. XGBoost doesn't need them filled in. Its sparsity-aware split finding learns, at every split, which side the missing rows should go.

  1. Scan only the rows where the feature is present, with running sums as usual.
  2. Add up the missing rows' \(G_{\text{miss}}\) and \(H_{\text{miss}}\) once.
  3. At each cut, compute the gain twice: once with the missing rows added to the left side, once to the right.
  4. Keep the better of all of these. The winning side is stored with the split as its default direction.
  5. At prediction time, a missing value follows its split's default direction.

  • Sparse matrices: in XGBoost, entries that aren't stored count as missing, so if your zeros are real zeros, a sparse matrix silently turns them into “missing”. (LightGBM keeps unstored entries as zeros unless zero_as_missing=True.)
  • Cost: the scan touches only present values, so very sparse features (one-hot columns, rare flags) are cheap.
  • Other libraries: LightGBM and sklearn's HistGB also learn a side per split (HistGB sends unseen-in-training missing values to the child with more rows). CatBoost doesn't learn one: by default a missing value is treated as smaller than every real value, so it always goes to the low side.

In an interview: “At each split XGBoost scans only the present values, then tries adding the missing rows' \(G\) and \(H\) to the left and to the right, and keeps whichever gives the higher gain as that split's default direction. No imputation, missingness can carry signal, and it's cheap on sparse data. The risk: if a feature had no missing values in training, the direction is a fixed default, so values that go missing only in production all go one arbitrary way.”

09Finding splits: exact, approximate, histogram

Exact greedy: running sums

Sort the rows by a feature, then sweep left to right, adding each row's \(g\) and \(h\) to \(G_L\) and \(H_L\), with \(G_R = G - G_L\) and \(H_R = H - H_L\). Every cut between distinct values is scored in one pass, with nothing refitted: that's why the gain needs only sums. XGBoost sorts each feature once before training (it stores the data in sorted column blocks), so each node costs one linear sweep per feature over its rows. Exact, but every distinct value is a candidate, which is slow on millions of rows.

Approximate: quantiles weighted by h

Instead of every value, propose candidate cuts at quantiles of the feature, with each row weighted by its hessian \(h_i\), so every bucket holds about the same total \(h\). Why \(h\): by the weighted least-squares view (section 06), each row is a squared-error target with weight \(h\), so rows the model is unsure about (\(p\) near 0.5) count more and get finer cut points, while confident rows get coarse ones. The candidates can be proposed once per tree (global) or again at every node (local). A weighted quantile sketch is a small summary that answers these weighted quantile questions within a set error and can be merged across machines, which lets the approximate method propose cuts when the data is split across machines.

Histograms: the modern default

  1. Once, before training, cut each feature into at most about 256 bins at its quantiles, and store each row's bin number (one byte).
  2. At each node, add up \(g\) and \(h\) per bin: one pass over the node's rows.
  3. Sweep the bin edges with running sums, scoring at most 255 candidates.
  • Sibling subtraction: a parent's histogram is the sum of its children's, so build the smaller child's histogram and get the bigger one's by subtraction. That at least halves the work at every level.
  • Where the speed comes from: far fewer candidates; one-byte codes, so passes over the rows are small and cache-friendly; histograms add up across threads, machines and GPUs.
  • The price: a cut can only land on a bin edge. In a simulated book, the best income threshold moved from 39.46 to 39.66 and lost 0.6% of its gain with 255 bins; with only 8 bins it moved to 48.6 and lost about a quarter. Quantile bins also shrug off outliers, which just share the last bin.

XGBoost (tree_method="hist", the default), LightGBM, CatBoost and sklearn's HistGradientBoosting all work this way.

Column subsampling, and parallelism

  • Column subsampling lets each tree (colsample_bytree), each level (bylevel) or each split (bynode) see a random share of the features; the three multiply, so 0.5 each on 64 features leaves 8 per split. It decorrelates the trees as in a random forest, speeds things up, and stops one dominant feature from taking every split, at the risk of missing the best feature at some nodes.
  • Parallel, but not across trees. Each tree needs the previous one's \(F\), so trees are built in sequence. The parallelism is inside a tree: \(g\) and \(h\) for all rows, histogram building, and the scans over different features all run at once.

In an interview: “Exact search sorts each feature once and sweeps every distinct value with running sums of \(g\) and \(h\). The approximate method proposes candidates at quantiles weighted by \(h\), because each row is a squared-error target with weight \(h\). Histogram search bins each feature once into about 256 quantile bins, sums \(g\) and \(h\) per bin in one pass, scans only bin edges, and gets one child's histogram free by subtraction. The price is a little threshold precision.”

10LightGBM: leaf-wise growth, GOSS, EFB

LightGBM uses the same core: \(g\), \(h\), the leaf score \(G^2/(H + \lambda)\), the same gain (reported without the ½) and leaves \(-G/(H + \lambda)\), with histograms by design. What differs is how a tree grows, plus two speed tricks and native categories. Its defaults also differ: \(\lambda = 0\), 31 leaves, at least 20 rows per leaf, learning rate 0.1.

Depth-wise vs leaf-wise growth

  • Depth-wise (level-wise) splits every leaf at the current depth, then goes one level deeper. XGBoost's default (grow_policy="depthwise"); a depth-\(d\) tree has up to \(2^d\) leaves.
  • Leaf-wise (best-first) splits, of all current leaves, the one whose best split gains most, until there are num_leaves leaves. LightGBM's way; XGBoost does it with grow_policy="lossguide".
  • Why leaf-wise: for the same number of leaves it usually lowers the training loss more, because it never spends a split on a leaf with little to gain.
  • The risk: deep, thin branches that fit a handful of rows. On a simulated loan book, LightGBM's first 8-leaf tree went one level deeper than a depth-3 tree could, isolating a 20-row group, and spent a split on a decoy feature.

GOSS: sample the rows that still teach something

Gradient-based one-side sampling. Rows with small \(\lvert g \rvert\) are already well fitted and add little to any split's gain. So keep the top \(a\) share of rows by \(\lvert g \rvert\) (say 20%; the paper ranks by \(\lvert g \rvert\), LightGBM's code by \(\lvert g h \rvert\), and it skips sampling for the first \(1/\eta\) rounds), sample \(b\) of all rows (say 10%) from the rest, and give each sampled row the weight \((1 - a)/b = 8\), since it stands in for 8 rows. The reweighting keeps \(G\) and \(H\) unbiased: without it the sums would come from the hardest rows only, and the leaves would overshoot toward them. Each tree sees 30% of the rows for little loss of accuracy.

EFB: bundle features that are never on together

Exclusive feature bundling. Sparse features that are rarely non-zero at the same time (one-hot columns, say) are merged into one feature, with each original's values shifted into its own range of bins, so a split can still separate them. Fewer histograms to build. Finding the best bundling is a graph-colouring problem, so it's done greedily, allowing a small rate of conflicts. Neither GOSS nor EFB defines LightGBM; its core is histograms plus leaf-wise growth.

Native categorical splits

Give LightGBM a column of category codes and it finds a good way to split the categories into two groups without trying all \(2^{k-1}\) groupings: it sorts the categories by \(G/(H + s)\), a Newton-style value per category with \(s\) = cat_smooth, and scans that order like a numeric feature. With plain \(G/H\), for squared error and the \(\lambda = 0\) gain, the best two-group split is always a cut of that sorted order (Fisher, 1958); with the smoothing it's a good heuristic rather than a guarantee. Very few categories (up to 4 by default) get one-vs-rest splits instead.

  • cat_smooth (default 10) does two jobs: categories with fewer rows than it are left out of the sorted scan (they go to the “other” side), and it adds pseudo-hessian to the rest, so a small category can't reach an extreme of the order by luck.
  • Other guards: cat_l2 adds to \(\lambda\) for these splits, max_cat_threshold limits how many categories the scan can put on one side, and min_data_per_group sets a minimum per side.
  • The risk: with hundreds of rare levels it can still overfit. On a useless 300-level pincode it dropped test AUC from 0.811 to 0.753, until cat_smooth was raised to 100.

XGBoost does the same with the histogram method and enable_categorical=True: a feature with at most max_cat_to_onehot levels gets one-vs-rest splits; otherwise its categories are sorted by their leaf weight \(-G/(H + \lambda)\) and the order is scanned like a number, with at most max_cat_threshold categories on one side. Same idea, same small-category risk.

In an interview: “LightGBM is histogram-based and grows leaf-wise: it always splits the leaf with the largest gain, so for the same number of leaves it lowers training loss faster, but it can grow deep, thin branches that overfit small data. num_leaves is the main capacity knob, with min_child_samples and max_depth as guards. GOSS keeps the large-gradient rows and an up-weighted sample of the rest; EFB bundles mutually exclusive sparse features. Categories are split by sorting them on \(G/H\).”

11CatBoost: ordered statistics, ordered boosting, symmetric trees

The problem with categories

A categorical feature with many levels (pincode, merchant ID, branch) is awkward for trees. One-hot encoding makes hundreds of sparse, individually weak columns; integer codes impose an order that means nothing. Target encoding replaces each category by its average target (“pincode 110034 → 12% default rate”): compact and powerful. But computed on the same rows the model trains on, it leaks: each row's own label is inside its category's average.

How big the leak is. In a simulated loan book, give every applicant a random pincode, 300 of them, with no effect on default. A pincode has about 12 training rows, so when one of them defaults, its own label lifts its pincode's rate by about 1/12, or 8 points. On training rows the encoding “knows” the answer; on test rows it's noise.

Ordered target statistics

Put the training rows in a random order and encode each row using only the rows before it with the same category, as if the data arrived one row at a time. A row's own label never enters its own encoding:

\[ \hat x_i = \frac{\sum_{j \prec i,\ c_j = c_i} y_j + a \cdot \text{prior}}{\#\{\, j \prec i : c_j = c_i \,\} + a} \]

In words: \(j \prec i\) means “before row \(i\) in the random order”. The prior (the overall rate) counts as \(a\) extra rows, so the first rows of a category, which have seen almost nothing, get an encoding near the prior instead of a wild value. Test rows use all the training rows. The early rows of each permutation get noisy encodings, so CatBoost uses several random permutations. An unseen category at inference gets the prior. With a real time order, has_time=True uses it instead of a random one, which matches how data arrives in production.

Ordered boosting: the prediction-shift problem

The same leak happens inside boosting itself. Row \(i\)'s gradient \(g_i\) is computed from a model that was trained on row \(i\), so on training rows the residuals are systematically smaller than they would be on new rows: the model's training predictions are shifted toward their own labels. The trees are then fitted to gradients that look better than reality, which is a bias, worst on small data. Ordered boosting computes each row's gradient from a model built only on the rows before it in the permutation, so no row's gradient comes from a model that saw it. Keeping one model per prefix would be far too costly, so CatBoost keeps a few, on prefixes of doubling length. It's boosting_type="Ordered"; the usual “Plain” mode is cheaper and common on large data.

Symmetric (oblivious) trees

Every node at the same depth asks the same question (the figure in section 10). A depth-6 tree is just 6 (feature, threshold) pairs and 64 leaves, and a row's leaf index is its 6 yes/no answers read as a 6-bit number. Prediction is a few comparisons and one array lookup, with no branching, so it vectorizes well and is very fast. Each level's question is chosen by its total improvement across every node of the level. The rigid shape is also a strong regularizer: 6 splits instead of up to 63, and no branch can carve out a handful of rows on its own. The cost is flexibility per tree, so it may need more trees.

CatBoost also builds combinations of categorical features (pincode × product) greedily as trees grow, with their own ordered statistics, and its defaults are strong: untuned, it scored 0.827 / 0.221 (AUC / log loss) on the simulated book where sklearn's untuned HistGB scored 0.808 / 0.250. Missing values aren't learned: by default they're treated as the smallest value.

In an interview: “Naive target encoding leaks, because each row's own label is inside its category's average, so a useless high-cardinality feature looks predictive on training rows and hurts on test. CatBoost's ordered target statistics encode each row using only the rows before it in a random permutation, plus a prior. Ordered boosting applies the same idea to the gradients, fixing prediction shift. Its symmetric trees ask one question per level, so the leaf index is a bit string: very fast inference and strong regularization.”

Depth sets the interaction order. A stump uses one feature, so a sum of stumps is a sum of one-feature effects, \(f_1(x_1) + f_2(x_2) + \dots\), and can't make a jump that happens only when A and B are true. For a 0/1 target that's 1 only when both are 1 (the four combinations equally common), the best a sum of stumps can do in squared error is −0.25, 0.25, 0.25, 0.75; a depth-2 tree gets 0, 0, 0, 1 exactly. On a smooth simulated target, stumps scored an RMSE of 20.5 (no better than linear regression) and depth 2 scored 10.5.

A tuning order that works

  1. Fix \(\eta\) at 0.05–0.1, set the number of trees high, and early-stop. Never grid-search the number of trees: one fit with early stopping reads the best round off the validation curve.
  2. Tree size with leaf size: max_depth or num_leaves, together with min_child_weight or min_child_samples. These usually matter most.
  3. Randomness: subsample and colsample_bytree.
  4. Penalties: \(\lambda\), \(\alpha\), \(\gamma\).
  5. Lower \(\eta\) (to 0.01–0.02), early-stop again, and refit.
  6. Score once on the test set.

Why this order: \(\eta\) and the tree count trade off almost one for one, so fixing \(\eta\) removes a redundant dimension; capacity has the biggest effect; randomness and penalties fine-tune what's left; and a smaller \(\eta\) at the end buys a slightly better minimum for more trees. Put \(\eta\) into a random search and the search drifts to tiny rates and slow models, because a smaller rate with more trees almost always looks a little better. Random search or Bayesian optimization beats a grid for steps 2–4. On the simulated book, this took validation log loss from 0.234 (defaults) to 0.226, and the winner was the smallest tree size tried (4 leaves): a winner at the edge of the grid means extend the grid.

Early stopping, done right

  • Keep the best round after a patience of, say, 50 rounds. LightGBM and XGBoost's sklearn API predict with the best round (with native xgb.train, pass iteration_range=(0, bst.best_iteration + 1)); sklearn's HistGB keeps the trees it built while waiting, so keep its patience small or refit.
  • The validation set must look like production. For credit or anything time-dependent, validate on a later period (out-of-time), with each customer on one side only. A random split of a drifting book stops at the wrong round.
  • Never early-stop on the test set: the round is then chosen for those rows, and no honest estimate is left. On the simulated book, stopping on test picked 24 trees and reported 0.218; stopping on validation picked 15 trees, which scored 0.220 on test.
  • Stop on the metric you'll use. AUC only cares about order and can stop where probabilities are still off; stop on log loss when the probability itself is used (pricing, expected loss).

13Practical behaviour

Class imbalance and scale_pos_weight

scale_pos_weight = k multiplies every positive row's \(g\) and \(h\) by \(k\), exactly as if each positive appeared \(k\) times. The model then fits the reweighted data, whose odds are \(k\) times the real ones. For one group, the weighted best constant solves

\[ \begin{aligned} k\, n_+ (p - 1) + n_-\, p &= 0 \\ \frac{p}{1 - p} &= k\, \frac{n_+}{n_-} \end{aligned} \]

In words: the zero-slope condition of the weighted log loss, with \(n_+\) positives and \(n_-\) negatives; the predicted odds come out at \(k\) times the true odds \(n_+/n_-\).

  • On the six rows, \(k = 2\) (still starting at \(p = 0.5\)): the root gain rises from 0.583 to 0.709, and the leaves become −0.222 and +1.0 (from −0.5 and +0.667): positives pull harder everywhere.
  • At \(k = 50\): an applicant with a true 3% risk has odds 0.031; times 50 that's 1.55, so a well-fitted model says about 0.61. In a simulated book with 8.7% defaults, a 100-tree depth-3 XGBoost model's mean prediction became 0.55, and its AUC fell from 0.825 to 0.794.
  • Fix the probabilities by subtracting \(\log k\) from the raw score, or by recalibrating on held-out data.
  • Do you need it at all? Often not. Starting at the log-odds of the base rate already balances the gradients (\(\sum g = 0\) at the start), and log loss is fine with rare positives. If you only need a ranking or a decision, keep the plain loss and move the threshold. Weighting can help when positives are so rare that splits on them can't clear min_child_weight; max_delta_step is the other knob for that case.

Monotonic constraints

Credit models are expected to move one way in some features: predicted risk mustn't fall as late payments rise, or rise as income rises. An unconstrained booster fits some noise, so in places a richer applicant gets a higher risk, which is hard to defend to a customer or a regulator and is usually overfitting anyway. A monotonic constraint forces the prediction to move only one way in a feature, with every other feature held fixed. It's enforced while the tree grows:

  1. Reject violating splits. For a split on a feature constrained to increase, a candidate whose left (lower-value) child gets a larger weight than its right child is refused (its gain is treated as \(-\infty\)).
  2. Pass bounds down. After an accepted split with child weights \(w_L \le w_R\), the midpoint \(m = (w_L + w_R)/2\) becomes an upper bound for every leaf in the left subtree and a lower bound for every leaf in the right subtree. Later splits, on any feature, inherit these bounds.
  3. Clip leaf values into their bounds, so nothing deeper down can undo the order.
  4. Each tree is then monotone in that feature, and a sum of monotone functions is monotone, so the whole model is.

On a simulated loan book, unconstrained XGBoost's average risk curve rose with income at 12 of 27 steps, and every applicant's own curve rose somewhere. Constrained (income −1, EMI share and late payments +1), no curve rose anywhere, test log loss was unchanged (0.222 → 0.221), and AUC fell from 0.832 to 0.811; on a test set this size a gap like that is partly luck (the true probabilities themselves score 0.817). A wrong constraint shows up as a flat curve and a worse score: forcing risk to rise with income took log loss to 0.262.

Caveats: the constraint holds with other features fixed, which can differ from the raw trend (if higher earners take bigger loans, raw default rates can rise with income even though, at a fixed loan size, they fall); and it says nothing about where missing values go, which is the learned default direction. LightGBM offers three enforcement methods (monotone_constraints_method): “basic” is the midpoint bounding above, the most restrictive; “intermediate” and “advanced” compute tighter, less restrictive bounds. Interaction constraints are the sibling tool: they say which features may share a tree path, e.g. {income, EMI} together and late payments alone, making the model \(f(\text{income}, \text{emi}) + g(\text{late})\) in log-odds.

With near-duplicate features, boosting tends to give the credit to whichever copy the early trees picked (the other's residual signal is gone), and which one wins can flip with the seed: add their importances or drop one before reading them.

TreeSHAP in one paragraph

A SHAP value splits one prediction into per-feature contributions that add up exactly to the raw score: \(F(x) = \phi_0 + \sum_j \phi_j\), with \(\phi_0\) the average score, in log-odds for a classifier. Each \(\phi_j\) is a Shapley value: feature \(j\)'s extra contribution when it “joins”, averaged over every order in which features could join, where a feature that hasn't joined is averaged out. For a rule “risk = 1 if income < 40k AND EMI share > 0.5”, with those conditions true for 19% and 38% of applicants independently (base 0.072), a flagged applicant gets 0.56 for income and 0.37 for EMI: the rarer condition moves the prediction further when it's revealed. With \(k\) features there are \(k!\) orders, too many to list. TreeSHAP computes the exact values from the tree's structure in polynomial time: for any set of known features it follows their branches and averages over the unknown ones' branches by the training cover that went each way, and one recursion handles all subsets at once. An applicant's largest positive values are the reasons for a decline. SHAP describes the model, not causes, and correlated features share credit arbitrarily.

Custom objectives, ranking, offsets and DART

  • Custom objectives: XGBoost and LightGBM accept a function that returns \(g\) and \(h\) for every row; that's all the tree builder needs. \(h\) must stay positive (libraries clip it to a small floor), so a loss with zero or negative curvature breaks \(-G/(H + \lambda)\) and the gain. The evaluation metric is separate from the objective.
  • Ranking (LambdaMART): within each query, every pair of items gets a “lambda” gradient weighted by how much swapping them would change NDCG; each item's lambdas sum to its \(g\) (with a matching \(h\)), and trees are grown as usual. Keep each query's rows together when splitting the data.
  • Offsets and continued training: base_margin (XGBoost) or init_score (LightGBM) gives each row its own starting score instead of one \(F_0\), such as log exposure in a Poisson model or an earlier model's score; boosting continues from it. Passing an existing model (xgb_model) adds trees to it.
  • DART drops a random few of the existing trees when computing each round's gradients, so no early tree dominates. It regularizes, but it's slower and doesn't combine well with early stopping.

Why boosting overfits noisy labels more than a random forest

Boosting puts each new tree where the remaining error is, and a mislabelled or unpredictable row stays in the remaining error. On the six rows, row 3 (a defaulter that looks like the non-defaulters) has \(g\) = −0.5 at the start, −0.574 after one tree, −0.70 after ten, and settles at −0.667, while row 5's \(g\) falls to −0.002. The unfixable row ends up with one of the largest gradients in the data, round after round, and deeper trees will spend splits isolating it. A random forest fits each tree to the labels with every row weighted equally; a noisy row distorts a few leaves in some trees, and averaging over bootstrap trees dilutes it. Log loss at least caps each row's pull at \(\lvert g \rvert \le 1\); AdaBoost's exponential loss doesn't, which is why it's even more fragile. For regression with squared error, one huge residual dominates \(G\) in every leaf it touches. Guards: early stopping, min_child_weight and \(\lambda\), subsampling, a robust loss (Huber, absolute error), and cleaning the labels.

No extrapolation

Every tree is flat beyond its last split, so the sum is too. An applicant with 10 late payments gets the same 66.35 as one with 3. In a simulated book, a booster predicted a credit limit of 242.6 at incomes of 150, 300 and 600 (₹k), where the truth was 240, 480 and 960. Fixes: predict a quantity that stays in range (limit ÷ income), detrend first and boost the residual of a linear model, or use linear leaves (LightGBM's linear_tree).

Calibration

A booster trained on log loss and early-stopped on log loss is often reasonably calibrated, because log loss rewards honest probabilities. It drifts when: you go past the best round (on the six rows, 200 trees took one- and two-row groups to 0.000 and 1.000); you use scale_pos_weight, class weights or undersampling (odds × \(k\)); you use a large \(\eta\) or tiny leaves. Check a reliability curve on held-out, out-of-time data, and fix it with Platt scaling (a logistic regression on the raw score, good with little data) or isotonic regression (more flexible, needs more data), fitted on data not used for training or early stopping.

In an interview: “scale_pos_weight multiplies the positives' \(g\) and \(h\), so the model learns \(k\) times the odds: subtract \(\log k\) or recalibrate, or just move the threshold. Monotone constraints are enforced at split time: violating splits are rejected and midpoint bounds pass down to the leaves, so every tree, and the sum, is monotone. Split-count and gain importances are biased and computed on training data; use SHAP or permutation importance. Boosting chases unfixable rows, can't extrapolate, and needs a calibration check after any reweighting.”

Tabular foundation models trained to do in-context learning are now competitive on small tables. Ensembles of a booster and a neural net often beat either alone.

15What-ifs

…the learning rate is 1?

Every tree goes in at full size, noise and all. On the six rows, one tree takes the late 2–3 group from 0.5 to 0.88, on two rows, and two trees to 0.96. For log loss a full Newton step from far away also overshoots, because the parabola is only accurate near the current point: in a simulated book, one full step took a group with a real 30.5% default rate from the 8.7% base rate to 58%. Validation loss bottoms early and high (\(\eta = 0.5\) was best after 2 trees at 0.239, against 0.232 for small rates) and then climbs fast. Given the same residuals, \(\eta\) doesn't change which split wins; but a full step changes the residuals every later tree sees, and keeps all of each tree's noise.

…the trees are very deep?

Each tree fits the current residuals almost exactly, noise included. With full-depth trees and \(\eta = 0.1\), every round leaves 90% of each residual and the next tree refits the same pattern, so after 200 rounds the sum is about \(1 - 0.9^{200} \approx 1\) times one memorizing tree: a test RMSE of 13.5 in a simulated book, no better than a single deep tree (13.9), against 10.3 for depth-3 trees. Boosting reduces bias; a deep tree has no bias left to reduce, only variance, and adding deep trees in sequence doesn't average it away. Depth also raises the interaction order and shrinks leaves, so min_child_weight and \(\lambda\) start to bite.

…λ is 0?

Leaves become \(-G/H\), so a leaf with a tiny hessian sum takes a huge step: 10 confident rows with one surprise default give 9.1 in log-odds instead of 0.82. Pure groups climb without limit: on the six rows the late 2–3 score reaches 17.6 after 200 trees, against 3.9 with \(\lambda = 1\). With squared error and big leaves, \(\lambda = 0\) barely matters, since \(H\) is a row count. LightGBM's default is \(\lambda = 0\), relying on min_child_samples instead.

…there's no early stopping?

Training loss keeps falling; validation loss is a U and climbs past the best round. In a simulated book at \(\eta = 0.1\), the best was 15 trees (0.232), and 600 trees reached 0.301 while training loss fell to 0.044. Probabilities grow overconfident: on the six rows, 200 trees push the late 1 and late 2–3 groups to 0.000 and 1.000. A small \(\eta\) makes the climb slower, not absent.

…min_child_weight is huge?

No split can give both children enough hessian, so every tree is a single leaf, \(w = -G/(H + \lambda)\): a constant shift. At the base-rate start \(G = 0\), so the model never moves from \(F_0\). On the six rows even the default of 1 does this (every cut leaves a side with \(H < 1\)): five trees, all single leaves of value 0, and every applicant stays at 0.5. Less extreme values bite harder as training goes on, because confident rows carry less hessian. High bias, by design.

…a feature is duplicated?

With exact search, the copy offers exactly the same gains, so ties are broken by a fixed rule and predictions don't change. Two things do change: with column subsampling, the duplicated feature is twice as likely to be offered at each tree or node, so it's effectively up-weighted; and importances. Without column subsampling every tie goes to the same copy (XGBoost prefers the lower column index), so one copy takes all the splits and the other shows zero; with column subsampling each copy wins when the other isn't offered, so the credit is split between them. Near-duplicates with a little noise behave like correlated features: the first trees take one, and the credit concentrates there.

…one label is a big outlier?

For regression with squared error, that row's residual is huge and dominates \(G\) in every leaf it lands in, so every tree bends toward it; in a simulated book, a 2% share of +₹500k typos took test RMSE from about 10 to 29.0, while absolute error (10.5) and Huber (10.9) shrugged it off. For classification a flipped label caps at \(\lvert g \rvert \le 1\) but never goes away (section 13), so deeper trees isolate it. Use a robust loss, early stopping and bigger leaves, and look at the rows with the largest final gradients: they're often label errors.

…every feature is missing for a row?

The row follows the default direction at every split, so in each tree it lands in one fixed leaf: the end of the “all-missing” path. Its prediction is \(F_0\) plus \(\eta\) times those leaves, which isn't the base rate and isn't a considered estimate either. Each default direction was learned from rows where that one feature was missing (or not learned at all), not from rows where everything was. On the six rows, after two trees, a missing late count gets 0.374 (the low-risk value) from this note's NumPy build and 0.744 (the high-risk value) from XGBoost's default histogram method: two arbitrary defaults, two very different answers. Catch such rows before scoring: count missing fields, route them to a fallback (the base rate, a rule, a manual review), and monitor how often it happens.

Quick ones

  • …you start from 0 instead of the base rate? The first trees spend themselves walking everyone to the base rate; the end point is the same, the early rounds are wasted.
  • …you fit the gradient instead of the negative gradient? Every step goes uphill and training loss rises each round. It's the classic from-scratch bug; the check is that training loss falls.
  • …the trees are fitted in parallel on the same target? They come out nearly the same, so the sum is one tree with a bigger step. The correction only happens because tree \(m\) sees what trees 1 to \(m - 1\) got wrong.
  • …the base learner is linear? A sum of linear models is one linear model, so boosting adds nothing a regularized linear fit doesn't have. Trees work because sums of steps build curves and interactions.
  • …a category at inference was never seen? CatBoost gives it the prior; LightGBM sends it down the “other” side of each categorical split; one-hot gives all zeros.

        return LEAF(-G / (H + lam))
    best = SPLIT_SEARCH(rows, G, H)
    if best.gain <= 0:
        return LEAF(-G / (H + lam))
    split rows by best.f < best.cut
        # missing f → best.default side
    return NODE(best,
                GROW(left,  depth + 1),
                GROW(right, depth + 1))

One split search, with the default direction

SPLIT_SEARCH(rows, G, H):
  best.gain = -infinity
  for each feature f:
    M = rows where f is missing
    Gm = Σ g over M;  Hm = Σ h over M
    P = rows with f present, sorted by f
    GL = 0;  HL = 0
    for k = 0 .. len(P) - 2:
      GL += g[P[k]];  HL += h[P[k]]
      if f(P[k]) == f(P[k+1]):
        continue      # no cut inside ties
      for side in (left, right):
        gl, hl = GL, HL
        if side == left:
          gl += Gm;  hl += Hm
        gr = G - gl;  hr = H - hl
        if min(hl, hr) < min_child_weight:
          continue
        gain = 1/2 * ( gl²/(hl + lam)
                     + gr²/(hr + lam)
                     - G²/(H + lam) ) - gamma
        if gain > best.gain:
          cut = (f(P[k]) + f(P[k+1])) / 2
          best = (gain, f, cut, side)
  return best

Cost: sorting once per feature before training makes each node one linear sweep per feature; histograms replace the sorted rows by at most 256 bins. With \(\gamma\), XGBoost's exact method then prunes bottom-up any split whose gain is below \(\gamma\) and whose children are both leaves.

XGBoost from scratch, in NumPy

Every piece by hand: \(g\) and \(h\), the running-sum split search with the default direction, the gain and the leaf value. It follows the pseudocode line by line.

import numpy as np

def sigmoid(z):
  return 1 / (1 + np.exp(-z))

def grad_hess(y, F, loss):
  if loss == "squared":
    return F - y, np.ones_like(F)
  p = sigmoid(F)                  # log loss
  return p - y, p * (1 - p)

def score(G, H, lam):
  return G * G / (H + lam)

def best_split(X, g, h, cfg):
  lam, best = cfg["lam"], None
  G, H = g.sum(), h.sum()
  for j in range(X.shape[1]):
    x = X[:, j]
    miss = np.isnan(x)
    Gm, Hm = g[miss].sum(), h[miss].sum()
    o = np.argsort(x[~miss])
    xs = x[~miss][o]
    gs, hs = g[~miss][o], h[~miss][o]
    GL = HL = 0.0
    for i in range(len(xs) - 1):
      GL, HL = GL + gs[i], HL + hs[i]
      if xs[i] == xs[i + 1]:
        continue          # no cut inside ties
      for m_left in (True, False):
        gl = GL + Gm * m_left
        hl = HL + Hm * m_left
        gr, hr = G - gl, H - hl
        if min(hl, hr) < cfg["mcw"]:
          continue
        gain = 0.5 * (score(gl, hl, lam)
          + score(gr, hr, lam)
          - score(G, H, lam)) - cfg["gamma"]
        if best is None or gain > best[0]:
          cut = (xs[i] + xs[i + 1]) / 2
          best = (gain, j, cut, m_left)
  return best

def build(X, g, h, depth, cfg):
  if depth < cfg["max_depth"]:
    s = best_split(X, g, h, cfg)
    if s is not None and s[0] > 0:
      _, j, cut, m_left = s
      miss = np.isnan(X[:, j])
      L = np.where(miss, m_left, X[:, j] < cut)
      d = depth + 1
      lt = build(X[L], g[L], h[L], d, cfg)
      rt = build(X[~L], g[~L], h[~L], d, cfg)
      return {"j": j, "cut": cut,
              "m_left": m_left,
              "left": lt, "right": rt}
  w = -g.sum() / (h.sum() + cfg["lam"])
  return {"leaf": float(w)}

def tree_predict(node, x):
  while "leaf" not in node:
    v = x[node["j"]]
    if np.isnan(v):
      go_left = node["m_left"]
    else:
      go_left = v < node["cut"]
    side = "left" if go_left else "right"
    node = node[side]
  return node["leaf"]

def fit(X, y, loss, n_trees, cfg):
  if loss == "squared":
    F0 = y.mean()
  else:                 # log-odds of base rate
    F0 = np.log(y.mean() / (1 - y.mean()))
  F = np.full(len(y), F0)
  trees = []
  for _ in range(n_trees):
    g, h = grad_hess(y, F, loss)
    tree = build(X, g, h, 0, cfg)
    step = [tree_predict(tree, x) for x in X]
    F = F + cfg["eta"] * np.array(step)
    trees.append(tree)
  return F0, trees

def predict(X, F0, trees, cfg, loss):
  F = np.full(len(X), F0)
  for t in trees:
    F += cfg["eta"] * np.array(
      [tree_predict(t, x) for x in X])
  if loss == "squared":
    return F
  return sigmoid(F)

17Interview questions

Answer out loud first, then open the answer.

1How does gradient boosting work, step by step?

It builds an additive model one small regression tree at a time: each tree is fitted to the negative gradient of the loss at the current predictions, and added after shrinking by the learning rate.

  1. Start every row at the best constant \(F_0\): the mean for squared error, the log-odds of the base rate for log loss.
  2. Each round, compute every row's gradient \(g\) (and, for XGBoost, the hessian \(h\)) at its current prediction.
  3. Grow a regression tree on them: classic GBM fits \(-g\) by least squares; XGBoost scores splits with the second-order gain.
  4. Set each leaf to the value that lowers the loss most: the mean residual for squared error, a Newton step \(-G/(H + \lambda)\) for log loss.
  5. Update \(F \leftarrow F + \eta \cdot \text{tree}(x)\) and repeat until validation loss stops improving.
  6. Predict with \(F_0 + \eta \sum_m f_m(x)\), passed through the sigmoid for classification.

Why it works: each tree moves every row's prediction downhill on its own loss, and because the step is a function of the features, it moves unseen rows sensibly too. On a toy where credit limits fall with late payments, tree 1 cuts at 1.5 late payments; tree 2 cuts at 0.5, because tree 1 over-pushed the one applicant with a single late payment. Follow-up: trees are built in sequence, since each needs the previous predictions; the parallelism is inside a tree. (02, 03)

2Why fit the negative gradient? Why not fit the target directly?

Adding a tree fitted to the negative gradient is one gradient-descent step on the predictions, so every round lowers the loss; for squared error the negative gradient is exactly the residual.

\[ \begin{aligned} L &= \sum_i \ell(y_i, F_i) \\ -g_i &= -\frac{\partial \ell(y_i, F_i)}{\partial F_i} \\ f_m &= \arg\min_{f} \sum_i \big(-g_i - f(x_i)\big)^2 \end{aligned} \]

In words: the steepest way down for each row is \(-g_i\); the tree is the closest function of \(x\) to that direction. \(-g\) is \(y - F\) for squared error, \(\text{sign}(y - F)\) for absolute error and \(y - p\) for log loss.

Why not the target: every round would see the same labels and grow the same tree, ignoring what the model already knows. With gradients, rows that are already right have \(g \approx 0\) and barely pull on the split, so each tree works on what's still wrong. Trade-off: the gradient gives a direction, not a step size, so the leaves are re-set by a line search or Newton step. Fitting \(+g\) by mistake makes the training loss rise every round: the classic from-scratch bug. (03)

3What loss does each tree minimize? Gini, entropy? Are they classification trees?

Neither Gini nor entropy: each tree minimizes the model's own loss after the tree is added, and its leaves hold real numbers, so every tree is a regression tree, even for classification.

\[ \begin{aligned} &\sum_i \ell\big(y_i, F_i + f(x_i)\big) \\ &\quad \approx \text{const} + \sum_i \big[ g_i f(x_i) + \tfrac12 h_i f(x_i)^2 \big] \\ &\text{Gain} = \tfrac12 \Big[\tfrac{G_L^2}{H_L + \lambda} + \tfrac{G_R^2}{H_R + \lambda} \\ &\qquad - \tfrac{G^2}{H + \lambda}\Big] - \gamma \end{aligned} \]

In words: XGBoost approximates the loss after the tree to second order, and the gain is how much a split lowers that approximation. Classic GBM instead grows each tree by squared error on \(-g\) and fixes the leaf values afterwards.

Why not Gini: Gini and entropy score class purity for a standalone tree whose leaves predict classes. Here a leaf is a correction added to a running log-odds score, and what matters is the ensemble's loss. Follow-up: for squared error with \(\lambda = 0\) the gain is exactly half the drop in squared error, the usual regression-tree criterion. (01, 06)

4Does each tree output a probability? Where's the sigmoid?

No: each tree outputs a change in log-odds, and the sigmoid is applied once, to the total.

\[ p = \sigma\Big(F_0 + \eta \sum_m f_m(x)\Big) \]

In words: add up the start and every tree's shrunk leaf value in log-odds, then convert to a probability. During training the sigmoid appears only when computing \(g = p - y\) and \(h = p(1 - p)\) from the running total.

Why: probabilities are bounded and can't be added (0.6 + 0.7 = 1.3), while log-odds can take any value, so any sum maps back into (0, 1). Example: start at \(F_0 = 0\) (a 50% base rate); if two trees add +0.6 and +0.465 for some applicant, \(F\) is 1.065 and \(p = \sigma(1.065)\), about 0.744. Follow-up: AdaBoost's score is half the log-odds, so its probability is \(\sigma(2F)\). (05)

5What is the initial prediction F₀, and why does it matter?

The best constant for the loss: the mean for squared error, the log-odds of the base rate for log loss.

\[ \begin{aligned} \text{squared:}\quad \textstyle\sum_i (c - y_i) &= 0 \\ c &= \bar y \\ \text{log loss:}\quad \textstyle\sum_i (\sigma(c) - y_i) &= 0 \\ c &= \log\frac{\bar y}{1 - \bar y} \end{aligned} \]

In words: set the slope of the total loss in one shared constant to zero. At that start the gradients already sum to zero, \(\sum g = 0\), so imbalance doesn't tilt the first trees.

Why it matters: start elsewhere and the first trees spend themselves walking everyone to the base rate. In a simulated book with 8.7% defaults, starting at 0.5 needed 64 trees instead of 35 for the same test log loss. Follow-up: for absolute error it's the median; XGBoost's base_score sets it, and recent versions estimate it from the data. (03)

6Derive g and h for squared error and for log loss. What changes for multiclass?

Squared error: \(g = F - y\), \(h = 1\). Log loss on the raw score: \(g = p - y\), \(h = p(1 - p)\).

\[ \begin{aligned} \frac{dp}{dF} &= p(1 - p) \\ \frac{\partial \ell}{\partial p} &= -\frac{y}{p} + \frac{1 - y}{1 - p} \\ &= \frac{p - y}{p(1 - p)} \\ g &= \frac{\partial \ell}{\partial p} \cdot \frac{dp}{dF} \\ &= p - y \\ h &= \frac{dg}{dF} \\ &= p(1 - p) \end{aligned} \]

In words: the sigmoid's slope \(p(1 - p)\) cancels the denominator, leaving the probability error; differentiating \(p - y\) again leaves only the sigmoid's slope.

Why it matters: \(h\) is how much \(p\) moves per unit of log-odds, so confident rows (\(p\) near 0 or 1) have \(h \approx 0\) and count little. Multiclass: \(K\) scores, softmax probabilities, \(g_k = p_k - y_k\) and \(h_k = p_k(1 - p_k)\) (XGBoost uses twice that), and \(K\) trees per round. Follow-up: absolute error has \(h = 0\) almost everywhere, so the Newton leaf breaks; classic GBM uses the median residual instead, and XGBoost's absolute-error and quantile objectives grow the tree with \(h = 1\), then re-set each leaf by a line search, like Friedman's step 4. (05)

7Derive XGBoost's optimal leaf weight and split gain.

Expand the regularized objective to second order, group rows by leaf, and minimize each leaf's parabola: \(w^* = -G/(H + \lambda)\); the gain is the drop in the resulting structure score.

\[ \begin{aligned} \Omega &= \gamma T + \tfrac12 \lambda \textstyle\sum_j w_j^2 \\ \text{Obj} &= \textstyle\sum_i \ell(y_i, F_i + f_i) + \Omega \\ &\approx \textstyle\sum_i \big[g_i f_i + \tfrac12 h_i f_i^2\big] + \Omega \\ &= \textstyle\sum_j \big[G_j w_j + \tfrac12 (H_j + \lambda) w_j^2\big] \\ &\quad + \gamma T \\ w_j^* &= -\frac{G_j}{H_j + \lambda} \\ \text{Obj}^* &= -\tfrac12 \textstyle\sum_j \frac{G_j^2}{H_j + \lambda} + \gamma T \end{aligned} \]

In words: line 3 is the Taylor expansion, dropping the current loss, which the tree can't change; lines 4–5 use that every row in leaf \(j\) gets \(w_j\); line 6 sets each leaf's slope \(G_j + (H_j + \lambda) w_j\) to zero; line 7 plugs it back. A split replaces one leaf by two and adds one \(\gamma\):

\[ \begin{aligned} \text{Gain} &= \frac12 \Big[\frac{G_L^2}{H_L + \lambda} + \frac{G_R^2}{H_R + \lambda} \\ &\qquad - \frac{(G_L + G_R)^2}{H_L + H_R + \lambda}\Big] - \gamma \end{aligned} \]

Why it's useful: the gain needs only sums of \(g\) and \(h\), so every cut is scored in one sweep with running sums. Check: six rows at \(p = 0.5\), \(\lambda = 1\), split late < 1.5: \(G_L = 1\), \(H_L = 1\), \(G_R = -1\), \(H_R = 0.5\), so the gain is ½ × (0.5 + 0.667 − 0) = 0.583 and the leaves are −0.5 and +0.667. XGBoost's dump shows 1.167, because it drops the ½. (06)

8Why second-order? Why divide by the hessian?

A first-order approximation gives a direction but no step size; the second-order term makes each leaf a parabola whose minimum is a Newton step, and dividing by \(h\) converts an error in probability into a step in log-odds.

\[ \begin{aligned} \ell(F + w) &\approx \ell(F) + g\, w + \tfrac12 h\, w^2 \\ w^* &= -g / h \end{aligned} \]

In words: a straight line has no bottom; a parabola does. Near \(p = 0.5\), one unit of log-odds moves \(p\) by about 0.25, so a leaf whose probabilities are 0.25 too high needs about one unit down: \(G/H\) = 0.25/0.25 = 1 (the exact answer on the toy was 1.10).

  • Rows weighted by certainty: confident rows have \(h \approx 0\), so they barely count in \(H\) or in the choice of split.
  • Any loss plugs in: any twice-differentiable loss with \(h > 0\) only needs to supply \(g\) and \(h\); that's how custom objectives work.

Trade-off: the parabola is accurate only near the current prediction. From far away a full Newton step overshoots (a group with a real 30.5% rate jumped from 8.7% to 58% in one full step), which is one reason for \(\eta < 1\) and for recomputing \(g\) and \(h\) every round. (05)

9What do λ, γ and min_child_weight do? Give numbers.

\(\lambda\) shrinks leaf values, most where the hessian sum is small; \(\gamma\) is the minimum gain a split must earn; min_child_weight is the minimum hessian sum each child must have.

  • \(\lambda\) sits in \(-G/(H + \lambda)\) and in the gain. A one-row leaf (\(G = -0.5\), \(H = 0.25\)) goes from 2.0 to 0.4 at \(\lambda = 1\); a 100-row leaf goes from 2.0 to 1.92. It's \(\lambda\) units of hessian saying “don't move”.
  • \(\gamma\) is a price per leaf. XGBoost compares it with the gain without the ½: the toy split (1.167) survives \(\gamma = 1.1\) and is pruned at 1.2. The exact method grows to max_depth and prunes bottom-up, so a weak split with a strong one below it survives; the default histogram method checks \(\gamma\) as it grows, so it never makes the weak split.
  • min_child_weight counts rows weighted by \(p(1 - p)\). Ten rows at \(p = 0.01\) have \(H = 0.099\): with one surprise default and \(\lambda = 0\) their leaf would be 9.1 in log-odds; the default of 1 refuses it.

Why they exist: a leaf with little hessian (few rows, or rows the model is already sure about) takes a big step on little evidence. Trade-off: all three raise bias and lower variance. For squared error min_child_weight is just a minimum row count; for log loss it tightens as predictions grow confident. (07)

10How does XGBoost handle missing values? What can go wrong?

Sparsity-aware split finding: at each candidate split it tries sending the missing rows left and right, and keeps the side with the higher gain as that split's default direction.

\[ \begin{aligned} \text{left} &= (G_L + G_M,\ H_L + H_M) \\ \text{right} &= (G_R,\ H_R) \\ \text{or: left} &= (G_L,\ H_L) \\ \text{right} &= (G_R + G_M,\ H_R + H_M) \end{aligned} \]

In words: scan only present values, compute the missing rows' sums \(G_M\) and \(H_M\) once, and score each cut twice with the usual gain: once with the missing rows' sums on the left (first two lines), once on the right. On the toy, two missing defaulters at late < 1.5 score 1.083 on the right against 0.167 on the left, so missing goes with the risky group.

Why it's good: no imputation, missingness itself can carry signal, and the scan costs only the present values, so sparse data is cheap. What goes wrong: if a feature had no missing values in training, the direction is a fixed default, not learned, so values that go missing only in production all go one arbitrary way (in a simulation, AUC fell from 0.832 to 0.66); sparse matrices treat unstored zeros as missing; and CatBoost doesn't learn a direction (missing is the smallest value). Monitor missing rates between training and serving. (08)

11Exact vs approximate vs histogram split finding. Why weight quantiles by h?

Exact scores every distinct value; approximate scores candidates at \(h\)-weighted quantiles; histogram bins each feature once and scores only bin edges.

  • Exact: sort each feature once, then sweep with running sums \(G_L\), \(H_L\) and \(G_R = G - G_L\). Precise, slow on big data.
  • Approximate: candidate cuts at quantiles where each row weighs \(h_i\), proposed per tree or per node; a weighted quantile sketch makes this mergeable across machines.
  • Histogram: about 256 quantile bins per feature, one-byte codes, one pass per node to sum \(g\) and \(h\) per bin, the larger child's histogram by subtraction. The default in XGBoost, LightGBM, CatBoost and sklearn's HistGB.
\[ g\, w + \tfrac12 h\, w^2 = \tfrac12 h \big(w + g/h\big)^2 - \frac{g^2}{2h} \]

Why \(h\): in words, each row is a squared-error target \(-g/h\) with weight \(h\), so unsure rows deserve finer cut points. Trade-off: binning costs a little precision: in a simulation the best income cut moved from 39.46 to 39.66 and lost 0.6% of its gain. (09)

12Learning rate vs number of trees: how do they trade off?

A smaller learning rate needs proportionally more trees and usually reaches the same or a slightly better validation loss, with a flatter minimum.

On a simulated loan book: \(\eta\) = 0.1 was best at 15 trees, 0.03 at 91 and 0.01 at 266, all at a validation log loss of 0.232; for small rates \(\eta \times\) trees stayed about 2.7. \(\eta = 0.5\) was best after 2 trees, at a worse 0.239.

Why small helps: each tree is a greedy, noisy fit to the same rows; a small step keeps only a little of each tree's noise, so the model averages over many trees. Past the best round, a small rate also climbs slowly, so a mis-set tree count costs less. \(\eta\) doesn't change which split a tree picks (every drop shrinks by the same factor \(2\eta - \eta^2\)); it changes the residuals later trees see. Trade-off: training and prediction time grow with the number of trees. In practice: fix 0.05–0.1, early-stop, lower it at the end if you can afford it. (03)

13How do you prevent overfitting in gradient boosting?

Stop it chasing noise at two levels, the ensemble and the leaf, and check it on validation data that looks like production.

  • Ensemble: early stopping on the number of trees; a small learning rate; row and column subsampling, which decorrelate the trees.
  • Each tree: shallow depth or few leaves (lower interaction order); min_child_weight or min_child_samples; \(\lambda\), \(\alpha\) and \(\gamma\).
  • Structure: monotone and interaction constraints remove wiggles that are usually noise.
  • Data: a robust loss for outlying targets, label cleaning, out-of-time validation for drifting data, and the test set used once.

Why boosting needs it: each tree fits what's left, and eventually that's noise, so training loss falls forever while validation loss is U-shaped. Follow-up: tune in order: \(\eta\) with early stopping, then size, then sampling, then penalties. (12)

14Boosting vs bagging: bias and variance?

Bagging averages deep, independent trees to cut variance; boosting adds shallow, dependent trees in sequence to cut bias.

\[ \text{Var}\Big(\frac1B \sum_b T_b\Big) = \rho\, \sigma^2 + \frac{1 - \rho}{B}\, \sigma^2 \]

In words: for a forest of \(B\) trees each with variance \(\sigma^2\) and correlation \(\rho\), more trees only shrink the second term, so adding trees never hurts. Boosting instead reduces the remaining error tree by tree; once only noise is left, more trees raise variance.

On a simulated book, boosting's validation loss was best at 15 trees (0.232) and reached 0.301 by 600, while the forest's fell steadily and flattened at 0.249. Trade-off: tuned boosting usually wins on accuracy; a forest is harder to break, parallel to train, and needs almost no tuning. (01, 14)

15Why does boosting overfit noisy labels more than a random forest?

Boosting aims each new tree at the remaining error, and a mislabelled or unpredictable row stays in the remaining error forever, so it keeps attracting splits.

On a six-row toy with one feature, a defaulter whose feature value matches two non-defaulters (so no split can separate them) has \(g\) = −0.5 at the start, −0.70 after ten trees and settles at −0.667, while a fixable row's \(g\) falls to −0.002. The unfixable row ends up with one of the largest gradients, round after round, and deeper trees will isolate it.

  • The forest: every tree fits the labels with each row weighted equally; a noisy row distorts a few leaves in some trees, and averaging over bootstrap trees dilutes it.
  • The loss matters: log loss caps each row's pull at \(\lvert g \rvert \le 1\); AdaBoost's exponential loss grows without limit, so it's more fragile; squared error lets one outlier dominate a leaf.

Guards: early stopping, min_child_weight and \(\lambda\), subsampling, a robust loss, and looking at the rows with the largest final gradients, which are often label errors. (13)

16Depth-wise vs leaf-wise tree growth?

Depth-wise splits every node level by level; leaf-wise always splits the single leaf with the largest gain, wherever it is.

  • Leaf-wise (LightGBM; XGBoost's lossguide) lowers training loss more for the same number of leaves, because no split is spent on a leaf with little to gain.
  • The risk: deep, thin branches that fit a few rows. On a simulated book, validation loss after 500 rounds was 0.243 with 4 leaves and 0.746 with 127.
  • Controls: num_leaves as the main knob, min_child_samples as the floor (it's what saved small data: 0.272 with one-row leaves vs 0.237 with 50-row leaves), max_depth as a cap.

Follow-up: CatBoost's symmetric trees are the opposite extreme: one question per level, fast and hard to overfit, less flexible per tree. (10)

17XGBoost vs LightGBM vs CatBoost?

All three are second-order gradient boosters; they differ in how trees grow, how splits are searched and sampled, and how categories are handled.

  • XGBoost: depth-wise by default, exact / approximate / histogram search, \(\lambda = 1\) by default, learned missing directions, monotone and interaction constraints, native categories (sorted by leaf weight, like LightGBM), custom objectives, a mature distributed and GPU ecosystem.
  • LightGBM: histograms with leaf-wise growth, GOSS and EFB; usually fastest on large data; overfits small data at default settings; categories split by sorting on \(G/H\).
  • CatBoost: ordered target statistics and ordered boosting, symmetric trees, strong defaults; the best native handling of high-cardinality categoricals; slower to train, very fast to predict.

How to choose: tuned, they usually land within noise of each other, so choose by the data. Many high-cardinality categories: CatBoost (with has_time if there's a time order), or XGBoost/LightGBM with out-of-fold or time-ordered target encoding. Very large data: LightGBM or XGBoost's histogram method. The validation design matters more than the library. (10, 11)

18Why is CatBoost's target encoding special? What's prediction shift?

CatBoost encodes each row using only the rows before it in a random permutation (plus a prior), so a row's own label never enters its own encoding; naive target encoding leaks exactly that.

\[ \hat x_i = \frac{\sum_{j \prec i,\ c_j = c_i} y_j + a \cdot \text{prior}}{\#\{\, j \prec i : c_j = c_i \,\} + a} \]

In words: the average label of earlier rows in the same category, pulled toward the overall rate by \(a\) pseudo-rows. Naively, each row's label sits inside its category's mean: a useless 300-level pincode scored train AUC 0.779 and test 0.471, and dropped a model's test AUC from 0.809 to 0.609. Ordered statistics removed the fake signal (train AUC 0.492, model 0.812). Smoothing alone doesn't, because it keeps the order.

Prediction shift is the same leak inside boosting: each row's gradient comes from a model trained on that row, so training residuals look smaller than they would on new data. Ordered boosting computes each row's gradient from a model built only on earlier rows. Trade-off: early rows get noisy encodings (CatBoost keeps several random permutations and uses different ones for different trees, so no row is always early), a random order isn't time order, and ordered boosting costs more. Elsewhere, out-of-fold target encoding does the same job. (11)

19Feature importance: weight vs gain vs cover vs SHAP. What is TreeSHAP?

Weight counts splits, gain averages their gains, cover averages the hessian reaching them; SHAP splits each prediction into additive per-feature contributions, and mean |SHAP| is the most trustworthy of the four.

  • Weight favours many-valued features, noise included: a useless age feature got 29% of splits in a simulation, while a 6-valued strong feature got 5%.
  • Gain favours a feature used in one big early split per tree (that same strong feature: 65%), and isn't consistent: a model can rely more on a feature while its gain falls.
  • Cover favours splits near the root. All three are measured on training data, so they reward noise splits.
\[ F(x) = \phi_0 + \sum_j \phi_j(x) \]

TreeSHAP, in words: \(\phi_0\) is the average raw score, and each \(\phi_j\) is a Shapley value, feature \(j\)'s marginal contribution averaged over all orders in which features could be revealed. TreeSHAP computes them exactly in polynomial time, by following known features' branches and averaging over unknown features' branches by the training cover. Caveats: SHAP explains the model, not causes; correlated features share credit arbitrarily; for global importance, permutation importance on held-out data is a good cross-check. (13)

20What are monotonic constraints, and how are they enforced?

They force the prediction to move only one way in a feature, with every other feature fixed, and they're enforced while each tree grows: violating splits are rejected and leaf values are bounded.

  1. For a split on a feature constrained to increase, a candidate whose lower-value child gets the larger weight is refused.
  2. After an accepted split with \(w_L \le w_R\), the midpoint \((w_L + w_R)/2\) becomes an upper bound for every leaf under the left child and a lower bound for every leaf under the right child; later splits inherit the bounds.
  3. Leaf values are clipped into their bounds, so each tree is monotone, and a sum of monotone trees is monotone.

Why credit wants it: decline reasons must make sense (more income can't raise risk), regulators check directions, and removing wiggles usually removes overfitting. In a simulation, constraining income, EMI share and late payments removed every rise in every applicant's curve at no cost in log loss (0.222 → 0.221), though AUC fell from 0.832 to 0.811. Trade-off: a wrong constraint adds bias (forcing risk to rise with income took log loss to 0.262); it holds “others fixed”, which can differ from the raw trend; and it doesn't govern where missing values go. (13)

21Class imbalance: what does scale_pos_weight do to the model?

It multiplies every positive row's \(g\) and \(h\) by \(k\), as if each positive appeared \(k\) times, so the model learns odds \(k\) times too high.

\[ \begin{aligned} k\, n_+ (p - 1) + n_-\, p &= 0 \\ \frac{p}{1 - p} &= k \cdot \frac{n_+}{n_-} \end{aligned} \]

In words: the weighted loss's best constant for a group with \(n_+\) positives and \(n_-\) negatives has \(k\) times the true odds. With \(k = 50\), a true 3% risk (odds 0.031) becomes odds 1.55, about 0.61; in a simulation with 8.7% defaults the mean prediction became 0.55 and AUC fell from 0.825 to 0.794.

What to do: subtract \(\log k\) from the raw score or recalibrate before using probabilities. Often you don't need it: starting at the base-rate log-odds already balances the gradients, and for a decision you can keep the plain loss and move the threshold. It can help when positives are so rare that splits on them can't clear min_child_weight; max_delta_step is the other knob there. (13)

22Are a booster's probabilities calibrated?

Often roughly, if it's trained and early-stopped on log loss; reweighting, too many rounds or a large learning rate break it, so always check.

  • Why it can be calibrated: log loss is a proper scoring rule: it's minimized by the true probabilities, so an honest fit is rewarded.
  • What breaks it: past the best round, groups get pushed toward 0 and 1 (on the toy, 200 trees put one- and two-row groups at 0.000 and 1.000); scale_pos_weight, class weights and undersampling multiply the odds; tiny leaves and large \(\eta\) make extreme steps.
  • How to check and fix: a reliability curve on held-out, out-of-time data; Platt scaling (a logistic regression on the raw score) with little data, isotonic regression with more, fitted on data not used for training or early stopping.

Follow-up: Platt scaling is strictly increasing, so the ranking and AUC are unchanged; isotonic regression creates ties, so AUC can shift slightly. Calibration matters when the probability itself is used, for pricing or expected loss. (13)

23Can gradient boosting extrapolate? Does it need feature scaling? What about outliers?

It can't extrapolate, it doesn't need scaling, and outliers in features are harmless while outliers in the target matter under squared error.

  • Extrapolation: each tree is flat beyond its last split, so the sum is too. A simulated booster predicted a limit of 242.6 at incomes of 150, 300 and 600 where the truth was 240, 480 and 960. Fixes: predict a ratio that stays in range, boost the residual of a linear model, or use linear leaves.
  • Scaling: a split only uses the order of a feature's values, so any monotone transform gives the same splits.
  • Outliers: a feature outlier just sits at one end (and shares the last histogram bin). A target outlier has a huge residual that every tree chases: 2% of +₹500k typos took a simulated test RMSE from about 10 to 29.0; absolute error or Huber brought it back to 10.5 and 10.9.

Follow-up: monitor inputs that drift beyond the training range; the model will silently predict the edge value. (13)

24Gradient boosting vs random forest vs a neural net on tabular data?

Boosting is usually the most accurate on typical tables, a forest is the robust low-effort alternative, and neural nets win with very large data, unstructured inputs, sequences or multimodal setups.

  • Why trees win on tables: tabular targets are irregular (thresholds, steps) and nets are biased toward smooth functions; useless columns hurt an MLP but a tree just never splits on them; and columns have individual meanings that trees use one at a time, while an MLP must learn which directions matter.
  • Practical edges of trees: no scaling, native missing values and categories, monotone constraints, TreeSHAP, cheap training.
  • When nets win: raw text or images in the row, transaction sequences, huge data, shared embeddings across tasks, end-to-end training with other modalities. Tabular foundation models are now competitive on small tables.

Trade-off: boosting needs early stopping and some tuning; a forest needs almost none; ensembles of a booster and a net often beat both. (14)

25What does XGBoost add over classic gradient boosting? How can it be parallel if boosting is sequential?

Second-order split finding, regularization inside the objective, learned missing-value directions, faster split search and column subsampling; it's parallel inside each tree, not across trees.

  • Splits from \(g\) and \(h\): classic GBM grows each tree by squared error on \(-g\) and adds a Newton step only in the leaves; XGBoost uses the second-order gain for both.
  • Regularization: \(\lambda\), \(\alpha\), \(\gamma\) and min_child_weight in the objective, plus column subsampling by tree, level or node.
  • Missing values: a default direction learned per split.
  • Speed: sorted column blocks, weighted quantile sketches, histograms, GPU and distributed training.

Parallelism: each tree needs the previous predictions, so trees are sequential; but computing \(g\) and \(h\) for all rows, building histograms and scanning features all run in parallel within a tree. Follow-up: for squared error with \(\lambda = 0\), classic GBM and XGBoost grow the same trees, since \(h = 1\). (06, 09)

26AdaBoost vs gradient boosting?

AdaBoost reweights rows each round and gives each weak learner a vote; it turns out to be forward stagewise modelling with the exponential loss, and gradient boosting generalizes it to any differentiable loss.

\[ \begin{aligned} \alpha_m &= \tfrac12 \log\frac{1 - \epsilon_m}{\epsilon_m} \\ w_i &\propto e^{-y_i F(x_i)} \end{aligned} \]

In words: a learner with weighted error \(\epsilon\) gets a vote \(\alpha\), and a row's weight is its current exponential loss, which is also the size of that loss's gradient (labels are ±1). So AdaBoost carries the gradient as a weight instead of fitting it as a target.

Why gradient boosting replaced it: the exponential loss grows exponentially with a confident mistake, so a mislabelled row gets an enormous weight; log loss grows only linearly there. Follow-up: AdaBoost's score is half the log-odds, so its probability is \(\sigma(2F)\).

28Write the pseudocode for gradient boosting and for one XGBoost split search.

Start at the best constant; each round compute \(g\) and \(h\), grow a tree by sweeping sorted features with running sums and scoring each cut with the gain (trying missing rows on both sides), set leaves to \(-G/(H + \lambda)\), and add \(\eta\) times the tree.

F = F0 for all rows
repeat M times:
  g, h = slope, bend of loss at F
  tree = GROW(rows, g, h)
  F += eta * tree(X)

# in GROW, at each node (mcw =
# min_child_weight):
for each feature f:
  Gm, Hm = sums over rows missing f
  GL = HL = 0
  for each cut, in sorted order of f:
    GL += g;  HL += h
    for side in (left, right):
      add (Gm, Hm) to that side's sums
      GR = G - GL;  HR = H - HL
      skip if HL or HR < mcw
      gain = ½(GL²/(HL+λ) + GR²/(HR+λ)
               - G²/(H+λ)) - γ
      keep the best (f, cut, side)
leaf value = -G / (H + λ)

Why it's shaped like this: the gain needs only sums, so one sorted sweep scores every cut; the missing rows' sums are computed once and tried on both sides. Follow-up: the cost is one linear sweep per feature per node after a single upfront sort, or a sweep over at most 256 bins with histograms. Full versions and a runnable NumPy build: section 16.

18Cheat sheet

The model and the start

\[ \begin{aligned} F(x) &= F_0 + \eta \sum_m f_m(x) \\ F_0 &= \bar y \quad \text{or} \quad \log\frac{\bar y}{1 - \bar y} \\ p &= \sigma(F) \quad \text{(once, at the end)} \end{aligned} \]

Gradients and hessians

\[ \begin{aligned} \text{squared error:}\quad g &= F - y \\ h &= 1 \\ \text{log loss:}\quad g &= p - y \\ h &= p(1 - p) \\ \text{pseudo-residual:}\quad r &= -g \end{aligned} \]

XGBoost at a node

\[ \begin{aligned} \ell(F + w) &\approx \ell(F) + g w + \tfrac12 h w^2 \\ w^* &= -\frac{G}{H + \lambda} \\ \text{Obj}^* &= -\frac12 \sum_j \frac{G_j^2}{H_j + \lambda} + \gamma T \\ \text{Gain} &= \tfrac12 \Big[\tfrac{G_L^2}{H_L + \lambda} + \tfrac{G_R^2}{H_R + \lambda} \\ &\qquad - \tfrac{G^2}{H + \lambda}\Big] - \gamma \\ w^*_{L1} &= -\frac{\text{sign}(G)\, (\lvert G \rvert - \alpha)_+}{H + \lambda} \end{aligned} \]

\(x_+\) means \(\max(x, 0)\).

Settings in one line each

  • \(\eta\): shrinks every tree; smaller needs more trees, generalizes a little better.
  • \(\lambda\): adds to \(H\); shrinks small-hessian leaves. \(\gamma\): minimum gain per split (XGBoost: no ½).
  • min_child_weight: minimum \(H\) per child; for log loss, rows weighted by \(p(1 - p)\).
  • Missing: try \((G_{\text{miss}}, H_{\text{miss}})\) on each side; keep the better as the default direction.
  • scale_pos_weight \(k\): odds × \(k\); subtract \(\log k\) or recalibrate.
  • Monotone: reject violating splits; midpoint \((w_L + w_R)/2\) bounds each subtree.

Libraries

  • LightGBM: leaf-wise (num_leaves), GOSS weight \((1 - a)/b\), EFB, categories sorted by \(G/(H + s)\) with \(s\) = cat_smooth.
  • CatBoost: ordered target statistic \(\big(\sum_{\text{earlier}} y + a \cdot \text{prior}\big)/(n_{\text{earlier}} + a)\), ordered boosting, symmetric trees.
  • SHAP: \(F(x) = \phi_0 + \sum_j \phi_j\), in log-odds.
